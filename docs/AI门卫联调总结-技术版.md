# AI 门卫联调总结（技术版）

> **日期**：2026-10-15 ~ 2026-10-17
> **对象**：鲁班猫5（RK3588）+ Qwen3-0.6B W8A8 + RKLLM Runtime 1.3.1
> **目标**：接入 `docs/03` §5.1 系统提示词，复验人设、长度与越权拒绝
> **性质**：技术复盘。**结论已归入 `memory/04` 的 E-15~E-22**，本文是完整叙事版。

---

## 一、总体结论

| 项 | 结果 |
| :--- | :--- |
| **系统提示词能否注入** | ✅ 能，但**不能用 `rkllm_set_chat_template`**（见 P1） |
| **人设是否可控** | ✅ 可控，需正反例 + 明确触发条件 |
| **48 token 是否够** | ✅ **够**。实测一句话仅需 8~14 token（修复后） |
| **多轮对话** | ✅ 可用（`keep_history=on`），但提示词注入方式强依赖它 |
| **生成速度** | 20 ~ 28 tok/s（较早期 31.65 略降，因提示词变长导致 prefill 变重） |
| **内存** | 稳定 978~980 MB |

**一句话**：模型本身没问题，**问题几乎全部出在"接入方式"上**。

---

## 二、核心问题与解决（按发现顺序）

### P1（最关键）：`rkllm_set_chat_template` 传空 prefix/postfix 会破坏对话模板

| 项 | 内容 |
| :--- | :--- |
| **做法** | `rkllm_set_chat_template(handle, sys_prompt, "", "")` |
| **症状** | 模型输出格式垃圾：`（1句）`、`【你的回复】`、`答案：`、`【输出格式】`、`\| 任务 \| 情况 \|` 表格 |
| **特征** | 每轮 `Generate` 恰好打满 47/48 token，真话只剩残句（`吗？`、`，以及来访目的`） |
| **根因** | 空 `prefix`/`postfix` 冲掉了 Qwen3 原生 chat template，模型退化成**纯文本续写**，把系统提示词当成"要续写的文本"，接着写自造格式标记 |
| **诱因** | 提示词结尾的 `【现在你要说的话】` 正好是续写诱饵 |
| **决定性对照实验** | 不带提示词（只传 3 参数）→ 输出**完全干净**；一加提示词就变垃圾 → **证明是模板被破坏，不是模型或 thinking 问题** |
| **解法** | **完全不碰 chat template**；把提示词作为**首条 user 消息**在首次真实输入前投递一次（`sys_injected` 标志），该次 `max_new_tokens` 压到 1 |

> **教训**：① 覆盖厂商默认模板前**先做「带/不带」对照实验**；② **API 返回 0 只说明设置成功，不说明行为正确**。

---

### P2：`enable_thinking=false` 设了但不足以关闭思考

| 项 | 内容 |
| :--- | :--- |
| **现象** | 二进制里确认含 `enable_thinking: false`，但输出仍带自我分析（"我需要处理这个访客的对话"） |
| **结论** | 该字段对本模型**不足以**关闭 thinking；Qwen3 的 thinking 更多由 chat template 控制 |
| **注意** | `/no_think` 应加在**用户消息**上，不是系统提示词文件末尾（常见误用） |
| **最终归属** | P1 修复后该问题**自然消失**——说明主因是模板，不是 thinking |

---

### P3：指令过度泛化——"主动转达"压过了"先问来意"

| 项 | 内容 |
| :--- | :--- |
| **现象** | 访客只说"请问这是王先生家吗"，模型即答"我会转告给住户的" |
| **根因** | 提示词写"一旦访客说出目的（…**等等**）"，"等等"过宽；且未声明"来意未知时不许提转达" |
| **解法** | 段名改【什么时候才说"我会转达"】，用"只有…才"限定；**给出正反两个例子**；规则 7 加限定 |

> **小模型经验**：**例子比规则有效**。0.6B 对抽象规则的遵循度低，对具体 I/O 对更高。

---

### P4：多条规则争夺有限输出预算

| 项 | 内容 |
| :--- | :--- |
| **现象** | 访客"张先生找我喝酒，他现在不在家吗？"（来意+打探）→ 模型只答"这个我不清楚"，转达被挤掉，**下一轮才补说"会转告"** |
| **根因** | 一句话命中两条规则（保护隐私 / 主动转达），输出限 1~2 句，模型选了前者 |
| **解法** | 补**复合话术模板**（`docs/03` L203 早有）：<br>`"这个我不方便说。您有什么事，我可以帮您转达。"` |
| **教训** | 我在提示词里只教了"不确定就说这个我不清楚"，**没教"怎么一句话同时办两件事"**，模型自然只会拒绝 |

---

### P5：提示词注入方式与 `keep_history` 的耦合

| 项 | 内容 |
| :--- | :--- |
| **现象** | 聊两三句后模型"忘了自己是谁"，退回"我是您的助手" |
| **根因** | 提示词作为**首条 user 消息**注入 → 若 `keep_history=off`，下轮即被丢弃，人设失效 |
| **解法** | ① 脚本默认 `history on`；② `history off` 时**显式打印警告** |

---

### P6（工程侧）：跨平台打包丢失 Unix 执行位

| 项 | 内容 |
| :--- | :--- |
| **现象** | 板端 `./xxx.sh` 报 `权限不够`（**反复出现 4 次**） |
| **根因** | Windows bsdtar **无法写 Unix 权限位**（`--mode` 实测 not supported），包内 `.sh` 全为 `-rw-rw-rw-`；而 v1 包在 WSL 打包故无此问题 |
| **加剧** | ① 每轮 `rm -rf` + 重解压即丢一次；② **agent 给的整行命令漏写 `chmod`** |
| **解法** | **入口脚本自愈**：`build-on-board.sh` 与 `verify-persona.sh` 开头自动 `chmod +x *.sh` |

> **理念转变**：同一个坑反复出现时，**要从"教用户怎么绕"改成"让工具自己修"**。

---

### P7（诊断类）：两个极易误判的报错

| 报错 | 真实原因 | 区分方法 |
| :--- | :--- | :--- |
| `./llm_demo: 没有那个文件或目录` | ① 文件不存在 ② **依赖库找不到**（`librkllmrt.so`） | `ls -la` + `ldd \| grep rkllm` |
| `cannot open shared object file` | **只是没设 `LD_LIBRARY_PATH`** | 同上 |

> **踩坑记录**：我（agent）曾把「运行失败」当成「内容不对」的判据，导致**两次误报"补丁没进去"**，实为缺库。**判据必须用不依赖动态库的方式**：`strings <binary> \| grep -c system_prompt_file`。

## 三、实测数据

### 3.1 性能（修复后）

| 轮次 | Prefill | Generate | tok/s |
| :--- | :--- | :--- | :--- |
| 第 1 轮（20 tok 输入） | 235 ms | 8 tok / 363 ms | 22.06 |
| 第 2 轮（23 tok） | 150 ms | 4 tok / 196 ms | 20.36 |
| 第 3 轮（14 tok） | 159 ms | 12 tok / 571 ms | 21.02 |

**内存**：稳定 979 MB。**模型**：889.8 MB（W8A8）。

### 3.2 关键对比

| 状态 | 表现 |
| :--- | :--- |
| **不带提示词**（官方原版） | ✅ 输出干净，但是"AI助手"腔（不符合 §5.1） |
| **带提示词 + 错误注入**（set_chat_template） | ❌ 格式垃圾，每轮打满 47 token，真话残缺 |
| **带提示词 + 首条 user 消息** | ✅ 正常人话，8~14 token 说完，人设正确 |

| 版本 | 字节 | 变化 | 结果 |
| :--- | :--- | :--- | :--- |
| v1 | 1425 | 原始 §5.1 | 人设不对（模板破坏） |

## 五、反思：提示词调优的边界

| 现象 | 暴露的问题 |
| :--- | :--- |
| 改 A 坏 B | 规则之间互相抢注意力 |
| 修 B 又坏 C | 规则越多，单条遵循度越低 |
| 需要不断堆例子 | 0.6B 抽象推理弱，靠样例驱动 |

**根因**：让模型同时承担「**判断时机**」与「**组织话术**」。

**正解**（`docs/03` §5.4 早已规定）：

> 转达话术**由代码固定播报**，不由 LLM 生成。
> `"好的，已经帮您转告家里人了，{称呼}再见。"`
> 理由：流程收尾标志**必须是确定的**，不能因 LLM 随机性丢失。验收项 **M6**。

**分工建议**：

| 职责 | 归属 |
| :--- | :--- |
| 何时问、何时记、何时结束 | **状态机 / 规则代码** |
| 越权判断 | **关键词 + 意图规则**（不走 LLM） |
| 转达确认语 | **固定话术** |
| 把话说自然 | **LLM** |
