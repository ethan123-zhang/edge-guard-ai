# 哨兵管家 — 实施计划

> 前提：**单人开发**（主力时间被压缩，用闲暇时间推进），队友零基础负责非技术工作，周期 4 周。
> 版本：v1.0（主线版）

---

## 1. 总原则

| 原则 | 说明 |
|---|---|
| **死亡点优先** | 第 1 周必须验证两个"不通则项目不成立"的技术点 |
| **先跑通，再跑好** | 骨架优先：链路通了才有资格谈优化 |
| **长尾任务并行** | 模型下载/转换是"提交后等结果"，挂着跑，不占人力 |
| **第 3 周冻结功能** | 之后只打磨，不加新功能 |
| **随时可演示** | 每周结束都要有一个"能演出来的东西" |

---

## 2. 周计划

### 第 1 周：打通两个死亡点（最关键的一周）

**本周目标**：两个核心技术点分别跑通。**这两点不通，整个项目不成立。**

| 任务 | 产出 | 验收 |
|---|---|---|
| **W1-1【今天/立刻】挂上模型下载与转换** | `.rkllm` 模型文件 | 文件存在且能加载 |
| **W1-2 Jetson：OpenCV 人脸识别跑通** | `vision/face_service.py` 能对静态图输出人脸数 | 打印出检测到的人脸 |
| **W1-3 RK3588：RKLLM 对话跑通** | `llm_demo` 能问答 | 看到 `rkllm init success` 和 tokens/s |
| **W1-4 关闭 AI 加速的幻象**：暂不做 TensorRT | —— | 记录当前单帧耗时（基线） |
| **W1-5【队友】采购麦克风** | 到货 | `arecord -l` 能识别 |

**本周最大风险**：RKLLM 模型转换。**如果第 1 周结束还没跑起来，立即启动降级**（见第 5 节）。

**本周结束时的"能演示的东西"**：Jetson 能识别一张图；RK3588 能在终端里对话。**虽然还没连起来，但两个死亡点都验证了。**

### 第 2 周：端到端骨架（打通链路）

**本周目标**：**从"两个孤岛"变成"一条链路"**。功能可以是假的，但数据必须真的流动。

| 任务 | 产出 | 验收 |
|---|---|---|
| **W2-1 定死接口**（照 `02-接口协议.md`） | 两侧 JSON 格式确认 | 用 `websocat` 能互发样例 |
| **W2-2 Jetson：WebSocket 上报** | 检测到人脸 → 发 `face_event` | 对端能收到 |
| **W2-3 RK3588：接收 + 写库** | 收到事件 → 写 `person`/`visit` 表 | `sqlite3` 能查到记录 |
| **W2-4 主人端最小看板** | 网页能显示收到的记录 | 浏览器能看到 |
| **W2-5 家里有人/无人开关** | 主人端能切换状态 | 切换后系统行为变化 |
| **W2-6【可选】补光灯触发** | PIR/软件触发开灯 | 灯能亮 |

> **本周末端到端链路必须通**：人脸 → JSON → 收库 → 看板显示。
> 这时候 ASR/LLM/TTS 都还没接，但**流程骨架已经成立**，后面全是"往里填"。

**本周结束时的"能演示的东西"**：站在摄像头前 → 看板上出现一条到访记录。

## 5. 降级预案（**第 1 周就要准备好**）

### 5.1 如果 RKLLM 跑不起来

| 降级级别 | 方案 | 影响 |
|---|---|---|
| L1 | 排查转换问题：**检查 Toolkit 与 Runtime 版本是否一致**（两者不匹配是很常见的原因），或换用 W8A8 + `normal` 算法重转 | 不影响能力 |
| L2 | 换更小/更成熟的模型（Qwen3-0.6B、Qwen2.5-0.5B），或改用 **CPU + llama.cpp** 跑 Qwen2.5-1.5B Q4_K_M（约 22 tokens/s） | 能力略降，但能跑 |
| L3 | **固定话术模式**：不用 LLM，用状态机 + 模板生成回复 | 失去"端侧 LLM"亮点，但流程完整 |
| L4 | 云端 API 兜底（现场开热点） | 依赖网络，风险高，最后手段 |

> **执行顺序**：L1 是排查（可能几分钟就解决），L2 是换方案，L3 是彻底放弃 LLM。**不要跳过 L1 直接换模型**——很多"转换失败"其实是版本不匹配。

> **L3 其实不丢人**：你可以在答辩时说"我们实现了 LLM 和固定话术双模式，LLM 不可用时自动降级"——**这本身就是一个可靠性设计亮点**。

### 5.2 如果 ASR 不可用

| 方案 | 说明 |
|---|---|
| 键盘输入模式 | 终端里打字当访客说话（**必做**） |
| 预录语音文件 | 提前录好"我找老王""我是他表哥"等，现场播放 |
| 关键词模式 | 不转写整句，只识别关键词（"送货""开门"） |

### 5.3 如果时间严重不足

**保命精简版**（只做这三样）：
1. 人脸识别 → 熟人/陌生人 → 到访计数
2. 家中无人时：**固定话术问候**（不接 ASR/LLM）+ 越权拒绝（规则）
3. 上报主人端

> 即使只有这三样，**"熟人记忆 + 越权拒绝 + 上报"仍然是一个完整的故事**。

## 6. 单人开发的自我保护机制

### 6.1 两小时止损线

**一个问题卡超过 2 小时，立刻换方案，不要硬啃。**

一个人在没人商量的情况下，容易在一个 bug 上耗掉整个周末。**设置硬性止损线**：
- 卡 2 小时 → 换个思路
- 卡 4 小时 → 换技术方案（降级）
- 卡 1 天 → 砍掉这个功能

### 6.2 "能跑"与"跑好"分离

| 阶段 | 目标 | 不要做的事 |
|---|---|---|
| 跑通 | 流程能走完 | 不要调参、不要优化 |
| 跑好 | 稳定、快、准 | 不要加新功能 |

**每次想优化之前，先问：这个功能跑通了吗？** 没跑通就先跑通。

### 6.3 每周留一个"演示备份点"

每周结束时，**把当前能跑的版本备份一份**（`git commit` 或复制目录）。

```
backups/
├─ week1-能识别能对话/
├─ week2-链路通/
├─ week3-功能全/
└─ week4-演示版/
```

**原因**：第 4 周你可能改出问题。**有一个"上周还能跑的版本"，心态会稳很多**——大不了回滚。

### 6.4 边做边写答辩材料

每完成一个模块，写 3~5 行：

```
## 模块：越权拦截
- 做什么：识别访客的越权请求并拒绝
- 怎么做的：独立规则引擎 + 固定话术库，不经过 LLM
- 为什么这么做：LLM 有被说服的风险，安全关键逻辑必须确定
- 数据：拦截率 X/Y
```

**攒到最后写会很痛苦，边做边写几乎零成本。** 这些片段直接就是 PPT 的素材。
