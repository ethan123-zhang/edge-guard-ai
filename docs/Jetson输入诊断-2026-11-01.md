# Jetson 现场零检出输入诊断

范围：先新增只读诊断脚本，再根据同帧证据增加按档选择的 Haar 均衡化开关。不改变尺寸/确认门槛、摄像头曝光控制或依赖。Codex 定义对照、审查并实测，DeepSeek 限定实现。

## 【输入输出定义】

输入为 /dev/video0、V4L2、请求1280×720的同一帧。输出为实际尺寸/格式、灰度统计、帧变化、Haar检测框、错误与耗时，不保存图像。

用户另行允许临时预览1帧：已完成，图像在本机忽略目录查看后删除；不把该授权扩展为持续截图。

## 【核心算法逻辑伪代码】

```text
同一帧 → 灰度统计与帧间差异
原灰度/均衡化灰度 × 最小框30px/80px：四路Haar，其他参数一致
生产检测器 → 核对与配置所选80px路径经嵌套抑制后的结果一致
汇总检测帧数和异常 → finally释放摄像头 → 保存元数据
```

30px路径仅用于定位尺寸门槛影响，不作为生产验收设置。检测对照本身不验证轨道确认和事件发送。

## 【异常与边界条件】

拒绝非正帧数和非有限/非正周期；输出父目录必须存在且在相机打开前检查。读帧失败、统计异常或任一路检测异常单独记录，不静默当作0框。退出0只说明采样完整，无脸不是“识别成功”。

## 【验收测试用例】

- Jetson原生Python3.6编译；非法参数、缺输出父目录在打开设备前退出2。
- 每帧尺寸/灰度/哈希变化与四路检测结果可回读；无图像文件。
- 单帧四路参数只有均衡化/最小尺寸两个因素，生产结果比较无差异。
- 先保持原取景取得基线；若同帧对照仍无法定位，再单独调整角度或补光，避免同时改变多个条件后宣称唯一原因。

## 当前现场证据

- USB UVC 设备 /dev/video0，当前1280×720、YUYV、9fps配置；自动曝光开启；无其他进程占用。
- 授权单帧预览确认人脸实际在画面中；镜头仰拍，背景顶灯较亮，人脸相对偏暗。角度与光照属于候选因素，尚不能确定唯一根因。
- 上轮标准人脸样例3/3检出，现场两轮各40帧均零检出。
- 本轮原取景同帧20帧：plain30/80均19帧检出，equalized30/80均3帧检出，生产3帧；20种灰度哈希、0错误、实际1280×720。当前场景下均衡化明显降低检出，最小尺寸30/80的结果相同。
- 同批数据按真实跟踪器confirm=3、TTL=2秒、cooldown=10秒回放：plain80经嵌套抑制产生1事件（第4帧），equalized80产生0事件。此结论不追溯解释上一轮零检出的唯一原因，也不证明所有场景都应关闭均衡化。

## 限定修复合同

增加布尔配置 `detection.haar_equalize`，默认true；仅 `jetson_local` 显式false。Haar按开关选择原灰度或均衡化灰度，保留80px门槛、嵌套抑制和所有跟踪规则。诊断脚本以实际配置选择比较路径，日志显示实际均衡化状态。用两分支、配置传递和非法类型测试验收，再上板真实主循环复验。

- 修改检测器/配置/Jetson档，补充12项开关回归；同步两个探针的预处理标注和比较路径。旧代码跑52项相关测试，6失败、4错误；修复后Jetson原生Python3.6下104项全通过，7个相关文件SHA256与本机一致。
- 修复后诊断10帧：四路及生产均10/10帧检出，生产与plain80经嵌套抑制后10/10帧一致，无异常。
- 真实主循环：20.5秒、37帧、1条本地陌生人事件，成功1/失败0、丢帧0、无截图、协议校验通过。
- 后一批均衡化路径同样10/10检出，说明采样批次仍有条件变化；不能把跨批改善全部归因于开关，更不能断言均衡化是前两轮零检出的唯一原因。关闭开关依据的是前一批同帧对照，当前效果仍需更广泛场景验证。
