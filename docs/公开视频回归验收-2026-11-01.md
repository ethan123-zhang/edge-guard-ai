# 公开视频离线回归验收（2026-11-01）

已按用户要求由DeepSeek联网找视频并实现离线验证，Codex独立审查与板端复验。无需用户取景；本轮没有调用摄像头或修改生产检测/跟踪算法。

## 【输入输出定义】

两份OpenVINO示例视频和两份冻结公开视频帧加人工空白的控制片；输出原生尺寸下的检测框、轨道前后状态、事件、源帧号、媒体时间、错误及分层计时。素材出处和哈希见[素材记录](公开视频验证素材-2026-11-01.md)。

新增`scripts/video_pipeline_probe.py`、`vision/tests/test_video_probe.py`。真实复用检测器、80px过滤、FaceTracker和事件协议；不读取人脸库、不保存测试截图、不发送网络。此入口验证这些组件组成的链路，不冒充完整VisionService或现场摄像头验收。

## 【核心算法逻辑伪代码】

```text
单次顺序解码到EOF → 媒体时间2Hz网格抽样
真实检测器 → 尺寸过滤 → 跟踪器 → 事件协议校验
保存每个门槛的元数据 → 以预先冻结的预期独立评估
```

板端OpenCV4.1.1读后POS_MSEC首帧83.333ms，但ffprobe真实首帧0；两原片和两控制片均逐帧核验为12fps恒定。本批显式使用`--time-source index-fps`，时间=源帧号÷12；原始POS_MSEC留档。处理墙钟仅作耗时统计，EOF停止、不循环、不放大视频。

## 【异常与边界条件】

无法安全回退的媒体时间明确失败，不制造“上一帧+1ms”。零采样、零解码、协议异常返回非零；参数错误在打开视频前退出2。解码/采样退出0只证明执行完整，不等于业务预期通过；独立验收有失败时，本轮评估器返回1。

人工空白控制片具有已知时间边界，但不等同自然遮挡/真人重入。原片没有完整逐帧门槛内人脸真值，不能从检出比例或总事件数宣称准确率合格。陌生轨道重建不代表身份已认出。

## 【验收测试用例】与结果

板端环境：Python3.6.9 / OpenCV4.1.1。完整141项单测通过，包含新增37项媒体时间/抽样/EOF/参数边界测试；脚本、测试及相关生产文件SHA256与本机一致。

| 用例 | 实测 | 判定 |
| --- | --- | --- |
| 原始双人片30～44秒 | 28采样；27帧2脸、1帧1脸；31秒产生2事件 | 通过本窗口预期 |
| 控制片：3秒正例、0.5秒空白、3秒正例、3秒空白、3秒正例 | 25采样；1秒2事件、10.5秒2事件，共4；短空白无新增 | 通过控制预期 |
| 控制片：有、有、无、有、有、有 | 6采样；实际1.5秒就触发2事件，严格连续3帧应等到2.5秒 | **失败，累计计票问题已自动复现** |
| 走廊原片全片 | 732帧到EOF、122采样、1事件 | 观察项，未判准确率通过 |
| 双人转头原片全片 | 1719帧到EOF、287采样、12事件 | 观察项；12事件不能解释成12人或12次到访 |

五次运行均无采样/协议错误；三个有冻结预期的用例为2通过、1失败，整体验收仍未通过。控制片参考40秒原始帧，板端原生检测到两脸，未通过改门槛或另挑通过帧调整预期。
