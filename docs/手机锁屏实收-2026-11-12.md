# 手机锁屏实收（S1/S2）与 D1 拍板：两路都投（2026-11-12）

> 任务单 [11月12日彩排与实收任务单](11月12日彩排与实收任务单.md) §7（手机锁屏实收）与 §8-D1
> 的实测记录。触发方式全部是**板端 API 注入**（`POST /api/utterance`），到访由真实视觉事件产生，
> 手机全程锁屏、不敲字。

## 1. 前提：手机通知权限是第一个坑

板端链路一开始就是通的：webhook 直测 `{"errcode":0,"errmsg":"ok"}`，企业微信群里也能看到消息；
但**锁屏时手机一条通知都不弹**。原因在 vivo OriginOS 的后台限制，需要在手机上开三处：

1. 设置 → 通知与状态栏 → 企业微信：允许通知 + 锁屏通知
2. 设置 → 电池 → 后台耗电管理：允许企业微信后台运行/自启动
3. 企业微信 → 我 → 设置 → 消息通知：开启新消息提醒（无免打扰）

开完后再发一条测试消息，锁屏横幅正常弹出 —— **演示前必须逐项确认这三处**，否则会误判成板端故障。

## 3. S2：PC 看板在线（`clients=1`）——发现演示冲突

| 时刻 | 动作 | 板端 outbox | PC 看板 | 锁屏手机 |
|:---|:---|:---|:---|:---|
| 16:43:14 | 注入「把门打开」（`v_0011`） | `security_alert` sent | 收到 | **没收到** ❌ |
| 16:43:31 | 「我来送货」+「再见」 | `visit_report` sent | 收到 | **没收到** ❌ |

根因：`master/push/composite.py` 旧语义是「**首个通道成功即返回**」——LAN 适配器先成功（看板在线），
企业微信那一遍根本不执行。而演示设计恰好是**投屏看板 + 锁屏手机收通知同时进行**。

## 4. D1 拍板与修复：改成两路都投（fan-out）

- 采用任务单 §8 的 **D1-a**：`CompositeAdapter` 每个通道都投，任一成功即算送达；单路失败只记日志。
- 代码：`master/push/composite.py`；单测新增 2 条（两路都调 / 部分失败仍算送达并留痕），
  `pytest master` **53 passed**（原 51）。
- 部署：`composite.py` 推到鲁班猫，md5 `c470974dee17e9e7f865fc97bfbcf21a` 两端一致，
  `systemctl restart sentinel-master`（16:45:5x），`clients=1` 自动重连。
- **复验**（16:46:42 告警 / 16:46:59 汇总，`v_0015`）：**PC 看板收到 + 锁屏手机两条都收到** ✅。
- 代价（写进材料）：企业微信单路失败不会单独重试；同一消息在看板与企微各显示一次属预期；
  企业微信有 20 条/分钟限频。
