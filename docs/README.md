## 这是什么

在大门口用 **Jetson Nano** 做人脸识别，判断来人是**熟人还是陌生人**并记录到访次数；当**家中无人**时，用 **鲁班猫5（RK3588）** 上的**端侧 LLM** 与来人**多轮对话**问明来意，**拒绝一切越权请求**，最后把结构化结果**推送给家庭主人**。

## 30 秒了解项目

### 硬件分工（"异构"的含义）

| 节点 | 硬件 | 角色 | 为什么是它 |
|---|---|---|---|
| 视觉节点 | Jetson Nano B01 | **眼睛** | GPU 擅长 CNN 并行计算 |
| 对话节点 | 鲁班猫5（RK3588） | **大脑** | 6 TOPS NPU 跑 LLM，低功耗适合常开 |

**所有业务逻辑集中在 RK3588，Jetson 只负责"识别 + 发事件"。** 这是单人开发下的刻意简化——减少双机联调面积。

### 三个核心亮点

1. **熟人记忆**：熟人再次到访时，问候会带历史上下文——*"王阿姨您好，您上个月来过，今天有什么事吗？"*
2. **越权拦截**：访客要求开门会被明确拒绝，且**判断不经过 LLM**（独立规则引擎），防止大模型被说服。
3. **断网可用**：ASR/LLM/TTS 全部本地运行，断网时数据写本地缓存，恢复后自动补传。

### 数据流

```
摄像头 → Jetson(检测+识别) → WebSocket → 鲁班猫5(判断+对话) → 主人端
                                              ↓
                                          SQLite 归档
```

## 本版本范围（重要）

**做**：人脸识别、熟人判定、到访计数、有人/无人判定、多轮对话、来意总结、越权拒绝、上报主人、本地归档。

**不做**（详见 `01-总体设计.md` 第 2 节）：活体检测、毫米波低功耗唤醒、暴力行为检测、口罩专项优化、云端通道、唤醒词、门内按键。

> 未做的项目在 `01` 文档第 6 节均有**设计分析**，答辩时作为"已知局限 + 未来工作"讲述。**诚实地说清楚没做什么，比做一堆半成品更有价值。**

## 五条铁律

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **播报时闭麦** | 否则系统会自己跟自己对话（教室混响会放大这个问题） |
| 2 | **卡 2 小时就换方案** | 一个人做，硬啃是最大的时间黑洞 |
| 3 | **第 3 周冻结功能，第 4 周不改环境** | 最后一周改环境是经典翻车姿势 |
| 4 | **所有阈值外置到配置文件** | 现场环境一变，改配置比改代码快一百倍 |
| 5 | **数据边测边记** | 延迟/准确率/功耗，最后三天补不出来 |
