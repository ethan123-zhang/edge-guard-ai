# 自然姿态与连续在场的本地事件验收（2026-11-01）

**未通过本轮较严格的本地去重目标：两名人员持续在场，预期2条face_event，实际12条。** 本轮没有修改生产算法或阈值，连续确认修复本身的三个冻结回归仍按前轮证据读取。

## 【输入输出定义】

输入为既有OpenVINO双人转头公开视频，原生768×432、12fps、1719帧。Codex审查全部287个2Hz采样画面，确认左右两名人员持续在画面内；标注在读取本轮运行结果前冻结。历史全片事件总数此前已见，不宣称对历史结果完全盲法。

人工标注仅含场景内左右标识、连续在场区间和姿态挑战窗口，不含姓名、身份特征或人脸库。输出为真实检测/过滤/跟踪/协议链路产生的本地face_event，按固定左右半画面归属。

**层级边界**：docs/02规定10秒身份冷却与10分钟业务到访去重为不同层。本轮“每次连续在场只产生一次本地事件”是比现有空间轨道TTL合同更严格的验收目标；没有运行对话节点或visit_report，不能把12条本地事件写成12个人、12次到访或12份最终到访报告。

## 【核心算法逻辑伪代码】

```text
独立审查源画面 → 冻结287个采样点的人员连续在场预期
原生视频按媒体2Hz采样 → 真实生产组件 → 原始轨道与本地事件
按左右场景区域对照预期：各1条、总计2条、首次应在1000ms
抽取实际过滤后框为相对时间/坐标夹具 → 真实FaceTracker快速回放
分别判断执行完整性、轨道去重与更严格的连续在场目标
```

## 【异常与边界条件】

标注覆盖的是完整2Hz网格，不是全部解码帧；没有逐脸框真值，不计算检测precision/recall。转头、低头和歪头均不等同真实出画；片中没有物体遮挡或同一人出画后自然重入，后二者仍未验收。

Haar框的返回顺序不作为身份真值。左右标识只用于此固定构图，不能推广为跨位置身份关联规则。所有事件均来自不同空间轨道，不是同一轨道重复发送；因此不能靠重置emitted、增加冷却或随意延长TTL来宣布问题解决。
