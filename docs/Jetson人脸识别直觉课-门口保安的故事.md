# Jetson 人脸识别直觉课：一个新保安的上岗故事

> 写给已经理解余弦相似度，但还不熟悉人脸识别整条链路的你。
>
> 这里不推导算法，不讲矩阵演算。我们让一个新保安到“哨兵管家”的门口上班，跟着他经历认人、认错、犹豫和改进的过程。
>
> 文中的小明、小王和教学分数都是虚构例子。第十一章单独解释项目已有的真实评估结果；教学建议不代表生产代码已经实现。

## 第一章：保安上岗，第一件事竟然不是认人

早上，小明走到门口。

你对保安说：“看看是不是小明。”

保安却说：“等等，我先得知道画面里哪一块是脸。”

摄像头拍到的是一整幅画面：门、墙、衣服、头发、路人。计算机最开始拿到的只是一堆像素，并没有自带“小明的脸在这里”这样的说明。

于是，第一个员工出场了：**人脸检测器**。它负责在画面里找脸、画框。

你的项目里出现过两种检测路线：Haar 和 YuNet。先不用研究它们内部怎么算，记住它们在这里都承担“找出脸的位置”的工作。YuNet 这条实验路线还能给出眼睛、鼻尖、嘴角等五个关键点，后面要用。

保安拿到一个框，说：“这里很像一张脸。”

注意，他还没有说：“这里是小明。”

**检测回答“脸在哪里”，身份识别回答“是谁”。这是两个问题。**

这解释了一个常见现象：屏幕上已经画出人脸框，但名字一直显示“未知”。找到了脸，不代表有足够证据确认身份。

反过来，如果连脸都没找到，调身份相似度阈值也帮不上忙：后面的认人步骤根本没拿到合适的输入。

## 第二章：照片歪了，保安先把它摆正

小明昨天录入人脸时看着镜头，今天却歪着头。

保安拿出两张照片，一张正，一张斜。他想：“如果直接比，照片的摆放方式也会影响结果。”

于是第二个员工出场：**人脸对齐**，也就是依据眼睛、鼻子、嘴角的位置，把脸调整到比较统一的方向、大小和位置，再裁出标准区域。

你可以把它想成整理证件照：让眼睛大致落在相同高度，让脸占差不多的面积。

这样，下一步更容易比较脸本身，而不是被“照片往左歪了多少、脸离镜头有多远”干扰。

但这位员工不是魔术师。

如果小明只露出半张脸，旋转照片并不能变出被挡住的另一只眼睛。如果关键点本来就找错了，把照片“摆正”的动作反而可能把脸裁歪。

所以：**对齐能减少拍摄差异，但不能保证恢复缺失的信息。**

项目里说的“五点对齐”，就是这一步。后面提到“对齐质量不好”，你可以先理解成：这张脸没有被可靠地整理到适合比较的状态。

## 第三章：保安不会记住所有像素，而是做一张“面孔名片”

现在照片摆好了。

保安没有逐个像素背下来，而是交给一个专门学习过人脸特征的模型，做出一张“面孔名片”。

这张名片不是姓名、身份证号，而是一串数字，叫作**特征向量**，也常叫 embedding。

你的项目实验里，SFace 承担这项工作，输出的是 128 维特征。这里的“128 维”可以先理解为名片上有 128 个数字槽位；它们是模型共同学出来的表示，不是第一个数字专门写眼睛、第二个专门写鼻子。

理想情况下，同一个人在不同照片里的名片比较接近，不同人的名片比较远。

你已经理解余弦相似度，所以从这里往后很自然：

```text
今天小明的脸 → 特征名片 ─┐
                        ├→ 算余弦相似度 → 得到“有多像”的分数
登记册里的小明 → 特征名片 ┘
```

但请记住：模型得到的是“有多像”的证据，分数本身不带“绝对是同一个人”的保证。

比如相似度是 0.70，不能直接翻译成“有 70% 的概率是小明”。余弦值不是经过校准的身份概率。

到这里，YuNet、对齐、SFace 三者的关系就串起来了：**找出脸 → 整理脸 → 生成用于比较的特征。** OpenCV 的官方教程也按检测、对齐裁剪、特征比较来介绍这条流程。[参考：OpenCV 人脸检测与识别教程](https://docs.opencv.org/5.0/tutorials/dnn/dnn_face/dnn_face.html)

## 第四章：τ 到底是谁？原来只是保安手里的那条线

保安拿着一张比较结果：“和小明的相似度是 0.58。”

你问：“所以让他算小明吗？”

保安说：“你得先告诉我，像到什么程度才算数。”

这个“像到什么程度才算数”的分界线，就叫**阈值**。符号 **τ** 读作“套”，这里只是给阈值起了一个数学名字。

假设规则是：

> 相似度达到 τ，就通过这次相似度检查；低于 τ，就不通过。

同一个 0.58，换一条线，结果会不同：

| 阈值 τ | 相似度 0.58 的结果 | 保安的态度 |
| --- | --- | --- |
| 0.45 | 通过 | 要求较宽松 |
| 0.60 | 不通过 | 要求较严格 |

**τ 不是另一个识别模型。它是你如何使用模型分数的决策规则。**

这里还要补上一个条件：我们讲的是“分数越大越像”的相似度。如果某套系统使用“越小越像”的距离，比较方向会相反。

你可能还见过“检测阈值”。它和这里的身份阈值不是同一条线：

- 检测阈值管“像不像一张脸”。
- 身份阈值管“两张脸像不像同一个人”。

所以，“检测分 0.99”不能理解成“99% 确定这是小明”。

## 第五章：保安第一次犯错，两种错竟然互相牵制

中午，两个麻烦接连出现了。

第一件事：小王来了，保安却把他认成小明。

第二件事：真正的小明来了，保安却说“不够像，不能确认”。

这两种错误在你项目的配对比较报告里分别记作 FAR 和 FRR：

| 情况               | 直觉解释      | 报告里的名字   |
| ---------------- | --------- | -------- |
| 不同人的两张脸被判成同一个人   | 认错了人、误关联  | FAR：误接受率 |
| 同一个人的两张脸没被判成同一个人 | 没认出本人、漏关联 | FRR：误拒绝率 |


这里有个容易混淆的地方：**FRR 不是“没有检测到脸的比例”**。本章说的是已经进入身份比较后，没认出同一个人。

而且两个比例的分母不同。假设测试准备了：

- 500 对不同人的照片，其中 5 对被错误合并，FAR 就是 1%。
- 500 对同一个人的照片，其中 20 对没认出来，FRR 就是 4%。

不是把两种错误都除以 1000。

严格的生物识别资料还会区分“单次比较错误”和“完整认证过程错误”，前者常用 FMR、FNMR。为方便读项目报告，这里沿用报告的 FAR、FRR，但它们在这份报告中统计的是照片配对比较，不能直接当成整个门口系统的错误率。[参考：NIST 对两类识别错误的解释](https://www.nist.gov/blogs/taking-measure/tale-two-errors-measuring-biometric-algorithms)

### 保安为什么不能把阈值拉高，彻底解决问题？

你说：“怕认错，就严格一点！”

保安提高 τ。小王比较难冒充小明了，但戴口罩、低头、光线暗的小明，也更容易过不了线。

你又说：“那就放松一点！”

保安降低 τ。小明更容易被认出，小王也更容易被误认。

在输入和评分固定、只调整这一个阈值时，方向是：

```text
τ 提高 → 接受更少 → 误关联通常减少，同人未关联通常增加
τ 降低 → 接受更多 → 同人未关联通常减少，误关联通常增加
```

有限样本上，有时调一点阈值数字不变，因为没有样本正好落在那一段；但取舍方向不会反过来。

门口提醒场景里，漏认一次可能只是多问一句“请问您是哪位”；认错人却可能让陌生人继承熟人信息。不同用途，对两种错误的容忍程度会不同。

## 第六章：有些分数混在一起，再好的分界线也切不开

下午下雨，小明的脸被雨伞遮住，又背着光。

他的照片和登记照只有 0.30 的相似度。

另一边，小王某张照片和小明登记照却有 0.40。

保安犯难了：

> “要接受 0.30 的真小明，我得把线放得很低；可这样，0.40 的小王也会通过。”

这就是**同人分数和异人分数发生重叠**。

```text
真小明的一张困难照片：0.30
小王的一张容易混淆照片：0.40
```

这两个样本的先后顺序已经排反了，靠一条“高于多少就接受”的线，不可能同时把它们判断正确。

这不意味着模型对所有人都没用，也不意味着永远找不到有用的阈值。它意味着：**对这批输入和这种评分方式，不能指望单一阈值做到所有样本都不犯错。**

于是下一步不该只问“τ 应该改成几”，还要问：

“是不是照片太差？对齐错了？登记照不好？是否需要再看一帧？是否应该允许暂不判断？”

## 第七章：AUC——先不画线，看保安会不会把证据排对顺序

主管决定考核保安。

他没有先规定 τ，而是准备两摞比较记录：一摞确实是同一个人，另一摞确实是不同的人。

每次各抽一条，问：

> “同人的那条，相似度有没有比异人的那条更高？”

这就接近 **AUC** 的直觉。这里的 AUC 特指 **ROC-AUC**，不是其他曲线的面积。

- 同人比较 0.76，异人比较 0.18：顺序对了。
- 同人比较 0.30，异人比较 0.40：顺序反了。

如果大量这样的比较中，同人分数几乎总能排在异人前面，AUC 就接近 1；约为 0.5，表示这种排序能力接近随机。遇到同分时，通常按半次排序正确计。[参考：Google 对 ROC-AUC 的直觉解释](https://developers.google.com/machine-learning/crash-course/classification/roc-and-auc?hl=en)

你还可以把它想成主管不断移动 τ，观察每个位置“认出多少本人、放过多少异人”。把这些取舍画成 ROC 曲线，曲线下面的面积就是 AUC。你现在不必会画图，先抓住“整体区分和排序能力”就够了。

### AUC=0.9939，是不是识别准确率 99.39%？

不能这样读。

更贴近含义的读法是：在这批评估记录里，随机各拿一条同人比较和异人比较，同人那条的分数排在前面的机会约为 99.39%，同分按约定处理。

它没有告诉你生产到底选哪一个 τ，也没有把摄像头漏脸、跟踪断开、重复上报都算进去。

主管说：“你的整体排序不错。”

这和主管说“你明天值班一定不会认错人”，是两件不同的事。

即使 AUC 很高，少数难样本仍可能重叠；如果业务尤其不能接受误认，还得专门看严格阈值下的错误情况。

## 第八章：EER——找到两种错误率大致相等的位置

主管又做了一个实验：慢慢移动 τ。

线很低时，很多人都通过，误认较多，漏认较少。

线很高时，很少人通过，误认较少，漏认较多。

中间可能有一个位置，两种错误率差不多。

这个位置对应的错误率，叫 **EER，等错误率**。

用一张虚构的教学表看：

| τ | FAR：异人误接受 | FRR：同人误拒绝 |
| --- | --- | --- |
| 0.20 | 8% | 1% |
| 0.30 | 3% | 3% |
| 0.50 | 0.2% | 10% |

这个例子里，EER 是 3%，对应 τ 约为 0.30。

真实测试是一个个离散样本，两边未必恰好相等，评估程序可能取最接近的位置或插值估计。因此看报告时，可以先读成“让两类错误率接近平衡时，大概错多少”。[参考：美国 GAO 对等错误率的说明](https://www.gao.gov/assets/a157314.html)

### EER 对应的 τ，是不是应该直接用到门口？

不一定。

EER 方便在相同评估条件下比较模型，但没有替你决定“误认”和“漏认”哪一种代价更大。

如果门口更怕误认，可能会选比 EER 点更严格的阈值，并接受更多次“暂时认不出”。

所以三者可以这样记：

- **AUC**：整体上，会不会把同人分数排在异人前面？
- **EER**：两种错误率接近平衡时，错误率有多大？
- **τ**：实际运行时，把分界线放在哪里？

前两个是考试成绩的不同读法，最后一个是上岗规则。

## 第九章：保安学会了“不急着下结论”

主管发现，保安总被逼着回答“是小明”或者“不是小明”。

可现实里经常还有第三种状态：**这次证据不足，暂时不能确认。**

主管决定教他三种办法。

### 办法一：模糊照片先别进登记册

小明背光走来，保安拍到一张很模糊的脸。

主管说：“这张可以先观察，但别拿它更新小明的标准照。”

这就是**质量门控**：先检查脸的大小、清晰程度、姿态、遮挡、关键点和对齐是否可靠，再决定这张脸能做什么。

质量分回答“这张证据适不适合使用”，不回答“这是谁”。检测分高，也不保证它适合身份比较。

项目里的 `align_rms_norm` 是一种对齐几何指标：关键点与标准模板越不吻合，残差通常越大。先把它理解成“摆正这张脸时，五官位置是否协调”的提示。它不是身份分，也不能单独保证人脸清晰或真实。

这里可以设两道不同的门：

- **入册更严格**：只有可靠的照片能成为以后反复使用的参考。
- **查询允许更宽一些**：当前照片不完美，可以尝试与好参考比较；证据仍不够，就暂缓。

原因很直观：一次模糊查询主要影响这次判断，一张错误参考却可能持续误导后面的判断。

### 办法二：准备几张靠谱参考，别让两张烂照片互相比

保安之前拿“小明今天的模糊侧脸”和“小明昨天的模糊低头照”比较，结果很不像。

现在主管给他准备几张可靠参考：正脸、轻微转头、合适光照。

今天的查询照只要和其中一张确实匹配，就可能找到更好的证据。这就是**多参考匹配**的直觉。

但“参考越多越好”也不成立。用最大相似度挑结果时，参考更多，也给了异人更多次偶然撞上高分的机会。参考必须控制质量、数量和身份来源，增加参考后还要重新评估规则。

尤其不能“这次有点像小明 → 自动写入小明参考库 → 后面越来越像”，否则一次误认可能被自己不断强化。这叫参考污染。

### 办法三：不只看第一名，还看第一名领先多少

傍晚，一个人走来。

保安报告：“像小明，0.62。”

主管问：“像小王呢？”

保安说：“0.61。”

主管摇头：“这只能说明两个人都像，不能说明你认准了小明。”

于是多了一条规则：第一名除了够高，还要比第二名明显高。

这个领先幅度叫**边距**，常写作 **δ**，读作“德尔塔”。

假设教学规则要求 τ=0.45、δ=0.10：

| 最像谁 | 第一名 | 第二名 | 差多少 | 判断 |
| --- | --- | --- | --- | --- |
| 小明 | 0.62 | 0.61 | 0.01 | 虽过 τ，但竞争太接近，暂缓 |
| 小明 | 0.62 | 0.20 | 0.42 | 同时满足这两道分数规则 |
| 小明 | 0.40 | 0.10 | 0.30 | 虽领先，但第一名本身不够高，暂缓 |

τ 管“有多像”，δ 管“有没有明显比其他候选更像”。

通过两道分数规则后，真实系统仍可能需要质量、时序和身份冲突检查。它们不能保证绝不认错。

还要注意：实验里知道标签，才能说“本方参考”和“异方参考”；实际运行不知道答案，只能比较候选第一名、第二名，再用真值验收是否选对。不能把实验时知道答案的信息偷偷带进运行规则。

## 第十章：人没走，为什么保安报了三次“新访客”？

晚上，小明一直站在门口。

第一次面向镜头，系统找到他，给了临时编号 7。

接着他低头看手机，几帧没有检测到脸。旧跟踪结束了。

他再次抬头，系统又找到一张脸，给了临时编号 12。

保安喊：“又来了一位！”

可你明明看见人一直没走。

问题出在：**跟踪编号不等于人的身份，也不等于一次到访。**

可以把它们想成三本不同的账：

| 账本 | 记什么 | 例子 |
| --- | --- | --- |
| 短时跟踪 | 连续画面里的这个框 | 轨道 7、轨道 12 |
| 人员关联 | 两段观察是否可能属于同一个人 | 7 和 12 是否还是刚才那位 |
| 到访会话 | 业务上是否还是同一次来访 | 同一位还在门口，就不重复通知 |

这还引出一个区别：

> “我不知道他叫什么，但知道他可能还是刚才那位。”

这叫匿名人员关联，不要求先把所有陌生人录进熟人库。熟人识别回答“是不是已登记的小明”，匿名关联回答“是不是刚才那个未知访客”。两者目的不同。

### 为什么不直接规定“十秒内都算同一个人”？

因为小明可能刚走，小王立刻站到同一个位置。

如果只看时间和位置，小王会继承小明的会话，甚至继承不属于他的身份。

时间和位置能提供线索，却不能替代身份证据。合理的处理应结合外观、质量、时间和位置，并允许证据不足时保留独立状态，暂不合并。

如果两个人同时出现，还要避免同一时刻把两张不同的脸都塞进同一个人员会话。仅仅“每张脸各自挑最像的人”可能造成冲突。

### 多看几帧是不是就稳了？

多帧确认有助于过滤偶发误检，但连续几帧很像，往往因为它们几乎是同一幅画面，不能当成几次完全独立的证明。

而且前十帧看见小明，后面一直没看见，不应该把前十帧的票永远攒着，直到很久之后一帧又触发确认。

因此需要限定时间窗口、允许的中断、证据过期和连续确认规则。它们处理的是“证据怎样随时间积累和失效”，不是换一个更强的人脸模型就会自动具备。

## 第十一章：把项目报告里的那组数字翻译成人话

下面来自仓库的[质量筛选与保守参考策略评估](质量筛选与保守参考策略-2026-11-06.md)，不是本教学文档重新跑出来的结果。

### 1. “AUC=0.9939，EER=1.6%，阈值约 0.289”

这部分测试使用了 500 对同人照片、500 对异人照片。

它表达的是：

> 在这批照片配对中，模型总体区分能力较好。移动分界线到约 0.289 时，两类比较错误率接近，约为 1.6%。

它没有证明摄像头门口场景下，只有 1.6% 的访客会识别失败，也没有证明 0.289 适合生产。

### 2. “τ=0.45，FAR=0/500，FRR=5.2%”

把它换成数量更好理解：

- 500 对异人照片里，本轮没有观察到误接受。
- 500 对同人照片里，有 26 对没有通过。

这体现了第五章的取舍：严格一些，可能少认错，但多漏认。

**0/500 表示这次没抓到错误，不表示真实错误概率就是零。**

而且 500 个异人对中错 1 对，经验比例就已经是 0.2%。因此，看到报告里“FAR=0.1% 阈值”这样的表述，不应理解为这 500 对已经精确验证了千分之一的风险；还需要看阈值估计方法和更多独立样本。

### 3. “视频关联覆盖 98.4%，310/315”

报告中，前一段视频里的高质量脸用于建立参考，后一段视频里 315 张检出脸用于观察匹配。候选 τ=0.45、δ=0.10 时，310 张满足规则。

这里说的是“这批检出脸里有多少张获得关联证据”，不是“门口所有人有 98.4% 被成功识别”。摄像头没有检出的脸，本来就没进入这 315 张里。

它与上一节 LFW 照片配对的 5.2% 漏认也不矛盾：一个是短时同视频参考匹配，一个是不同照片之间的比较，输入条件、比较方式和统计对象都不同。

更关键的是：视频只有两个身份，参考与观察来自同一视频的时间切分，还不等于在独立门口素材上过关。

### 4. 为什么又说“单一全局阈值不可用”，又说“候选 τ=0.45”？

前者说的是：把所有脸直接两两比较时，同人和异人的分数重叠，单阈值不能把这批配对全部分对。

后者说的是：先筛选可靠参考，再拿查询脸去比参考，还加上领先幅度等条件，探索出一个候选操作点。

**比较对象和决策流程变了，分数分布也会变。** 这不是“发现一条万能分界线”，而是给保安换了一套更合理的取证和判断流程。

按这份项目记录，质量门控、参考库和边距属于探索评估；生产跨轨关联仍未启用，整体可靠性仍未通过。数字有帮助，但还不能替代独立场景和板端验收。

## 第十二章：真正站在门口时，遇到这些现象该先想什么？

保安上了一天班，你来问诊。

下面是理解问题的排查顺序，不是已经执行过的修复清单。

| 你看到的现象               | 故事里的原因          | 应先检查或考虑的处理                 |
| -------------------- | --------------- | -------------------------- |
| 人站着，却没有人脸框           | 第一位员工没找到脸       | 画面曝光、脸尺寸、遮挡、姿态、裁剪区域，再看检测器  |
| 脸框很好看，却认不出熟人         | 找脸成功，身份证据不足     | 对齐、查询质量、登记参考、同人分数，再评估身份阈值  |
| 检测分很高，身份分很低          | “像脸”和“像某人”是不同问题 | 分开查看两个阶段，别把检测分当身份可信度       |
| 一个人脸上出现大框套小框         | 检测器给了重复或错误候选    | 检查候选框去重、几何关系与轨道来源，防止多建轨    |
| 一低头就报新访客             | 检测中断，轨道变了       | 检查短期关联和到访会话，别只放宽识别阈值       |
| 新来的人继承上一人的身份         | 时间、位置或旧证据被过度信任  | 新身份证据、会话冲突、旧证据过期与参考更新条件    |
| 两人并排，名字互换            | 候选竞争接近或分配冲突     | 候选边距、同时出现约束，歧义时暂缓确认        |
| 偶尔认错后，越用越容易认错        | 误认样本写进参考库       | 暂停自动写入，审查参考来源，严格控制更新       |
| 单张图不错，视频很糟           | 单张身份能力没覆盖时序问题   | 分开验收识别、跟踪、恢复、换人、去重和事件      |
| 画面越来越落后于真人动作         | 处理慢，旧帧不断排队      | 分辨采集与推理耗时、队列长度，考虑丢弃旧帧而非积压  |
| PC 上正常，Jetson 上效果有差异 | 模型、预处理或运行环境有差异  | 同一输入逐阶段核对框、关键点、裁剪和特征；在板端复验 |

### Jetson 在这里扮演什么角色？

Jetson 是保安值班的工作台，模型才是处理图像的方法。

换更快的工作台，可以减少等待，让模型更及时地处理画面；但不会自动让低质量照片变清楚，也不会自动解决身份冲突。

反过来，模型再好，如果一直处理几秒前的旧帧，门口业务也会出问题。

GPU 是否真正参与加速，还取决于所用推理后端、构建方式和模型支持。不能因为程序跑在 Jetson 上，就认定它已经用了 GPU；本文不对当前板端加速状态作判断。

## 第十三章：还有一关，认得像不代表真的是活人

保安刚学会认小明，你拿着小明的照片走到门口。

他可能照样觉得“很像小明”。

因为刚才的人脸比较主要在判断图像中的外观身份，并没有自动回答“这是镜头前的真人，还是屏幕、照片里的脸”。

这属于**活体检测或呈现攻击检测**要处理的问题，需要额外证据与专门验证；加一个活体模型也不意味着所有照片、屏幕或面具攻击都能挡住。

同样，“认出小明”也不自动等于“允许执行任何操作”。身份结果和业务授权需要分别判断。

这不是本课要求你立刻实现的新功能，只是让你知道：人脸相似度解决的边界在哪里。

## 第十四章：第二天，你已经能听懂保安的汇报了

第二天早上，保安说：

> “检测到了脸，但有些侧，先没写进参考库。当前最像小明，分数过了 τ，不过和小王差得太少，没过 δ，所以暂时不确认。等下一张更清楚的脸，再结合短时跟踪继续判断。”

现在你可以逐句翻译：

“检测到了脸”——找脸这一关过了。

“有些侧，没写进参考库”——质量门在保护长期使用的证据。

“过了 τ”——相似度达到接受门槛。

“没过 δ”——与其他候选竞争太接近，还没认准。

“暂时不确认”——证据不足时保留未知，避免强行猜人。

“结合短时跟踪继续判断”——让后续观察接得上，同时防止换人后错误继承。

而当主管拿来报告说“AUC 很高，EER 较低”，你也知道：这是模型在指定考试里的表现。真正上岗，还要看所选 τ、质量筛选、参考策略、时序规则，以及整条业务链路的现场结果。

**一套识别系统的本事，既包括认准的时候给出答案，也包括证据不足的时候知道该等一等。**

## 随手查词

| 词 | 先记这一句话 |
| --- | --- |
| 人脸检测 | 在画面里找脸的位置 |
| 关键点 | 眼睛、鼻子、嘴角等位置线索 |
| 对齐 | 把脸整理到适合比较的方向和位置 |
| 特征向量 / embedding | 模型生成的数字“面孔名片” |
| 余弦相似度 | 比较两张特征名片有多像，不直接等于概率 |
| τ / 阈值 | 相似度要多高才接受 |
| FAR | 本文报告中，不同人被误判为同人的比例 |
| FRR | 本文报告中，同人没有被认出来的比例 |
| ROC-AUC | 同人分数排在异人分数前面的整体能力 |
| EER | 两种错误率接近平衡时的错误水平 |
| 质量门控 | 判断这张脸适不适合承担某种证据用途 |
| 参考库 | 拿来与当前脸比较的可靠特征集合 |
| δ / 边距 | 第一候选至少要领先第二候选多少 |
| 轨道 ID | 一段短时跟踪的编号，可能断裂或换号 |
| 匿名关联 | 不知道姓名，也尝试判断是否还是刚才那位 |
| 到访会话 | 业务上同一次来访的记录 |
