## 2. 板端编译 rkllm runtime

> ⚠️ **不要用官方 `build-linux.sh`！** 它写死了交叉编译器路径
> `~/opts/gcc-arm-10.2-2020.11-x86_64-aarch64-none-linux-gnu/bin/...`，
> 那是给 **x86 PC 交叉编译**用的。**在板子上本机编译会直接失败**（找不到该路径）。
> **用我准备好的 `build-on-board.sh`**（改用系统 gcc/g++）。

> ⚠️ **也不要从板子上克隆仓库**：实测板子直连 GitHub 只有 **37 KiB/s**，
> 773M 的仓库根本下不动。**用 PC 上打好最小包传过去**（见下）。

### 2.2 板端解压并编译

```bash
sudo apt update
sudo apt install -y cmake build-essential          # 只需这两个

cd ~
tar xzf rkllm-board-v1.3.1-v2.tar.gz               # ← 注意是 -v2
cd rkllm-board-v1.3.1                              # 解压后目录名不带 -v2

bash fix-perms.sh                                  # ★ 必须先做！补执行位
./build-on-board.sh
```

> ⚠️ **★ `bash fix-perms.sh` 这一步不能跳。**
> 本包在 **Windows 上用 bsdtar 打的**，而 **Windows tar 无法写入 Unix 权限位**，
> 所以包里所有 `.sh` 都是 `-rw-rw-rw-`（**没有 +x**）。
> 直接 `./build-on-board.sh` 会报 **`权限不够`**（这是 v1 没有的问题 ——
> v1 是在 WSL/Linux 里打的，保留了 `-rwxr-xr-x`）。
>
> ✅ **2026-10-17 起已自愈**：`build-on-board.sh` 与 `verify-persona.sh`
> **开头会自动 `chmod +x *.sh`**。只要用 `bash` 前缀启动一次，之后 `./xxx.sh` 全部可用。
>
> **不想补权限也行**，用 `bash` 直接调用即可（等效）：
> ```bash
> bash build-on-board.sh
> bash setup-sentinel-dir.sh
> bash verify-persona.sh
> ```
>
> 📌 **给 agent 的铁律**：凡"解压后跑脚本"的整行命令，
> **必须带 `chmod +x *.sh` 或统一用 `bash` 前缀**。此坑已反复踩 4 次
> （详见 `memory/04` 的 E-19），不要再依赖用户记得手动 chmod。

> ⚠️ **解压后的目录名是 `rkllm-board-v1.3.1`（不带 `-v2`）**，
> 只有压缩包文件名带 `-v2`。别在 `cd` 时加 `-v2`。
> **务必重编译**：板子上已有的可执行文件是官方版，不重编跑不出人设。

**成功标志**：看到 `llm_demo` 可执行文件生成在
`examples/rkllm_api_demo/deploy/install/demo_Linux_aarch64/`。

```bash
ls -la ~/rkllm-board-v1.3.1/examples/rkllm_api_demo/deploy/install/demo_Linux_aarch64/
# 应有：llm_demo  和  lib/librkllmrt.so
```

> ⚠️ **两种"看起来像失败"的情况，别搞混**（都实测踩过）：
>
> | 现象 | 真实原因 | 处理 |
> | :--- | :--- | :--- |
> | `error while loading shared libraries: librkllmrt.so` | **只是没设 `LD_LIBRARY_PATH`**，二进制本身没问题 | `export LD_LIBRARY_PATH=./lib:$LD_LIBRARY_PATH` |
> | 用法里没有 `system_prompt_file` | 编进去的是官方原版 | 查源码是否补丁版 |
>
> **可靠判据**（不依赖动态库）：
> ```bash
> strings ~/rkllm-board-v1.3.1/examples/rkllm_api_demo/deploy/install/demo_Linux_aarch64/llm_demo \
>   | grep -c system_prompt_file
> # 输出 >=1 → 补丁已编入；0 → 编的是官方原版
> ```
> **不要**用"直接跑 `./llm_demo` 看用法"当判据 —— 没设库路径时它会加载失败，
> 空输出会被误读成"补丁没进去"。

### 2.3 把 LLM 相关文件归整到 `~/sentinel/`（**推荐，一次性**）

> **目的**：把散落的模型、提示词、编译产出收进一个目录，
> 后续 `dialog/` 代码直接长在里面，路径也固定下来。

```bash
cd ~/rkllm-board-v1.3.1
./setup-sentinel-dir.sh
```

**归整后的板端结构**：

```
~/sentinel/
├── models/    Qwen3-0.6B_W8A8_RK3588.rkllm     ← 模型（889.8MB）
├── prompts/   system-prompt.txt                ← §5.1 提示词
├── rkllm/     demo_Linux_aarch64 → 软链到编译产出
├── rkllm-src/                                  ← 预留：runtime 源码
└── logs/                                       ← 预留：运行日志/tok·s 记录
```

> ✅ **脚本安全性**：**只移动、从不删除**；移动前检查目标是否已存在，
> **冲突时跳过而非覆盖**；移动后会**核对模型 SHA256**。
> `rkllm/` 用**软链**指向原编译产出，不复制 7.7MB 动态库。
>
> ⚠️ **模型核对不通过时不要继续跑复验** —— 否则会把"传输不完整"
> 误判成"模型有问题"，白折腾重转模型（这个坑见 `04` 的 P9 记录）。

## 3. 拷模型并跑通对话

```bash
# 在 PC 上拷到板子（板子实测 IP = 192.168.3.214，用户 cat）
scp "E:\哨兵管家\board-pkg\Qwen3-0.6B_W8A8_RK3588.rkllm" cat@192.168.3.214:~/models/
# 若 ~/models 不存在，先在板子上 mkdir -p ~/models
```

> 也可用 VSCode Remote-SSH 直接拖拽上传（你已在用这种方式连板子）。

**板端核对完整性**：

```bash
sha256sum ~/models/Qwen3-0.6B_W8A8_RK3588.rkllm
# 应输出：8064c9a9b78b7c1068e26dd8e9901109c715b0af29907379c66379dc412b7679
```

**运行**：

```bash
# 进入编译产出目录（路径以 build-on-board.sh 的输出为准）
cd ~/rkllm-board-v1.3.1/examples/rkllm_api_demo/deploy/install/demo_Linux_aarch64/

export LD_LIBRARY_PATH=./lib:$LD_LIBRARY_PATH    # 必须！否则找不到 librkllmrt.so
export RKLLM_LOG_LEVEL=1                          # 关键：打印性能日志

# 用法：llm_demo <模型路径> <max_new_tokens> <max_context_len>
#       参数个数必须 ≥ 4，否则只打印 Usage 就退出
./llm_demo ~/models/Qwen3-0.6B_W8A8_RK3588.rkllm 128 2048
```

> 源码里的用法定义（已核对 `llm_demo.cpp` 第 74-75 行）：
> `Usage: ./llm_demo model_path max_new_tokens max_context_len`

## 6. 常见故障

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `rkllm init failed` | 版本不匹配 / 文件损坏 | ① 核对 SHA256 ② 核对 runtime 是否为 1.3.1 |
| `librkllmrt.so not found` | LD_LIBRARY_PATH 没设 | `export LD_LIBRARY_PATH=./lib:$LD_LIBRARY_PATH` |
| NPU 报错 | rknpu 驱动过旧 | `sudo cat /sys/kernel/debug/rknpu/version` |
| 内存不足被 kill | 模型 890MB + 运行时开销 | 关掉无关服务；查 `free -h` |
| 输出乱码/重复 | 量化损失 / 参数不当 | 试 `max_new_tokens` 调小 |
