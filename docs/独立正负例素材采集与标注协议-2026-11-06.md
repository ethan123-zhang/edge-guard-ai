# 独立正负例素材采集与标注协议（2026-11-06）

用途：为「跨轨短期匿名关联」补独立正负例，验收质量筛选与保守参考策略能否在**换人、相邻双人、原人恢复、歧义**四种场景下不误并、不漏并。现有公开视频只有固定构图两人，不能替代本协议素材。

素材是任务前置条件；没有素材不得冻结相似度/边距门槛，也不得启用生产关联。

## 1. 拍摄要求

| 项 | 要求 |
| --- | --- |
| 机位 | 固定不动机位，模拟门口摄像头；镜头高度约 1.5 m，距站位 1.5–2 m |
| 分辨率/帧率 | ≥ 768×432，≥ 12 fps；优先 1080p 30fps |
| 人脸大小 | 站位时人脸框宽 ≥ 100 px（真实链路里低于 80 px 的脸不应作为关联证据） |
| 光线 | 正常室内光，避免逆光与强侧光；不要开美颜/磨皮 |
| 时长 | 每段 30–60 s，单个文件只演一个场景 |
| 画面 | 人被完全出画时，确实走出画面边缘（不是只转身背对） |
| 隐私 | 只拍本人或已同意的志愿者；视频只存本地忽略目录，不入 Git、不上传公开仓库 |

**录制工具**（2026-11-08 新增，免得再手搓一行 `cv2.VideoWriter`）：

```powershell
py -3.12 scripts/record_camera.py --list     # 先看本机摄像头与实测帧率
py -3.12 scripts/record_camera.py --dir datasets/scenarios/real-20261108
# 预览窗口里：T 开始、C 停止、Q 退出；停止后脚本自动回读校验并写 <视频>.capture.json
py -3.12 scripts/record_camera.py --headless --seconds 5   # 无人值守自检
```

- **本机索引**：`0` = 笔记本内置 HP True Vision FHD，`1` = 外接 **HD USB Camera**（就是接 Jetson
  的那颗）。脚本默认 `--camera 1 --width 1920 --height 1080`。
- **这颗外接相机 720p 只有 ~9 fps，1080p 才是 30 fps**（720p 走 YUY2，1080p 走 MJPG）；
  想拍 720p 30 fps 是做不到的，别把帧率低当成脚本卡了。内置相机反过来（720p 26 fps）。
- Windows 上 OpenCV 不支持按设备名打开，只能用索引；`--list` 装了 `pygrabber` 才会打印名字。
- 窗口实时显示**实测采集帧率**；录制中显示红点与时长。写盘帧率按实测值取舍，避免回放加速/变慢。
- `capture.json` 里的 `fps / frames / recorded_fps / video_sha256` 就是标注文件
  `fps/width/height` 与 `video_sha256` 的现成来源，不要手填。
- 现有 `datasets/scenarios/sc0*.mp4` 是 LFW 合成夹具，真实素材建议放子目录或用不同文件名。

## 2. 四个场景（各拍 2 条，便于复验）

### sc01 同位置换人（replacement）

A 走到标记点站 5 s → 完全出画 1–2 s → B 走到同一标记点站 5 s → 重复 2 轮。
A、B 外观可有差异，也可拍一条"同色衣服/相近发型"的困难版。

断言：B 首次确认必须新建会话；A 已上报的会话不得被 B 继承而漏报。

### sc02 跨位置相邻双人（adjacent）

A、B 并排站在画面左右两侧（间隔约 0.5 m），同框 20 s；中间 5 s 内两人交换左右位置（不遮挡彼此脸），再站 5 s。

断言：两条独立会话，同一时刻不得共享同一会话；交换后仍按各自证据关联。

### sc03 原人恢复（recovery）

A 站 5 s → 完全出画 5–10 s → A 回原位站 5 s；重复 2 轮。中间可加入转头、低头，但不换人。

断言：证据足够时 A 必须关联回原会话（本地事件仍 1 条）；证据不足时保留独立候选，不得强并。

### sc04 歧义（ambiguity）

同一段内拍三个子例：① A 站定后 1 s 内换成 B；② A 转身背对 3–5 s 再转回；③ A、B 外观相近、先后站同一位置。

断言：不得强行合并；保留独立候选并记录"未关联/歧义"理由。

## 3. 标注格式

标注文件为 JSON（UTF-8），与实际视频同目录、同名 `.json`：

```json
{
  "schema": "sentinel/scenario-annotation@1",
  "video": "sc01_replacement.mp4",
  "video_sha256": "<64 hex>",
  "fps": 12,
  "width": 768,
  "height": 432,
  "scenario": "replacement",
  "notes": "A=左位深色外套, B=右位浅色衬衫",
  "frames": [
    {"frame_index": 0, "t_ms": 0,
     "faces": [{"identity": "A", "bbox": [120, 90, 140, 150]}]},
    {"frame_index": 6, "t_ms": 500,
     "faces": [{"identity": "A", "bbox": [122, 91, 141, 151]},
               {"identity": "B", "bbox": [430, 95, 135, 148]}]}
  ]
}
```

标注规则：

- `identity` 在同一段内稳定唯一（A/B/…），不是模型输出，是人工真值。
- 只标**可见人脸**；被遮挡、背对、出画时该帧不写这个人，不要编框。
- `bbox` 用像素坐标 `[x, y, w, h]`，框住人脸（可略松，不要包含整头或身体）。
- 允许每 6 帧标一次（与评估抽样对齐）；场景切换点前后建议逐帧标。
- 标注文件入 Git 前必须确认不含图像、特征向量或身份库信息。

## 4. 复算与验收

素材齐备后，用与[质量筛选研究](质量筛选与保守参考策略-2026-11-06.md)相同的质量指标与规则复算：

1. 按场景分别统计 `own`、`own − other` 分布与关联覆盖。
2. 逐条核对第 2 节的断言；换人场景错关联必须为 0，恢复场景漏关联需给出证据不足的理由。
3. 在独立素材上重新选 τ/δ（不得沿用现有视频调出的值），并记录选择依据。
4. 板端（OpenCV 4.1.1）复跑质量指标分布，确认 `rms_norm` 门槛跨版本可用。
5. 以上全部通过后，才把关联层实现与门槛写进限定任务卡，并保持生产默认关闭。

评估脚本的 `--annotations` 入口尚未实现；素材到位后先补该入口并用合成标注做单测，再跑真实素材。

## 5. 存储与清理

- 视频与标注草稿放 `datasets/scenarios/`（已在 `.gitignore` 的 `datasets/` 下），不入 Git。
- 入库的只有汇总统计与结论；需要逐帧证据时只保留不含人脸像素的框/余弦汇总。
- 项目结束或用户要求时删除原始素材；删除前确认没有其他评估依赖。
