# 无头注册与终端自检（Jetson / SSH）

> 2026-11-07 · 板端没有显示器、SSH 下没有 X —— 现场注册人脸与现场排障都必须在**纯终端**里完成。
> 本文对应两个脚本：`scripts/camera_watch.py`（新增）与 `scripts/enroll_faces.py --auto`（新增）。

## 为什么需要

板子是 Jetson Nano，现场不接显示器；SSH 会话里也没有 X server。原来的交互式注册
`scripts/enroll_faces.py --camera 0` 依赖 `cv2.imshow` / `cv2.waitKey`，在 SSH 里一调用就
`cv2.error`（Qt/GTK 支持没编进这个 L4T OpenCV），**必崩**。于是：

- **现场注册**：`enroll_faces.py --auto` —— 倒计时后自动连续取帧，按质量门挑帧，全程只打印文字；
- **现场排障**：`camera_watch.py` —— 每秒一行看 fps / 人脸 / 框大小 / 质量，Ctrl-C 优雅退出。

两条命令都只用 `vision.config.load(profile)` 里的参数（阈值、分辨率、FOURCC 都在配置里），
组件装配和 `scripts/vision_sim.py` 完全一致：`runtime.backend` 是 `auto/cpu/trt` 就走
`onnx_pipeline`（YuNet + SFace），是 `legacy` 就走旧路径。

## 命令一：终端实时自检 `camera_watch.py`

板端（真实摄像头，`board.yaml`：v4l2 / MJPG / 1280×720 / 30fps）：

```bash
cd ~/sentinel-quality-20261106
export OPENBLAS_CORETYPE=ARMV8 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
python3 scripts/camera_watch.py --profile board --duration 5
```

真实输出（2026-11-07 板端，空房间，TensorRT 路径）：

```text
[watch] 后端：runtime.backend=auto → onnx（检测 yunet-onnx(tensorrt(yunet_fp16.engine), ...) / 识别 sface-onnx(tensorrt(sface_batch_fp16.engine), batch<=8)）
[watch] 视频源=camera device=0 1280x720 backend=v4l2 fourcc=MJPG fps=30
[00:01] fps=17.8 帧=18 人脸=0（画面里没人） | 已知库=0 人
[00:02] fps=18.7 帧=38 人脸=0（画面里没人） | 已知库=0 人
...
[watch] 结束：帧=99 时长=5.1s 平均fps=19.3 有人脸帧=0.0% 最大脸=0px
```

有人脸、且命中已知库时（本机视频源示例）：

```text
[00:01] fps=69.0 帧=69 人脸=1 最大框=233px 分数=0.88 质量=0.10 已知=probe conf=0.94 | 已知库=1 人
```

参数：

| 参数 | 默认 | 说明 |
| :--- | :--- | :--- |
| `--profile` | `board` | 配置档（`vision/config/*.yaml`） |
| `--config-dir` | `vision/config` | 换配置目录（模型路径等） |
| `--source` | 配置里的 `camera.source` | 摄像头序号 / 视频文件 / 图片目录 |
| `--duration` | `0`（一直跑） | 跑多少秒后自动退出 |
| `--no-recognize` | 关 | 跳过 SFace 推理，只测检测/取景（**启动时仍会装载识别模型**，只是每秒不再跑识别） |
| `--jsonl PATH` | 无 | 每帧检测结果逐行落盘（含 bbox / score / quality，末尾一条 summary） |

行格式：`fps` 是**累计平均**；`帧` 是累计帧数；`人脸` 是这一秒里**同一帧最多**检测到几张；
`最大框` 是这一秒最大人脸的高度（px）；`质量` 是 `align.quality()`（越小越好，见下节）。
**每行只在 1 秒边界打印一次**，不会刷屏；`Ctrl-C` 走 `finally` 释放摄像头后正常退出。

## 命令二：无头现场注册 `enroll_faces.py --auto`

板端（现场站在镜头前，一次命令完成注册）：

```bash
python3 scripts/enroll_faces.py --auto --profile board --id p_10023 --name 王阿姨
```

流程：打印「3 秒后开始，请正对镜头」→ 倒计时 → 每 `--interval`（默认 0.6 s）取一张、共
`--samples`（默认 5）张 → 每张跑检测 → 过质量门的帧「采纳」，其余「丢弃」→ 采纳的帧取平均
写进 `vision/face_db/<id>.npy`（走原来的 gallery 保存逻辑，`--id/--name` 不变）。

板端真实输出（2026-11-07，摄像头对着空房间 —— 这就是「未采纳」的样子；为省时间用了
`--countdown 1 --samples 3`）：

```text
[enroll] 1 秒后开始，请正对镜头
[enroll] 第 1 张：没检测到人脸 → 丢弃
[enroll] 第 2 张：没检测到人脸 → 丢弃
[enroll] 采集结束：采纳 0/3 张
[enroll] 没有采集到任何特征，未保存
[enroll] --auto 未采纳：先用 scripts/camera_watch.py --profile board 看到画面/人脸，...
```

本机没有摄像头时，用视频文件自测同一条取帧/质量门路径（**用临时人脸库，别污染真库**）：

```powershell
py -3.12 scripts\enroll_faces.py --auto --profile board `
  --source datasets\doorway-20261107\raw\d03_cafe_entry_woman.mp4 `
  --samples 3 --id probe --name Probe --gallery-dir <临时目录>
```

```text
[enroll] 质量门：人脸高度 >= 80px，对齐质量 <= 0.16（association.quality_max_rms）
[enroll] 第 1 张：框 217px 分数 0.92 质量 0.077 → 采纳
[enroll] 第 2 张：框 213px 分数 0.90 质量 0.059 → 采纳
[enroll] 采集结束：采纳 3/3 张
[enroll] 已保存 probe（Probe），共 3 个样本；人脸库现有 1 人
```

参数：

| 参数 | 默认 | 说明 |
| :--- | :--- | :--- |
| `--auto` | — | 无头采集（不开窗口、不 `waitKey`）；与 `--images` 互斥，与 `--camera` 互斥 |
| `--source` | 配置里的 `camera.source` | 仅 `--auto`：摄像头序号 / 视频文件 / 图片目录（复用 `vision.camera.create_source`） |
| `--samples` | `5` | 取几张候选帧 |
| `--interval` | `0.6` | 每张间隔秒数 |
| `--countdown` | 摄像头 3 s / 视频文件 0 s | 开始前倒计时 |
| `--min-face-px` | `detection.min_face_px`（80） | 人脸高度下限 |
| `--gallery-dir` | `recognition.gallery_dir`（`face_db`） | 换人脸库目录（自测用临时目录） |

## 注册质量怎么看

一道门、三个量，全部来自配置：

1. **质量 = `align.quality()`** = 五点对齐残差 ÷ 眼距（`align_rms_norm`），**越小越可信**。
   门限 `association.quality_max_rms`：`board.yaml` 是 **0.16**，`base.yaml` 默认 0.10。
   板端实测 40 帧 79 张脸：p10 0.111 / median 0.145 / p90 0.287 —— 0.16 这道门入册率约 58%，
   而质量和「是不是同一个人」强相关（0.05~0.10 通常是正面清晰；0.2 以上常见于侧脸、背光、
   关键点抖动，宁可丢弃重采）。
2. **人脸高度 ≥ `detection.min_face_px`**（默认 80px）。720p 下 1~2 m 正脸通常 150~350px；
   小于 80px 说明离太远，特征不可靠。
3. **检测分数 ≥ `detection.score_threshold`**（0.6）—— 低于门限根本不会出现在检测结果里。

采纳数 ≥ 1 才会保存（多张取平均，比单张稳）；**全部丢弃时退出码 1**，并打印排查提示。
想复现「未采纳」：`--min-face-px 2000` 之类的参数即可让所有帧都过不了门。

## 采不到脸怎么排查（按顺序）

1. 先跑 `camera_watch.py --profile board --duration 5`：
   - `fps=0` / `一帧都没拿到` → 摄像头没出流（见 2、3）；
   - `fps≈18 人脸=0（画面里没人）` → 流正常，是**视野里没脸**（见 4、5）。
2. **设备/占用**：别的进程（vision_sim、上次没退干净的 probe）占着 `/dev/video0` 时打不开；
   跑完的进程必须释放（两个脚本都在 `finally` 里 `release()`）。
3. **采集格式**：`board.yaml` 必须是 `backend: v4l2` + `fourcc: MJPG` + `fps: 30`。
   板端实测 `backend: auto` 会落到 GStreamer 后端，不认 FOURCC，50 帧连续读不到；
   不写 MJPG 会被协商成 YUYV，采集只有 9.9 fps。
4. **距离/角度**：脸高 < 80px = 太远；正脸、眼睛平视镜头，别低头/侧脸。
5. **光线**：背光、逆光、暗光都会把质量推过 0.16（丢弃），补光或换位置再采。
6. **模型**：行尾出现 `未知（识别器 none）` 说明没有 SFace 模型，注册也会直接报「识别器是 none」。
7. **取证**：`--jsonl watch.jsonl` 落每帧 bbox/score/quality；`--no-recognize` 用来区分
   「检测/取景问题」还是「识别问题」。

## 和交互式路径的区别

| | 交互式 `--camera` | 无头 `--auto` |
| :--- | :--- | :--- |
| 需要显示器 / X | 是（`imshow`） | **否**，纯终端 |
| 人怎么参与 | 看预览窗口按 SPACE/ENTER/q | 倒计时后全自动 |
| 取哪些帧 | 人凭感觉按 | 质量门自动挑（分数 + `align.quality()` + 脸高） |
| 输出 | 预览窗口 | 逐张「第 i 张：框 320px 分数 0.91 质量 0.08 采纳/丢弃」 |
| 板上可用 | 否（SSH 里 `imshow` 必崩） | 是 |
| 原有行为 | 完全保留 | 新增，互不影响（`--auto` 与 `--images`/`--camera` 互斥） |

## 附：本机（Windows `E:\哨兵管家`）自测的路径限制

板端 Linux/UTF-8 没这个问题。本机仓库路径含中文，OpenCV 的 ONNX 读取走窄字符 `fopen`，
读不了中文路径（项目记忆里的 **E-48**），所以本机直接跑 `--profile board` 会 exit 2 并提示。
自测办法：把模型拷到纯 ASCII 目录，用 `--config-dir` 指一份把 `detection.model` /
`recognition.model` / `runtime.detector_onnx` 改成 ASCII 绝对路径的配置（本次验收就是这么跑的）。
