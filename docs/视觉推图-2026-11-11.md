# 视觉推图：事件与照片分开走，照片按 msg_id 绑定（2026-11-11）

> 任务书阶段 2 的最后一环：视觉节点（Jetson）的 `face_event` 已经能到主人端（鲁班猫），
> 但**照片还在 Jetson 本地**，看板/APK 只能显示"缺图·采集中"。本文记录这一环的实现、
> 配置、上板方式与验收证据。
>
> 证据：[vision-snapshot-push-2026-11-11.json](data/vision-snapshot-push-2026-11-11.json)
> · 设计依据：[主人端-设计与接口 §5](主人端-设计与接口-2026-11-11.md)

## 1. 契约（不改已有事件字段）

```
Jetson 存完 JPEG ──POST /vision/snapshot?msg_id=&face_id=&frame_ts=──▶ 鲁班猫 :8766
        header: X-Vision-Key: <与 master.local.yaml security.vision_key 一致>
        body:   JPEG 原字节（Content-Type: image/jpeg）
```

- `msg_id` **必须就是产生这张图的 `face_event.msg_id`**（任务书 §二.4：不按文件名/时间猜归属）。
- 乱序安全：照片先到只登记 `snapshot_asset`；事件后到时靠 `visit_event` join，详情页先显示缺图。
- 重复上传同一 `msg_id` 幂等（主人端返回 `duplicate: true`，不覆盖、不重复登记）。

## 2. 代码

| 位置 | 作用 | 关键约束 |
|---|---|---|
| `vision/snapshot_push.py` | `SnapshotPusher`：有界队列 + 守护线程 + 有界 HTTP | `enqueue()` 永不阻塞/抛；队列满丢最新并计 `dropped`；`close()` 先把队列发完 |
| `vision/service.py#_report` | 一张图只编码一次：本地落盘与推图共用 JPEG 字节 | 推图不依赖 `save_snapshots`（关掉本地落盘也能推） |
| `vision/service.py#run` | 收尾 `finally` 里 `pusher.close()` | 主循环退出前把已入队的发完 |
| `vision/config.py` | `output.snapshot_push` 默认值 + 校验 | 开启时必须 `http://...`、`timeout>0`、`queue_size>=1` |
| `scripts/board_vision.sh` | 板上常驻启停（start/stop/status） | 密钥读 `$APP_DIR/.env` 并 **export**；`python3 -u` |

为什么用线程而不是在 `_report` 里同步 POST：主循环 17 fps，对端没起/accept 了不应答时
一条 POST 会把帧率拖到 8 fps 以下（`ws_client.py` 2026-11-07 已在事件通道踩过）。
推图失败只记账（`failed`/`last_error`），**不影响事件上报**。

## 3. 配置

```yaml
# vision/config/base.yaml（默认关）
output:
  snapshot_push:
    enabled: false
    url: ""
    key: ""          # 空 = 读环境变量 SENTINEL_VISION_KEY（不进仓库）
    timeout: 2.0
    queue_size: 8

# vision/config/board.yaml（板上打开）
output:
  snapshot_push:
    enabled: true
    url: http://192.168.5.11:8766/vision/snapshot
server:
  ws_url: ws://192.168.5.11:8765      # 鲁班猫的视觉入站口
```

密钥两条路：`export SENTINEL_VISION_KEY=...`，或板上写 `/home/jetson/sentinel-vision/.env`
（`chmod 600`）。**不设密钥时事件照常上报，只关推图**，启动日志会明说缺哪个变量。

板上跑 OpenCV 必须 `OPENBLAS_CORETYPE=ARMV8`（脚本已带）；摄像头必须 `v4l2 + MJPG`
（已在 `board.yaml` 写死）。

## 6. 踩坑（都已修）

1. **`nohup` 重定向后日志为空**：python3 的 stdout 块缓冲，`tail -f` 看不到任何输出，
   现场会以为进程没起来。→ 脚本用 `python3 -u`，`vision_sim.log()` 加 `flush=True`。
2. **`. ./.env` 不 export**：变量只在 shell 里，子进程 python 拿不到，日志报"缺少共享密钥"。
   → 显式 `export SENTINEL_VISION_KEY`，并用 `/proc/<pid>/environ` 验证（`grep SENTINEL`）。
3. **本机 OpenCV dnn 读不了中文路径的 ONNX**（`E:\哨兵管家\vision\models\...` 直接报
   `Can't read ONNX file`）：本机联调要把模型拷到纯 ASCII 目录再改配置；板上是 Linux/UTF-8，无此问题。
4. **摄像头摆位**：实拍帧糊成一片时 YuNet 仍会给出高置信假框（bbox 覆盖大半画面），
   产生 1 条假到访 —— 演示前必须把镜头对向门口/桌面，这是摆位问题不是检测回归。
