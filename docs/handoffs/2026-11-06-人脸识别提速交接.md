## 当前速度基线（板端，40 采样帧中位）

| 阶段 | CPU dnn | TensorRT 封装（默认关） |
| --- | --- | --- |
| 检测（engine/前向） | ~52 ms + 解码 31 ms | 11.7 ms + 解码 31 ms |
| 检测段合计 | 83.8 ms | 45.9 ms |
| SFace（该帧所有脸） | 218.1 ms | 35.8 ms（批量） |

**瓶颈已经定位**：旧 `decode()` 每帧在纯 Python 重建 5875 个先验框 + NMS ≈ **31 ms**，把检测段的 GPU 收益吃掉一半。单跑 engine 是 11.7 ms，检测段理论值应能压到 ~15 ms。

## 下一步顺序（建议直接按 P0→P3 做）

### P0 解码先验预计算（收益最大、风险最低）

- 位置：`logs/video-validation/legacy-pipeline-probe.py` 的 `decode()`，生产侧将来要进 `vision/`。
- 做法：把四档先验表（40/20/10/5 网格）在模块加载时算一次并缓存；NMS 用 `cv2.dnn.NMSBoxes` 保持；输出仍为 15 列数组（bbox + 5 关键点 + score）。
- 验收：固定视频 40 帧，检出脸数/bbox 与旧解码逐帧一致（≤0.0001 px）；解码耗时 <5 ms；228 项单测通过。
- 参考命令：

  ```powershell
  py -3.12 logs\video-validation\scenario_eval.py --scenario-dir datasets\scenarios `
    --model-dir vision\models --helper logs\video-validation\legacy-pipeline-probe.py `
    --output logs\video-validation\scenario-eval-20261106.json
  ```

### P1 接进 `VisionService`（默认关闭，`auto` 才启用）

- 新增一个后端选择入口（例如配置 `runtime.backend: auto|cpu|trt`），服务启动时 `create_backend()`；返回 `None` 就保持 CPU。
- 检测：用 TRT engine 出原始输出 → 新解码；识别：对齐后按批送入 SFace engine。

## 已知坑（都已在代码/文档里处理）

1. 板端 `cv2` 4.1.1 没编 CUDA；不要重编 OpenCV，走 TensorRT。
2. YuNet ONNX 声明输入 120×160，实际喂 320；TRT 要用 320 声明副本（`yunet_2022_opset9_trt320.onnx`）。
3. SFace 原 ONNX 是静态 batch=1；动态批量要另存 batch 维为 `N` 的副本（`sface_dynamic_batch.onnx`）。
4. pycuda 不能只存 int 指针（DeviceAllocation 被 GC 后 memcpy 报 invalid argument）；封装里已保留对象。
5. 固定机位合成素材对旧解码器的大脸先验网格敏感（5×5、步长 64），位置选错会整帧漏检。
6. 板端 numpy/cv2 import 需要 `OPENBLAS_CORETYPE=ARMV8`。
