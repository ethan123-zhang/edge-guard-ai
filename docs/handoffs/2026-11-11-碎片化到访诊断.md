# 诊断：同一个人被反复记成新到访（2026-11-11）

> 现象反馈：用户一直坐在电脑前（应是一次连续在场），手机看板却持续出现"同一个访客"的多条到访。
> 结论先行：**不是配置变化导致的，也不是 120 秒会话窗口的问题**；
> 根因是这些脸过不了质量门、没有可用特征向量，关联层退化成"只按轨道连续"，
> 轨道一断（抬手/转头超过 2 秒）就新建会话 → 新访客 → 新到访。

## 1. 证据：同一人 11 秒被记成两条

DB（`data/sentinel.db`）当时 16 条到访 = **16 个不同的 `unk_<帧时间戳>` 身份**，
每条一张照片、全部 `completed=0`、没有 `departed_at`：

```
21:15:25  v_20261111_0014  face=unk_1794402924331
21:15:36  v_20261111_0015  face=unk_1794402936011   ← 同一个人的新轨道
```

取两张快照对比：黄卫衣、眼镜、耳机，**同一个人**；第二张里正抬手挡脸。

视觉端日志（`journalctl -u sentinel-vision`）逐行对应：

```
21:15:25 会话 37 是弱证据建出来的 → 上报 unk_1794402924331     ← 新建到访 v_0014
21:15:29 关联层：轨道 89 并入会话 37（理由 track_bound；同类 — / 异类 —）
21:15:36 会话 38 是弱证据建出来的 → 上报 unk_1794402936011     ← 又新建 v_0015
21:15:44 关联层：轨道 92 并入会话 37（理由 track_bound；同类 — / 异类 —）
21:15:50 关联层：轨道 95 并入会话 37（理由 track_bound；同类 — / 异类 —）
21:18:01 关联层：轨道 102 并入会话 37（理由 track_bound；同类 — / 异类 —）
```

`同类 — / 异类 —` = **外观分数为空**，说明这些会话里没有存进任何特征向量，
关联层只能靠"轨道连续"判同一个人。

## 2. 根因链

1. 摄像头在室内、脸偏侧/距离远/常被手或耳机遮挡 → 对齐残差 `rms_norm` 过不了质量门
   （`association.quality_max_rms: 0.16`）→ 该会话**没有入册特征**（日志称"弱证据建出来的会话"）。
2. 关联层的外观比对（`tau=0.45 / margin=0.10`）没东西可比 → 退化为 `track_bound`：
   只有同一空间轨道在 `track_ttl_sec: 2.0` 秒内连续才算同一个。
3. 手抬起挡脸、转头看屏幕超过 2 秒 → 轨道被回收 → 下一帧检测到是**新轨道** →
   **新会话** → 首报确认后上报 → 主人端新建到访。
4. 主人端的 10 分钟业务复用窗口（`dialog/visits.py` `WINDOW_MIN=10`）是**按 face_id** 算的；
   陌生人每次是新的 `unk_<帧时间戳>`，所以这层对陌生人完全兜不住。
5. 120 秒的 `session_ttl_sec` 在这个场景里没参与判据——没有特征时到不了外观比对这一步。

这也是 2026-11-01 就记录过的老问题在真实场景里的表现：
[自然姿态本地事件验收](自然姿态本地事件验收-2026-11-01.md) 里"两人持续在场 287 个采样点，
预期 2 条事件，实际 12 条（12 个不同轨道）"。

## 3. 排除"配置变化"

- Jetson `sentinel-vision` 从 **20:04:17 启动后没有重启过**（journal 里只有 1 条 Started），
  PID 4997 一直没变；本轮改动全在 20:44 之后、且只碰主人端（`/api/health` 鉴权、重启/reboot 鲁班猫）。
- 重复到访在 **20:30:42 / 20:31:15 / 20:31:57** 就出现，早于本轮第一次改动。
- 主人端重启最多让当时那条"进行中的接待"丢上下文，不会凭空造多条事件；
  事件是按 `msg_id` 幂等的（`VisitBook.arrive` 重复 `msg_id` 只返回既有结果）。

## 4. 本次调整（2026-11-11 21:35 生效）

`vision/config/board.yaml`：

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `recognition.track_ttl_sec` | 2.0 | **5.0** | 短时丢脸（抬手/转头 2–5 秒）不再拆轨道 |
| `association.track_ttl_sec` | 2.0 | **5.0** | 与上一条对齐 |
| `association.quality_max_rms` | 0.16 | **0.20** | 让侧脸也能入册，外观关联才有东西可比（有"错并"风险，要复测） |

`session_ttl_sec` **保持 120**（它对当前的失败路径不起作用，改它没有意义）。

生效确认（重启后启动日志）：

```
[vision] 关联层：开（tau=0.45, margin=0.10, 质量门 rms<=0.20）
```

## 5. 复测方法与结果

**方法**：21:36 起用户自然坐在摄像头前 10 分钟（看屏幕、转头，中途抬手挡脸 1–2 秒），
统计新增到访条数，并看关联层日志里是否开始出现真实外观分数（`同类 0.xxx` 而不是 `—`）。

**结果**：见 §6（本次实验由后台任务采集，完成后回填）。

## 6. 复测结果（2026-11-11 21:36–21:46）

**结果：10 分钟自然坐姿只新增 1 条到访**（`v_20261111_0018`，21:42:18，照片仍是同一个人：
黄卫衣/眼镜/耳机），其余 9 分钟没有新事件。

对照：

| 时段 | 场景 | 新增到访 |
|---|---|---|
| 20:30–21:19（改前，约 49 分钟） | 用户在桌边做 adb 操作、时不时挡脸/转头 | 10 条（含 3 条在 75 秒内、2 条在 28 秒内、2 条在 11 秒内） |
| 21:36–21:46（改后，10 分钟） | 自然坐着（中途按约定抬手挡脸 1–2 秒） | **1 条** |

日志证据（改后窗口）：

```
21:35:34 [vision] 关联层：开（tau=0.45, margin=0.10, 质量门 rms<=0.20）
21:35:34 [vision] 首报确认（轨道 1：3 帧 / 166 ms，理由 track_bound）→ 上报 v_0017
21:42:18 [vision] 会话 2 是弱证据建出来的 → 上报 unk_1794404537960   ← 10 分钟里唯一的重复
21:42:38 [vision] 上报：轨道 8 全程没有合格证据（残影/侧脸）→ 不报
```

**怎么读这个结果**：

- 改善是真实的：改前几十秒就能刷 2–3 条，改后 10 分钟只有 1 条。
- 但这 10 分钟里**没有任何"关联层：轨道 X 并入会话 Y"且带外观分数**的日志，
  说明质量门放宽到 0.20 **没有真正触发外观并人**——改善主要来自 `track_ttl_sec` 2→5 秒
  （轨道断得短就不拆轨）。
- 剩下这 1 条仍发生在"抬手挡脸"之后：那一刻脸没有可用特征、轨道又断得超过 5 秒，
  于是照样新建会话。
- 实验不是严格对照（改前用户在操作电脑、改后是静坐），只能算观察性证据。

## 6.1 建议的下一步（未做）

1. 想再压重复：把 `recognition.track_ttl_sec` / `association.track_ttl_sec` 再放到 8–10 秒，
   再用同样 10 分钟复测；代价是"人真的走了但轨道还留着"的时间变长，风险较小。
2. `quality_max_rms=0.20` 在这段场景里**没有观察到触发外观并人**，所以它的收益是未证实的；
   风险（把不同的人并成同一次在场）也还没被触发。当前保留的是**已实测过的组合**
   （track_ttl=5 + quality=0.20，10 分钟 1 条），演示前如有条件，补一次"换人/相邻双人"短测；
   无条件就保持现状，不要在没有复测的情况下继续往上放。
3. 演示场景（访客走进来、说一两句、离开）本来就短，这个碎片化影响远小于"长时间坐在镜头前"。

## 7. 风险与后续

- `quality_max_rms` 放宽会增加"错并"（把不同的人并成同一次在场）的概率；
  若复测出现错并，回退到 0.18 或只保留 `track_ttl_sec=5`（风险最低的一组）。
- 演示前仍要清库（现有 17 条全是调试到访），清库会连带让手机 token 失效。
- 长期解法（未做）：主人端加"业务级到访去重"（按门口/时间窗而不是 `face_id`），
  或给陌生人做外观聚类后再落到业务层。
