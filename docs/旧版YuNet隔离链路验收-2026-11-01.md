# 旧版YuNet隔离链路验收

结论：**实验副本已在Jetson原有OpenCV4.1.1跑通四帧检测、五点关键点、相似变换对齐与SFace特征提取。** 无需为本次实验升级系统。检测覆盖、人员区分与跨轨去重仍未验收，不能启用生产关联。

## 【输入输出定义】

输入为OpenCV官方旧版YuNet固定提交`c97242ce7f2a554e288b50eabd9f5df957e78801`、已有SFace及已有公开视频。测试源帧为0、120、720、1500，320×320输入，置信度门槛0.9，NMS门槛0.3。

输出见[结构化证据](data/jetson-2026-11-01-legacy-yunet-capability.json)：模型哈希、转换节点、四帧等价性、板端前向、框/五点与特征维数。没有保存图像或特征向量；左右仅为既有固定构图的评估标签，不作为生产身份。

官方来源：[旧模型固定提交](https://github.com/opencv/opencv_zoo/tree/c97242ce7f2a554e288b50eabd9f5df957e78801/models/face_detection_yunet)、[OpenCV4.5.5检测解码](https://github.com/opencv/opencv/blob/4.5.5/modules/objdetect/src/face_detect.cpp)、[对齐与特征实现](https://github.com/opencv/opencv/blob/4.5.5/modules/objdetect/src/face_recognize.cpp)。

## 【核心算法逻辑伪代码】

```text
原YuNet2022加载 → 板端报缺少Slice starts
本机检查图：opset11、3个Slice的参数均为常量、5个MaxPool ceil_mode均为0
实验副本：Slice常量输入转starts/ends/axes属性（只允许step=1）
→ 删除默认ceil_mode=0 → 标记opset9 → ONNX checker
PC同一4帧：原图/副本各执行一次，逐输出检查有限性和数值误差
板端副本 → loc/conf/iou → 按官方旧版先验框和公式解码 → NMS
原图尺度五点 → 相似变换对齐112×112 → SFace前向 → 有限性/维数检查
```

原模型SHA256为`50ef07f702a31741ca46a4c0d947773b64143b9362780237bf0d427d6c79bab7`；实验副本为`f664a8d7e393935dc6d6e0823da8f903c84ae816b66a97d7157b9320f9d21b2f`。原模型没有被覆盖。转换仅针对该固定模型，不是通用ONNX降级工具；自动版本转换未成功，未把失败输出用于测试。

## 【异常与边界条件】

- 原2022模型直接导入同样失败；成功的是经过校验及有限样本等价检查的实验副本。
- 四帧数值等价不是任意输入的全局等价证明，ONNX checker只证明结构合规。不同OpenCV版本输出存在数值差异，不声称PC与板端逐数相同。
- 解码预处理沿用官方无均值减法；前轮加载/张量冒烟不能替代这里的正确预处理链路。
- 对齐实现的本机结果与原生alignCrop比较，三个人脸样本的平均绝对像素差均小于0.0002；此对照不等于板端识别精度验证。
- 10秒与60秒处均未检出，125秒处只检出一张脸。不得以首帧两脸通过代替自然姿态覆盖率验收。
- 四帧相似度只作观察：板端右侧125秒对首帧右侧约0.722，对首帧左侧约0.065；不能以这一个正例和少量负例冻结生产阈值。
- 未修改生产算法、配置或系统依赖，未读取身份库、调用摄像头或保存帧/向量。模型、实验脚本与原始诊断在忽略目录；临时认证读取桥接脚本已移除。
