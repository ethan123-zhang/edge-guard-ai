## 【核心算法逻辑伪代码】

```text
校验文件/参数/输出路径 → 初始化一个检测器和一个跟踪器
顺序解码，按累计解码序号/fps建立显式人工循环媒体时钟
按媒体2Hz采样，并按单调墙钟节拍运行到600秒
EOF只重开视频解码器，不重置检测器、跟踪器、事件状态或累计时钟
真实检测 → 原生80px过滤 → 跟踪 → 协议校验
定期采样/proc/self/status、/proc/self/fd（非Linux明确unsupported）
finally释放解码器 → 写完整/部分结果，异常返回非零
```

输入已有证据为12fps恒帧率，原片1719帧；此工具显式人工拼接循环，累计frame_index/fps可跨EOF保持递增，原片frame_index与loop同时记录，不伪造上一帧+1ms。先确认源FPS有限且>0，并在每次EOF核对实际解码数一致；零帧/变长循环明确失败。单次生产探针的EOF停止行为保持不变。

## 【异常与边界条件】

- 时长/采样率必须有限且>0；拒绝设备号、目录和不存在的文件。输出路径在解码前校验。
- 采用进程内单调墙钟节拍，调度落后如实报告；真实耗时和虚拟循环媒体时长分开，不把快进10分钟视频写成10分钟运行。
- RSS/FD/线程只存周期快照与有限计时窗口，不无限积累原始帧或逐帧元数据。非Linux资源监测标unsupported，不伪造0。
- Linux资源观察：60秒预热后RSS增长<=64MiB、FD增长<=2、线程增长<=4；完整600秒运行无异常、无协议错误。迟到分位数单独报告，不替代资源/业务验收。
- Python3.6兼容，无新依赖；板端运行环境使用`OPENBLAS_CORETYPE=ARMV8 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1`。
