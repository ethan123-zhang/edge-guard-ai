## 0. 本设计要交付什么

用户确认的载体是**服务端 + 安卓 APK 两者都做**；本次实现范围到**任务书阶段 2–3**，并把阶段 5 的补发与鉴权一并做掉：

- 做：鲁班猫（RK3588）上的主人端服务（WS 8766 + HTTP API + 照片 + 待发队列 + 推送适配器）、Web 看板、WebView 壳 APK、键盘接待入口（将来天问51 走同一入口）。
- 不做（任务书 §一、§二.6 明确排除）：实时视频、远程喊话、远程开门、完整历史的外网浏览、应用商店上架、收费；不在鲁班猫上跑 ASR/LLM/TTS（第 4 阶段的语音由天问51 承担）。

**方案 A（已批准）**：服务端先行 → 静态 Web 看板（手机/笔记本/投屏同一份）→ 最小 APK 壳。APK 与 Web 共用一套 UI 与 API，避免两套实现。

## 2. 总体结构

**单端口 8766**：同一个 TCP 监听上按 `Upgrade: websocket` 分流，HTTP 与 WS 共用端口，手机只记一个地址。

```
Jetson(192.168.43.11)                鲁班猫(192.168.43.10)                  主人端
  vision/service.py ──WS 8765──▶  (本设计不改 8765 入站)
       └──POST /vision/snapshot──▶ master/server.py :8766 ──HTTP+WS──▶ Web 看板 / APK
                                     ├─ api.py       路由与鉴权
                                     ├─ reception.py 接待会话（键盘/天问51 同入口）
                                     ├─ outbox.py    待发消息（稳定键、重试收敛）
                                     ├─ snapshots.py 照片落盘与绑定
                                     ├─ ws.py        主人端连接广播
                                     └─ push/        推送适配器（lan 已定；relay/vendor 占位）
```

代码位置：新增 `master/` 包（纯标准库，兼容板端 Python 3.6+）。不复用 `vision/ws_client.py`（那是视觉侧客户端），只复用 `vision/ws_protocol.py` 的帧与握手。

| 文件 | 职责 | 不做什么 |
|---|---|---|
| `master/server.py` | 监听 8766、分流、线程池、优雅退出、信号处理 | 不含业务判断 |
| `master/api.py` | HTTP 路由表、请求解析、JSON 响应、鉴权装饰 | 不写 SQL |
| `master/reception.py` | 接待会话：规则优先、槽位、汇总一次、收口 | 不碰门锁、不调 LLM |
| `master/outbox.py` | 入队/去重/退避重试/收敛/三种观测点记录 | 不生成文案 |
| `master/snapshots.py` | JPEG 原子落盘、按 `msg_id` 登记、选图规则 | 不猜"最新照片" |
| `master/ws.py` | 连接注册、广播、客户端 ack | 不校验业务字段 |
| `master/auth.py` | 设备 token（sha256 存库）、照片短时签名 | 不存明文 token |
| `master/push/*.py` | `send(message_key, payload) -> ack/fail` 适配器 | 不改消息内容 |
| `master/config.py` + `config/master.yaml` | 端口、密钥、保留期、超时（外置，铁律 ④） | token 不进 git |

## 3. 数据契约（只加不删，旧库可直接升级）

三张新表，全部 `CREATE TABLE IF NOT EXISTS`：

```sql
-- 待发消息：message_key 是幂等键，重试复用同一行、同一 payload
CREATE TABLE IF NOT EXISTS outbox (
    message_key     TEXT PRIMARY KEY,   -- 'report:<visit_id>' / 'alert:<visit_id>:<utterance_id>'
    visit_id        TEXT NOT NULL,
    kind            TEXT NOT NULL,      -- 'visit_report' / 'security_alert'
    payload         TEXT NOT NULL,      -- 协议 §4.1 / §4.2 的 JSON 原样冻结
    created_at      INTEGER NOT NULL,   -- 触发时刻（毫秒）
    status          TEXT NOT NULL DEFAULT 'pending',  -- pending / sent / failed
    attempts        INTEGER NOT NULL DEFAULT 0,
    last_attempt_at INTEGER,
    last_error      TEXT
);
CREATE INDEX IF NOT EXISTS idx_outbox_pending ON outbox(status) WHERE status != 'sent';

-- 照片资源：以来源事件 msg_id 为主键，绝不按文件名/时间猜归属
CREATE TABLE IF NOT EXISTS snapshot_asset (
    msg_id      TEXT PRIMARY KEY,
    face_id     TEXT NOT NULL,
    frame_ts    INTEGER NOT NULL,
    path        TEXT NOT NULL,          -- data/snapshots/<yyyymmdd>/<msg_id>.jpg（相对路径）
    bytes       INTEGER NOT NULL,
    status      TEXT NOT NULL,          -- received / missing / failed
    received_at INTEGER NOT NULL
);

-- 主人端设备绑定：未登记/已吊销 token 一律拒绝
CREATE TABLE IF NOT EXISTS client_device (
    device_id  TEXT PRIMARY KEY,
    name       TEXT,
    token_hash TEXT NOT NULL,           -- sha256(token)，不落明文
    created_at INTEGER NOT NULL,
    last_seen  INTEGER,
    revoked    INTEGER NOT NULL DEFAULT 0
);
```

**照片与到访的关联**不新增映射列，直接走已有 `visit_event` 账本：

```sql
SELECT sa.* FROM snapshot_asset sa
JOIN visit_event ve ON ve.msg_id = sa.msg_id
WHERE ve.visit_id = ? AND sa.status = 'received'
ORDER BY sa.frame_ts ASC, sa.msg_id ASC
LIMIT 1;   -- 取该到访"最早一条已收到"的照片
```

选图规则是**确定性**的：最早一条已收到，不是"最新一张"。这样 A 的照片迟到、B 的照片先到时，两次到访各有自己的图，不会串。

**消息键**：

| 消息 | 键 | 语义 |
|---|---|---|
| 普通汇总 | `report:<visit_id>` | 一次到访最多一行；只有明确来意才创建；重试/重连复用同键 |
| 越权告警 | `alert:<visit_id>:<utterance_id>` | `utterance_id` 由客户端在发送这条话语时生成，网络重试必须复用 |

**与旧字段的兼容**：

- `visit.report_status` 保留（旧代码/旧库都认），但**不再是补传真源**：有汇总且送达 → `sent`；"只留图"的到访置 `local_only`（新增枚举值，旧消费者按 `!= 'sent'` 扫描会想补发，所以**启动扫描只扫 `outbox`**，不再扫 `visit`）。这正是任务书 §阶段3"实现时重点检查"警告的陷阱。
- `dialog_turn` 只加一个可空列 `utterance_id TEXT`（配部分唯一索引），用于接待入口幂等；旧行该列为 NULL，不受影响。
- 协议消息**不改已有字段**；`face_event` 不加字段，照片走独立 HTTP 上传接口（任务书 §2.2 要求"把照片与产生它的事件一起标识"）。

## 4. 接待会话（键盘入口，规则优先于模型）

入口：`POST /api/utterance {visit_id, text, utterance_id, source}`。键盘现在用；天问51 将来把识别文本发同一入口（`source:"twen51"`），核心逻辑不返工。

顺序钉死（安全关键）：

1. **幂等**：按 `(visit_id, utterance_id)` 查重，重复投递只返回既有结果，不重复入队、不重复计数。
2. **越权规则先跑**：`privilege.detect(text)` 命中 → 立即 `outbox` 入队 `security_alert`（**不等收尾、不等图片**），写 `visit.privileged=1`，返回写死的拒绝话术（不由 LLM 生成）。
3. **再抽来意**：只有**明确说明**才算来意（"我来送快递/放门口"）；"你好""把门打开"不算。来访者**自称**的姓名单独存 `caller_name`，**不**据此认定熟人。
4. **汇总只生成一次**：收口动作时，若明确来意已成立 → 以 `report:<visit_id>` 入队一条 `visit_report`（含时间、身份、来意、留言、照片标识），payload 冻结；后续输入只更新 `visit` 行，**不重建消息**（保留原触发时间与消息身份，任务书 §2.5）。
5. **收口动作**：正常结束 / 沉默超时 / 接待超时三种，各有明确动作；`completed` 按是否正常结束写。`departed_at` **只在有离场证据时**写 —— 当前 `face_event` 没有离场信号，所以**不写**，材料里如实说明"接待结束时间 ≠ 实测离场时间"（任务书 §阶段3）。

四行行为映射（任务书 §一）：

| 访客输入 | 本地 | 汇总 | 告警 |
|---|---|---|---|
| 只打招呼/沉默/未说明来意 | 照片 + 到访行 | 不入队 | 不入队 |
| "送快递，放门口" | 照片 + 来意 + 留言 | `report:<visit_id>` 一次 | — |
| 只要求开门 | 照片 + `privileged=1` | 不入队 | `alert:<visit_id>:<utterance_id>` 即时 |
| 要求开门 + 说明送货 | 同一 `visit_id` 三者齐全 | `report:<visit_id>` 一次 | `alert:...` 一条（独立） |

复合句先触发告警再保留来意；同一话语的网络重试因 `utterance_id` 幂等不会多发。

## 5. 照片链路

```
Jetson: service 存完 JPEG ──POST /vision/snapshot?msg_id=&face_id=&frame_ts=──▶ 鲁班猫
        失败：只记日志 + 本机文件保留待重试（不阻塞事件上报）
鲁班猫: 校验共享密钥与参数 → 写 data/snapshots/<yyyymmdd>/<msg_id>.jpg（tmp→rename 原子）
        → snapshot_asset 登记（received / failed）
        → 若该 msg_id 的到访已存在，立即可见；否则等 face_event 到达后由 join 自然可见
```

- **乱序**：照片先到（事件后到）也按 `msg_id` 对上，不需要缓冲队列；事件先到、照片迟到时详情页先显示"缺图·采集中"。
- **缺图**：旧记录无照片可正常打开并显示缺图；新到访缺图记 `failed` 并在材料里报采集失败，**不得拿旧照片顶替**。
- **手机永远不拿 Jetson 本地路径**：手机只经鲁班猫的 `/api/visits/{id}/photo` 取图。

## 6. API 与鉴权

| 接口 | 方法 | 鉴权 | 说明 |
|---|---|---|---|
| `/api/health` | GET | token 可选（公网模式下必填） | 板端在线、视觉心跳、outbox 积压数；置 `security.health_requires_token: true` 后无 token 返回 401 |
| `/api/current` | GET | Bearer token | 当前接待 / 最近到访 / 家中状态 |
| `/api/visits?before_ts=&limit=` | GET | Bearer token | 历史分页（`before_ts` 翻页） |
| `/api/visits/{id}` | GET | Bearer token | 详情：时间、身份、自称、来意、留言、对话全文、越权原话、投递状态 |
| `/api/visits/{id}/photo` | GET | Bearer token **或** `?exp=&sig=` 签名 | 照片；未绑定/过期/错签 → 401/403 |
| `/api/utterance` | POST | Bearer token | 接待入口（键盘 / 将来天问51） |
| `/api/ack` | POST | Bearer token | 客户端回报"已展示"，用于第三种观测点（手机展示） |
| `/vision/snapshot` | POST | `X-Vision-Key` 共享密钥 | Jetson 图传（仅局域网） |

WS：`ws://<rk>:8766/ws?token=...`

- 下行：`state_sync` / `visit_report` / `security_alert` / `history_response`（字段照 [02-接口协议](02-接口协议.md) §4）
- 上行：`history_request` / `set_home_state`（照 §5）；按 §8 约定，未知 `type` 忽略不报错
- 客户端收到消息回 `{"type":"ack","message_key":...}`；服务端记 `lan_ack`

**鉴权细节**：token 由 `config/master.yaml` 的盐值与设备登记生成，库里只存 `sha256`；照片签名 URL = HMAC-SHA256(`visit_id|photo_msg_id|exp`, secret)，推送到外网的通知里带它，未绑定客户端拿到别的 ID 也解不开。三个观测点分别落 `event_log`：`push_accept`（推送平台受理）、`lan_ack`（接入方确认）、`client_shown`（手机展示），对应任务书 §阶段5"接入方确认、推送平台受理、手机展示是不同观测点"。

## 7. Web 看板（静态页面，无构建链）

`master/web/index.html` + `app.js` + `style.css`，由 8766 直接静态服务；手机浏览器、笔记本、投屏同一份。

- 顶部状态条：家中有人/无人、视觉在线、接待中、服务器时间
- 当前到访卡：照片、注册姓名或"陌生访客"、**访客自称单独一列**、第 N 次、来意、留言、告警红条（含原话与实际回应）
- 历史列表：时间倒序、分页、可点开详情（对话全文、消息投递状态）
- 断线时明确显示"离线，数据来自本地库"，不假装实时
- **不出现**任何开门/喊话/远程控制入口（任务书边界，答辩要主动讲）

## 8. APK（WebView 壳 + 原生通知入口）

`android/` 最小工程（Kotlin，minSdk 24 / targetSdk 34，Gradle wrapper）：

- 设置页：服务器地址 + 粘贴 token 绑定（`client_device` 登记）；局域网直连
- 主界面：WebView 指向同一服务（`/`），复用看板，不重写 UI
- 通知入口：`PushAdapter` 接口，通道定了再插（厂商 SDK / 自建 relay）；收到通知点击打开 `/api/visits/{id}` 详情
- 构建前置：**JDK17 + Android SDK**（本机目前都没有，且外网下载被策略代理 403 —— 见风险 R2）

## 9. 与视觉节点、旧库的兼容约束

- **不改 `vision/` 事件字段**：只新增"存图后 POST 到鲁班猫"这一调用；`save_snapshots`/`snapshot_dir` 配置键已存在（`vision/config.py`），核对板上真正启动的配置与后端（任务书 §二.2）。
- **字段只增不删**，未知 `type` 忽略；旧 SQLite 数据不用迁移，只跑 `init_schema` 加表。
- 时间一律 Unix 毫秒；展示层转本地时间。
- 不靠"最新照片/文件顺序/姓名/当前屏幕"匹配访客（任务书 §二.4）。
