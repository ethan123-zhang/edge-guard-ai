# P2 摄像头打通与公开素材复评（2026-11-07）

一句话：USB 摄像头在板上跑通了 —— 1280×720 从 **6.2 fps → 17.6~17.8 fps**（改 MJPG + v4l2），
用公开素材替代真实门口素材做了关联层与"注册再认"复评，三项关联判据全过；
顺带抓到一个新坑：**近黑帧会让 YuNet 吐出高置信假脸**（未修，列为下一步）。

## 一、摄像头：不显式要 MJPG 就掉到 YUYV，且 auto 会落到 GStreamer

板端实测（每条 40 帧，`logs/probes/camera_probe.py`）：

| 打开方式 | 协商结果 | 采集 fps | 生产管线 fps |
| :--- | :--- | ---: | ---: |
| `backend=auto` 1280×720，不设 fourcc（改前的 board.yaml） | YUYV | **9.95** | **6.16** |
| `v4l2` + `MJPG` 1280×720（钉 60） | MJPG | **49.6** | — |
| `v4l2` + `MJPG` 1280×720，改后生产两次 20 s | MJPG | — | **17.8 / 17.6**（推理 26.0 ms，丢帧 0） |
| `v4l2` + `MJPG` 640×480 | MJPG | 97.2 | 27.2 |

两个坑：

1. **FOURCC 不设** → 1280×720 被协商成 YUYV（USB2 带宽只有 9 fps），管线被采集卡死在 6 fps。
2. **`backend: auto` 这个 L4T OpenCV 4.1.1 会先试 GStreamer 后端**：GStreamer 管线不认
   `CAP_PROP_FOURCC` / `CAP_PROP_BUFFERSIZE`，设了 MJPG 之后**连续 50 帧读不到**
   （`vision_sim` 直接判"摄像头被拔"退出）。所以 `board.yaml` 必须显式写 `backend: v4l2`。

### 代码改动（本轮收尾时本机/板端各 352 项单测全过）

| 文件 | 改动 |
| :--- | :--- |
| `vision/config.py` | `camera.fourcc` / `camera.fps` 新键（默认 `""` / `0` = 不干预，旧行为不变）+ 校验（坏 FOURCC 点名报错） |
| `vision/camera.py` | 打开顺序改成 FOURCC → FPS → 分辨率 → BUFFERSIZE；预热帧全失败时**当场抛 `SourceError`**，带"把 backend 改成 v4l2"的提示（不再静默丢 50 帧） |
| `vision/config/board.yaml` | `backend: v4l2`、`fourcc: MJPG`、`fps: 30`（附实测数字注释） |
| `vision/config/base.yaml` | 两个新键的默认值 |
| `vision/tests/test_camera.py` | 新增：设置顺序、fmt 留空不改行为、读不到帧时的报错提示 |

板端验证（`logs/probes/verify_camera_guard.py`）：
`auto + MJPG` → 抛错并提示 v4l2；`v4l2 + MJPG` → 20/20 帧读通，协商 `MJPG 1280x720`。

> 备注：`cap.set(CAP_PROP_FPS, 30)` 实际没生效（相机仍报 60）。当前管线是**算力瓶颈**
> （17.8 fps @ 26 ms 推理），60 fps 采集不拖后腿，反而让 `BUFFERSIZE=1` 拿到更新鲜的帧。

## 二、公开素材复评 P2 第 2、3 项

真实门口素材采不到，改用公开免费素材 + 受控切片拼序列。素材在
`datasets/doorway-20261107/`（8 条 Coverr 免费片，1920×1080 H.264，带 `manifest.json` /
`LICENSE.md` / `_preview/`，整目录被 `.gitignore` 忽略）。

选片依据是**逐帧 YuNet 检出统计**（人脸框高、在场时长、同帧人数），不是人眼描述 ——
本机视觉引擎不可用（`read_image` / `modlens` 都报错），这一点必须在验收时说明。

| 用例 | 期望 | 实测（板上，生产代码路径，关联层开） |
| :--- | :--- | :--- |
| 同一人出画再回（cafe 1.0 s → 空镜 2 s → 5.5 s） | 只报 1 条 | **1 条**（关联抑制 1） |
| 两个不同人先后出现（cafe → traveler） | 2 条、绝不合并 | **2 条**（关联抑制 0） |
| 两人并排（teamwork 0.5–3.5 s） | 各 1 条 | **2 条**（关联抑制 0） |
| 注册 A（cafe 5.6~7.9 s 抽 5 帧）→ A 的另一个姿态/距离 | 命中 | `is_known=True` **conf=0.849** |
| 注册 A → B 的素材 | 不能认成 A | `is_known=False` **conf=0.114**（阈值 0.363） |

事件自身 `frame_ts → ts` 时延 **41–61 ms**（视频源；n=4）。同一帧两条事件的第二条记录到
1.17 s，尚未定位（已列为待查，不影响上面的条数判定）。

### 边界（不能拿这些结论替代真实门口验收）

- 序列是**切片+同机位空镜拼接**的合成素材，不是实验室门口；场景是办公室/走廊/咖啡馆/车站。
- 没有逆光样本；侧脸只抓到 <2 s（`d05`）。
- 原始素材里**没有"同一人进出再回来"的镜头**，S2 是靠同一段片切两段模拟的。

## 三、新发现：近黑帧 → YuNet 假脸（当天晚上已修，验收见第四节）

用黑场当"人离开"的间隔时，序列里稳定多出一条 `bbox=[50,-7,1144,746]`（比画面还高）的事件。
根因探针（`logs/probes/black_frame_probe.py`，生产检测器，板端）：

| 输入 | 检出 | score | 备注 |
| :--- | ---: | ---: | :--- |
| 全黑 (0) | 1 | **0.8862** | `overlap` 分支输出 **1.0688**（>1，被 decode clip 成 1） |
| 暗帧 (16) | 1 | 0.6732 | 刚过 0.6 门限 |
| 灰 64 / 128 / 200 / 白 255 | 0 | — | — |

- CPU dnn 与 TensorRT 输出**完全一致**（同 bbox、同 score）→ 不是 engine 的问题。
- Windows 上 cv2 4.13 的官方 `FaceDetectorYN` + 2023 模型对同一批纯色帧 **0 张脸**；
  但模型版本不同，**不能据此断言我们的解码错了**。
- 影响：**摄像头被遮 / 夜间无红外 / 流掉线出黑帧 → 会误报一条"陌生人"事件**。
- 三个候选修法：① 帧级保护（近均匀帧跳过检测并单独计数）② 检测框合理性（超画面/占比过大丢弃）
  ③ 换 2023 模型的低 opset 副本 + 重建 engine（要重做 parity 与板上回归）。
  建议先做 ①，因为它同时覆盖"相机被遮/掉线"这种真实故障；② 是它掉队时的兜底。

## 四、当晚两个 P0 修复（已验收）

按用户决定：近黑帧走**帧级均匀保护**，WS 阻塞一并修。

### 4.1 帧级均匀保护（`detection.blank_std`）

`vision/service.py` 在检测前先算"整帧缩到 160 宽后的灰度标准差"，低于阈值就跳过
检测+识别、只把空结果喂 tracker（让旧轨道按 TTL 自然老化），并计入 `stats.blank`。
阈值默认 **2.0**（`0` = 关闭，恢复老行为）。

板端验收（`logs/probes/reliability_board_probe.py`）：

| 用例 | 结果 |
| :--- | :--- |
| 全黑 10 帧 | 空白 10、**事件 0**（修复前是 1 条假陌生人） |
| 黑/真/黑 混排 30 帧 | 空白 10、事件 1（真帧已知人脸 conf **0.89**，框 254×220 正常） |
| 真实素材帧 std | 最低 **17.66**、中位 37.7~46.1 → 阈值 2.0 有 8.8 倍余量，不会误伤 |

### 4.2 WS 出口有界（`server.timeout / send_timeout / max_reconnect_sec`）

`vision/ws_client.py`：握手与 `sendall` 都有超时（原来握手前 `settimeout(None)`、
发送无超时），失败立刻断开、计数，重连退避 3s → 6s → 12s … 封顶 60s。

板端验收（同一段素材跑三次，各 12 s）：

| 出口 | fps | 失败 | 最大帧间隔 |
| :--- | ---: | ---: | ---: |
| 无出口（基线） | 14.26 | 0 | 86 ms |
| 端口拒绝 | 14.40（**1.01×**） | 1 | 80 ms |
| 半死对端（accept 后不应答） | 13.11（**0.92×**） | 1 | **1070 ms = 一次握手超时**，之后退避不再重复探测 |

修复前对端"半死"时主循环会永久卡在握手/发送上（P2.5 实测 16.5 → 8.2 fps）。

### 4.3 回归

- 板端与本机测试：**352 项全过**（板端 2 skipped）。
- 素材复评结果与修复前完全一致：同一人再回 1 条 / 不同人 2 条 / 两人并排 2 条 /
  已知再认命中 / 陌生人未错认。
- 证据：[reliability-fixes-2026-11-07.json](<docs/data/reliability-fixes-2026-11-07.json>)。

## 六、现场能力：无头注册 + 部署/engine 校验（2026-11-07 晚补齐）

### 6.1 `scripts/camera_watch.py`：SSH 终端里"看得见"

板上没有显示器、SSH 下没有 X，`cv2.imshow` 必崩。这个脚本每秒打一行：

```
[00:01] fps=18.4 帧=19 人脸=0（画面里没人） | 已知库=0 人
```

参数：`--profile board`、`--duration`、`--source <视频>`、`--no-recognize`、`--jsonl`。
板端实跑（真实摄像头，5 s）：**fps 18.4~19.8（avg 19.5）**，人脸 0（空房间），
`--no-recognize` 也通过；结束打印帧数/平均 fps/有人脸帧占比/最大脸像素。

### 6.2 `scripts/enroll_faces.py --auto`：纯终端注册

不倒计时看窗口，直接采：`--auto`（与 `--images`/`--camera` 互斥）、`--samples`、`--interval`、
`--countdown`、`--source <视频/图片/序号>`、`--gallery-dir`。每帧打印
「框 217px 分数 0.92 质量 0.077 → 采纳 / 丢弃（原因）」，采纳帧取平均后走原 gallery 保存。

质量门沿用板上标定：`association.quality_max_rms=0.16`（对齐残差÷眼距）+ 人脸高度
`detection.min_face_px`（80）。本机用素材视频验证 3/3 采纳、强制丢弃分支 exit 1；
板上空房间验证走到「未采纳」exit 1 且相机正常释放。

### 6.3 `scripts/deploy_board.ps1` + `scripts/ensure_engines.py`

- **部署**（Windows 一键）：tar+scp 同步 `vision/`+`scripts/` → 板端核 tar 哈希 → 解包 →
  `sha256sum -c` 清单 → `check_backend`（必须 exit 0）→ `run_tests`（必须 OK）。
  实测：**99 个文件 / 35.25 MB，sha256 99/99 一致，352 项测试 OK（2 skipped）**；
  清单不变自动跳过上传（幂等），`-Force` 强制重传，`-DryRun` 只看计划。
- **engine 校验/重建**（板端）：读 `runtime.detector_engine/recognizer_engine` 的 sidecar
  （schema `sentinel/trt-engine@1`，绑 engine 与模型 sha256 + TensorRT 版本）→ 不一致或缺文件
  就用 `trtexec` 重建（先建 `.build.tmp`，反序列化通过才原子替换）→ 重写 sidecar → 复验。
  实测：`--check` exit 0（0.3 s）；在 `/tmp` 副本上真重建一次 **150.6 s**，生产 engine 哈希
  前后不变（`f5908efa…b354e`）；`--check --fp32` 会明确指出精度不符并 exit 1。

> 为什么必须校验：engine 与 TensorRT 版本/设备绑定。换板或升级 JetPack 后 sidecar 校验不过，
> `backend: auto` 会**静默回退 CPU**（17.6 → 3.7 fps），现场只表现为"变慢了"。

## 复现命令（板端，工作目录 `~/sentinel-quality-20261106`）

```bash

python3 scripts/check_backend.py --profile board                      # 必须退出码 0
python3 scripts/ensure_engines.py --check                             # engine/sidecar 校验
python3 scripts/camera_watch.py --profile board --duration 5          # 终端自检（SSH）
python3 scripts/vision_sim.py --profile board --no-server --duration 20   # 应 ≥15 fps、丢帧 0
python3 -m vision.run_tests                                          # 352 项，2 skipped

python3 camera_probe.py              # 采集格式/帧率矩阵
python3 verify_camera_guard.py       # auto+MJPG 报错提示 / v4l2 正常
python3 material_quality_probe.py woman-enters-a-cafe-9961.mp4      # 素材人脸覆盖
python3 eval_material_board.py       # 关联层 + 注册再认复评（出 material-eval/material-eval.json）
python3 black_frame_probe.py         # 近黑帧假脸复现
python3 reliability_board_probe.py   # 帧级保护 + WS 有界 验收
```
