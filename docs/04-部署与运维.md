# 哨兵管家 — 部署与运维

> 本文档面向**单人开发 + 现场演示**场景，重点是"少装东西、少出故障、出事能快速恢复"。
> 版本：v1.0（主线版）

---

## 1. 环境准备：核心原则

单人项目最大的时间杀手**不是写逻辑，是跟环境搏斗**。因此本项目的环境原则是：

| 原则 | 做法 |
|---|---|
| **能用官方自带的，绝不自己编译** | Jetson 用 JetPack 自带 Python；RK3588 用系统 Python |
| **能不装的依赖，绝不装** | 人脸识别用 OpenCV 自带模型，**不装 insightface 全家桶** |
| **长尾任务提前启动** | 模型下载/转换是"提交后等结果"型，**第一周就挂上** |
| **所有配置外置** | 阈值、地址、开关全在 `config.yaml`，现场可改，不改代码 |

## 2. Jetson Nano B01（视觉节点）

### 2.1 硬件准备

| 项 | 要求 | 说明 |
|---|---|---|
| 供电 | **5V 4A DC 圆口**（推荐）或高质量 5V2.5A MicroUSB | 供电不足会随机重启，是 Nano 最常见的"玄学故障" |
| 散热 | **散热片 + 风扇（必须）** | 满载降频可达 30%+，实验室测的速度现场会掉 |
| 摄像头 | 亚博智能 1080p USB 摄像头 | 已具备 |
| 存储 | ≥32GB microSD（Class10/A1） | |
| 网络 | 无线网卡或网线 | **建议网线**（更稳），但现场可能只能 WiFi |

> **供电是头号坑**：Jetson Nano 在推理时瞬时电流大，用劣质电源或细 USB 线会导致掉电重启，现象是"跑一会儿就死机"。**如果遇到随机的重启，先换电源和线。**

### 2.2 系统与依赖

使用 **JetPack 4.6**（Nano 官方支持的最高版本）。**不要尝试升级 Python 版本**。

```bash
# 系统更新
sudo apt update && sudo apt upgrade -y

# 核心依赖（尽量少）
sudo apt install -y python3-pip python3-opencv v4l-utils sqlite3

# Python 依赖（仅这几个）
pip3 install --upgrade pip
pip3 install opencv-python numpy websockets pyyaml

# 验证
python3 -c "import cv2; print(cv2.__version__)"
```

**关于 OpenCV**：JetPack 自带 OpenCV。先检查自带版本是否包含 `FaceDetectorYN` / `FaceRecognizerSF`（需要 OpenCV ≥ 4.5.4）：

```bash
python3 -c "import cv2; print(cv2.__version__); print(hasattr(cv2,'FaceDetectorYN'), hasattr(cv2,'FaceRecognizerSF'))"
```

- 若输出 `True True` → 直接用自带的
- 若输出 `False` → 装 pip 版：`pip3 install opencv-python==4.8.1.78`（注意：pip 版可能覆盖系统的，谨慎）

### 2.3 模型文件

YuNet 与 SFace 是 OpenCV 官方模型（**很小，几百 KB**）：



### 2.4 摄像头验证与参数调优

```bash
# 查看摄像头
v4l2-ctl --list-devices

# 查看支持的分辨率
v4l2-ctl -d /dev/video0 --list-formats-ext
```

**关键设置：锁定曝光和白平衡**。教室灯光变化会导致画面忽明忽暗、识别率崩。锁定后画面稳定，阈值才可控。

```bash
# 关闭自动曝光，手动设定（数值现场调）
v4l2-ctl -d /dev/video0 -c auto_exposure=1
v4l2-ctl -d /dev/video0 -c exposure_time_absolute=150

# 关闭自动白平衡
v4l2-ctl -d /dev/video0 -c white_balance_automatic=0
```

若驱动不支持这些控制项，则在代码里用 `cv2.VideoCapture` 的 `CAP_PROP_AUTO_EXPOSURE` 设置。

### 2.5 网络配置：静态 IP（必做）

**不要用 DHCP**。IP 变了，两侧代码就连不上，现场会浪费大量时间排查。

```bash
# NetworkManager 设静态 IP（示例：192.168.43.11）
sudo nmcli con mod "连接名" ipv4.addresses 192.168.43.11/24
sudo nmcli con mod "连接名" ipv4.gateway 192.168.43.1
sudo nmcli con mod "连接名" ipv4.dns 192.168.43.1
sudo nmcli con mod "连接名" ipv4.method manual
sudo nmcli con up "连接名"
```

**约定地址**（在 `config.yaml` 中对应）：

| 设备 | 静态 IP |
|---|---|
| 手机热点网关 | 192.168.43.1 |
| 鲁班猫5（对话节点） | **192.168.43.10** |
| Jetson Nano（视觉节点） | 192.168.43.11 |
| 主人端（手机/笔记本） | 192.168.43.x（DHCP 即可） |

### 2.6 开机自启（必做）

现场如果设备重启，**必须自动恢复服务**，不能靠人工 SSH 上去敲命令。

`/etc/systemd/system/sentinel-vision.service`：

```ini
[Unit]
Description=Sentinel Vision Service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=nvidia
WorkingDirectory=/home/nvidia/sentinel/vision
ExecStart=/usr/bin/python3 /home/nvidia/sentinel/vision/face_service.py
Restart=always
RestartSec=5
StandardOutput=append:/var/log/sentinel-vision.log
StandardError=append:/var/log/sentinel-vision.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable sentinel-vision
sudo systemctl start sentinel-vision
sudo systemctl status sentinel-vision
```

> `Restart=always` + `RestartSec=5` 是**断线自愈**的关键：程序崩溃或被网络断开导致退出，5 秒后自动重来。

### 3.3 RKLLM 部署（**最长的长尾任务，第一周就启动**）

**流程概览**（参考[野火 RKLLM 教程](https://doc.embedfire.com/linux/rk356x/Ai/zh/latest/lubancat_ai/env/rkllm.html)）：

```
① PC(x86 Linux) 上装 RKLLM-Toolkit
② 下载原始模型（HuggingFace/ModelScope）
③ 转换为 .rkllm（量化 W8A8）
④ 拷贝到鲁班猫5
⑤ 板端编译 rkllm runtime 例程
⑥ 跑通对话
```

#### 步骤 ①：准备 x86 Linux 环境

**RKLLM-Toolkit 只有 Linux 的 wheel，Windows 装不了。** 用 **WSL2**（推荐，最省事）：

**① -0 先配代理（否则 WSL 里下载极慢或直连失败）**

> ⚠️ **WSL2 是独立虚拟机，里面的 `127.0.0.1` 指 WSL 自己，不是 Windows。**
> Windows 上开着代理，WSL 里**默认不走**。必须用宿主机在 WSL 网络中的**网关地址**。

```bash
# 查宿主机在 WSL 网络里的地址（重启后会变，每次新会话先查）
ip route | grep default        # 例：default via 172.28.240.1 dev eth0

# 设成变量后配置（把 IP 换成上一步查到的）
PROXY="http://172.28.240.1:10090"

# git
git config --global http.proxy  "$PROXY"
git config --global https.proxy "$PROXY"

# pip
mkdir -p ~/.pip
printf '[global]\nproxy = %s\nindex-url = https://pypi.tuna.tsinghua.edu.cn/simple\ntrusted-host = pypi.tuna.tsinghua.edu.cn\n' "$PROXY" > ~/.pip/pip.conf

# 验证
curl -s -o /dev/null -w "HTTP=%{http_code}\n" -x "$PROXY" https://github.com
```

> 本仓库已提供一键脚本：`scripts/wsl_setup_proxy.sh`（把 `PROXY_HOST` 改成实际网关即可）。

**① -1 装 Toolkit**

```bash
# 在 WSL2 (Ubuntu 22.04) 中 —— 本机实测 Python 为 3.10.12，故用 cp310 wheel
mkdir -p ~/rkllm-work && cd ~/rkllm-work
git clone https://github.com/airockchip/rknn-llm.git --branch release-v1.3.1 --depth 1
cd rknn-llm/rkllm-toolkit/packages

# Wheel 文件名随版本变化，别照抄旧文档。先看一眼有哪些：
ls *.whl
# v1.3.1 提供 cp310 / cp311 / cp312 三个，按本机 python3 --version 选：
pip3 install rkllm_toolkit-1.3.1-cp310-cp310-linux_x86_64.whl

# 验证
python3 -c "from rkllm.api import RKLLM; print('ok')"
```

> 本机实测这套流程可用，脚本见 `scripts/wsl_setup_rkllm.sh`（会自动匹配 cp 版本）。
> 前置条件：**WSL 相关命令必须用 `danger-full-access` 跑**，否则被降权到 Low IL 会报
> `E_ACCESSDENIED`（详见 `memory/04` 的 E-7）。

> ⚠️ **两个版本坑（2026-10-15 实测）**：
> ① 最新版是 **`release-v1.3.1`**（2026-09-29），文档旧版写的 `v1.3.0` 已过时；
> ② wheel 名里的**版本号与 cp 号都会变**，旧文档写的 `rkllm_toolkit-1.3.0-cp310-...whl`
> **在 v1.3.1 下根本不存在**。**永远先 `ls *.whl` 再装**，不要照抄文件名。
>
> ⚠️ **Toolkit 版本必须与板端 Runtime 版本对齐** —— 这是转换失败的头号原因（见 `06` 降级 L1）。
> 转换前先查板端：`sudo cat /sys/kernel/debug/rknpu/version` 与 `find / -name librkllmrt.so`。

#### 步骤 ②③：下载并转换模型

**模型选择**：

| 模型 | 建议 | 理由 |
|---|---|---|
| **Qwen3-0.6B** | ✅ **首选** | 野火教程实测：prefill 305 tok/s、生成 23.96 tok/s、内存 784MB，延迟最低 |

```bash
#   pip3 install modelscope
#   modelscope download --model Qwen/Qwen3-0.6B --local_dir ~/sentinel-models/Qwen3-0.6B

# 转换（修改 export_rkllm.py 中的 modelpath）
cd rknn-llm/examples/rkllm_api_demo/export/

# 产出：Qwen3-0.6B_W8A8_RK3588.rkllm
```

**转换参数要点**（**以 v1.3.1 官方 `export_rkllm.py` 为准，2026-10-15 核对**）：

```python
target_platform      = "RK3588"
optimization_level   = 1            # ⚠️ v1.3.1 新增，旧文档漏了
quantized_dtype      = "W8A8"       # W8A8 用 normal 算法；W4A16 用 grq
quantized_algorithm  = "normal"
num_npu_core         = 3            # RK3588 有 3 个 NPU 核
max_context          = 4096         # ⚠️ 官方示例是 4096，旧文档写 2048
device               = "cuda"       # ⚠️ 见下方说明；无 N 卡则改 "cpu"
dataset              = "./data_quant.json"
```

> ⚠️ **旧版 `docs` 与 v1.3.1 的三处差异**（照抄旧文档会报参数错误）：
> ① `optimization_level` 是 v1.3.1 **新增的必填项**；
> ② `max_context` 官方示例为 **4096**（本项目对话短，2048 也够，但别以为官方是 2048）；
> ③ `load_huggingface()` 签名变了，现在是
> `load_huggingface(model, model_lora=None, device='cuda', dtype="float32", custom_config=None, load_weight=True)`。
>
> **`device` 怎么选**：先跑 `python3 -c "import torch; print(torch.cuda.is_available())"`。
> `True` 用 `"cuda"`（**快得多**），`False` 用 `"cpu"`。
> 注意：官方脚本开头有 `os.environ['CUDA_VISIBLE_DEVICES']='0'`，**无 N 卡时要删掉这行**。

### 3.4 麦克风（**唯一必须新购的硬件**）

**问题**：原有麦克风噪声太大。教室是混响环境（大空间、硬墙面），单麦基本不可用。

**远场拾音（1~3 米）的三个必要条件**：

| 需求 | 为什么 | 怎么判断 |
|---|---|---|
| **麦克风阵列 + 波束成形** | 单麦在混响中不可用 | 至少 2 麦，4 麦更好 |
| **硬件 AEC（回声消除）** | 播报时喇叭声音会被录进去 | 产品页写"回声消除" |
| **降噪 / VAD** | 判断客人说完了没有 | 通常与 AEC 一起提供 |

**选型建议（按优先级）**：

1. **ReSpeaker USB Mic Array（4 麦阵列）** — **首选**。Linux 免驱，当 USB 声卡用，资料多，自带 AEC/降噪/波束成形。
2. **带降噪的 USB 会议全向麦** — 便宜保底方案，AEC 靠软件补。
3. **ReSpeaker 2-Mic Pi HAT** — 便宜，但是 **I2S 接口，鲁班猫 40pin 未必兼容**，需先查引脚定义。**有风险，不推荐赶时间时选。**

**买前验证清单**：
- [ ] USB 免驱（Linux `arecord -l` 能识别）
- [ ] 明确标注支持 **AEC / 回声消除**
- [ ] 拾音距离 ≥ 3 米
- [ ] 有 Linux 下的使用案例

**到货后验证**：

```bash
arecord -l                          # 应能看到设备
arecord -d 5 -f cd test.wav         # 录 5 秒
aplay test.wav                      # 回放确认
```

### 3.5 麦克风门控（**最重要的保命机制**）

**问题**：TTS 播报时，喇叭的声音会被麦克风录进去 → ASR 转出系统自己的话 → LLM 又回应 → **自问自答死循环**。教室混响会让这个问题更严重。

**解决方案（按可靠性排序）**：

| 方案 | 做法 | 可靠性 |
|---|---|---|
| **软件门控（推荐）** | 播报期间不读麦克风数据；播报结束后延时 300ms 再开 | 高，成本为零 |
| 静音麦克风 | `amixer set Capture nocap` / 恢复 `cap` | 高，但依赖声卡支持 |
| 硬件 AEC | 依赖麦克风阵列能力 | 中，看硬件 |

**必须实现软件门控**：

```python
def speaking(text):
    mute_mic()                       # ① 关麦
    tts_play(text)                   # ② 播报
    time.sleep(POST_TTS_DELAY)       # ③ 等混响消散（300ms）
    flush_audio_buffer()             # ④ 丢弃缓冲里的残留音频（关键！）
    unmute_mic()                     # ⑤ 开麦
```

> **第 ④ 步是最容易漏的**：即使关了麦，**音频缓冲里可能还留着播报期间采集的数据**，不丢弃的话开麦后立刻被当成"用户说话"。**必须清空缓冲区。**

**验证方法**：让系统连着播报两次，看它会不会自己接自己的话。**没有自问自答才算通过。**

### 3.6 ASR / TTS 部署

**ASR（本地离线，CPU 运行）**：

```bash
pip3 install sherpa-onnx
# 下载中文模型（SenseVoice 或 Paraformer）
```

**为什么 ASR 用 CPU 不用 NPU**：RK3588 的 NPU 资源**被 LLM 占用**。若 ASR 也抢 NPU，会互相阻塞，导致两边都变慢。ASR 放 CPU 上跑，与 LLM 并行，整体延迟更低。

**TTS（本地离线）**：

```bash
# 方案一：piper（轻量、快）
# 方案二：edge-tts（需要外网，不推荐现场用）
# 方案三：预生成音频文件 + aplay（最稳，见下）
```

> **强烈建议的优化**：**把固定话术预先生成为音频文件**（问候语、拒绝话术、收尾语），直接 `aplay` 播放。
> 好处：① 省掉 TTS 合成时间，体感明显变快；② 不受网络/模型影响，演示极稳；③ 只有 LLM 的自由回复才需要实时合成。
> **这是性价比最高的优化手段。**

## 4. 网络方案（现场是手机热点）

### 4.1 关键认知：热点后面是 NAT

```
门口设备(192.168.43.x) → 手机热点 → 运营商 NAT → 互联网
                                              ✗ 外部连不进来
```

**因此**：
- ❌ 不要让主人端在"外网"连设备（连不上）
- ❌ 不要依赖云端 MQTT（教室热点未必有外网）
- ✅ **主人端连同一个热点，局域网直连** —— 这是本版本的方案

### 4.2 演示时的网络拓扑

```
              ┌─────────────────┐
              │   手机热点       │
              │ 192.168.43.1    │
              └────┬─────┬──────┘
                   │     │
        ┌──────────┘     └──────────┐
        ▼                            ▼
┌───────────────┐            ┌──────────────┐
│ 鲁班猫5        │            │ Jetson Nano  │
│ 192.168.43.10 │◀──WS 8765──│ 192.168.43.11│
│ (对话+主人端   │            │ (视觉)        │
│  8766)        │            └──────────────┘
└───────┬───────┘
        │ WS 8766
        ▼
┌───────────────┐
```

### 4.3 演示当天必须提前做的网络检查

```bash
# ① 两台设备能互 ping
ping 192.168.43.10    # 在 Jetson 上
ping 192.168.43.11    # 在鲁班猫上

# ② 端口通

# ③ 主人端能打开
# 手机浏览器访问 http://192.168.43.10:8766
```

> **提前 30 分钟到场做这个检查**，不要等评委坐下了才发现连不上。

### 4.4 断网降级

本版本无外网依赖（ASR/LLM/TTS 全本地），因此：

| 情况 | 影响 | 处理 |
|---|---|---|
| 手机热点断开 | 主人端收不到推送 | 数据写库（`pending`），热点恢复后自动补传 |
| 两台板子之间断连 | 视觉事件发不出去 | Jetson 侧本地缓存事件，重连后补发 |
| 完全没有网络 | 只能本机演示 | **准备"纯本机模式"**：在鲁班猫上直接跑对话，用本地回环 |

**断网补传的验证方法**（这是答辩亮点，必须能演示）：

1. 关掉主人端
2. 完整走一遍迎宾流程
3. 检查数据库：`sqlite3 data/sentinel.db "SELECT visit_id, report_status FROM visit;"`
   → 应为 `pending`
4. 打开主人端
5. 检查：记录自动变成 `sent`，且主人端收到了这条推送

## 5. 现场配置清单（可调参数）

**所有阈值必须在配置文件里，不要写死在代码里。**现场环境一变，改配置比改代码快一百倍。

| 参数 | 文件 | 现场调整场景 |
|---|---|---|
| `detection.score_threshold` | vision | 漏检多 → 调低；误检多 → 调高 |
| `recognition.match_threshold` | vision | 熟人认不出 → 调低；认错人 → 调高 |
| `roi.*` | vision | 观众误触发 → 缩小 ROI |
| `min_face_px` | vision | 远处人误触发 → 调大 |
| `camera.exposure_value` | vision | 画面太亮/太暗 |
| `dialog.max_rounds` | dialog | 演示时间紧 → 调到 2 |
| `asr.vad_silence_ms` | dialog | 判停太慢 → 调到 500 |
| `mic.post_tts_delay_ms` | dialog | 自问自答 → 加大到 500 |

**建议做一个"演示档"配置**：把参数调成"演示友好"（识别宽松、对话短、延迟低），现场一键切换。

## 6. 故障排查手册（**打印一份带到现场**）

### 6.1 视觉节点

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 摄像头打不开 | 设备号变了 / 被占用 | `ls /dev/video*`；`fuser /dev/video0` |
| 检测不到人脸 | 阈值太高 / 光照差 / ROI 错 | 打印检测分数；临时 `roi.enabled=false` |
| 熟人认不出 | 阈值太高 / 光照变了 | 临时降 `match_threshold` 到 0.3 |
| 帧率极低 | 散热降频 / 分辨率太高 | 检查温度；降到 640×480 |
| 随机重启 | **供电不足** | 换 5V4A 电源和短线 |
| 连不上对话节点 | IP 变了 / 服务没起 | `ping`；`systemctl status sentinel-dialog` |

### 6.2 对话节点

| 现象 | 可能原因 | 排查 |
|---|---|---|
| LLM 加载失败 | 模型文件损坏/路径错 | 检查路径与文件大小 |
| NPU 报错 | 驱动版本不匹配 | `sudo cat /sys/kernel/debug/rknpu/version` |
| **系统自问自答** | **闭麦失效** | 检查 `mute_during_tts`；加大 `post_tts_delay_ms`；确认清空了缓冲区 |
| **听不到说话** | 麦克风选错设备 | `arecord -l`；在配置里指定设备号 |
| 对方听不到播报 | 音量/输出设备错 | `aplay -l`；`alsamixer` 调音量 |
| 说话后没反应 | VAD 没判停 | 看日志是否有 `LISTENING → THINKING` |
| 回复很慢 | 上下文太长 | 缩短提示词；`max_new_tokens` 降 64 |
| 回复乱码/带符号 | LLM 输出格式问题 | 检查后处理是否生效 |

### 6.3 网络

| 现象 | 排查 |
|---|---|
| 主人端打不开 | 确认手机连的是同一个热点；`ping 192.168.43.10` |
| 推送收不到 | 看日志推送是否报错；查 `report_status` |
| 热点频繁断 | **换有线**；或换一个热点；把设备放近 |
