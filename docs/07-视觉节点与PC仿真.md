# 07 · 视觉节点与 PC 仿真

> 状态：**PC 仿真已跑通（2026-10-23）**；板端待 TF 卡到货后按第 6 节上板。
> 代码：`vision/`（9 个模块）+ `scripts/vision_sim.py` + `scripts/vision_endpoint_sim.py`。
> 这份文档回答一个问题：**在没有 Jetson、没有摄像头、甚至没有模型文件的情况下，
> 怎么把"视觉节点"这份代码开发到"上板即可跑"。**

---

## 1. 仿真的边界（先说清楚它不能证明什么）

| 能证明 | 不能证明 |
|---|---|
| 事件 JSON 符合 `docs/02` §3.1，字段/时间戳/边界都对 | 板端 aarch64 上的实际耗时（x86 只作参考，不能外推） |
| 检测→识别→稳定→上报→入库 的**接线**没问题 | YuNet 在 1280×720 下的真实召回率/误检率 |
| 连续帧确认、10 秒冷却、一次停留只发一条 | CUDA / 内存带宽相关的性能表现 |
| WebSocket 握手与帧格式（纯标准库实现）能与服务端互通 | 板端驱动（V4L2、CSI 摄像头）的问题 |
| 配置外置、降级路径（没模型也能跑） | 真实门口气流/逆光/多人的鲁棒性 |

**一句话**：仿真证明的是"我们的代码没有接错线"，
不是"这块板子能跑到 15 fps"。板端数字必须上板测（`scripts/vision_selftest.py`）。

---

## 2. 模块与职责

| 文件 | 职责 | 关键约束 |
|---|---|---|
| `vision/config.py` | `base.yaml` + profile 覆盖、校验、路径解析 | 阈值全部外置（铁律 ④）；报错要点名是哪个键 |
| `vision/camera.py` | 摄像头 / 视频文件 / 图片目录三种源 | `read()` 返回**帧时刻**，`face_event.frame_ts` 用它 |
| `vision/detector.py` | YuNet（准）与 Haar（离线兜底） | `auto` = 有模型用 YuNet，没有就降级并**明确打印** |
| `vision/recognizer.py` | SFace 特征 + L2 归一化；`none` 降级 | SFace 的 `alignCrop` 必须吃 YuNet 的 5 点关键点 |
| `vision/gallery.py` | `face_db/<face_id>.npy` + `registry.json` | 特征以 .npy 为准；目录在 .gitignore（隐私） |
| `vision/tracker.py` | 连续 N 帧确认、冷却、一次停留一次上报 | 不依赖 cv2，能纯逻辑单测 |
| `vision/events.py` | 构造 `face_event` / `vision_heartbeat`，合规检查 | 毫秒时间戳；陌生人 `name` 显式 `null` |
| `vision/ws_protocol.py` | RFC6455 最小实现（握手 + 帧） | 纯标准库：板端不用 pip 也能跑 |
| `vision/ws_client.py` | 客户端，断线不阻塞主循环 | 重连节流 `reconnect_sec` |
| `vision/service.py` | 主循环 + 心跳 + ROI + 截图 + 统计 | `Sink` 抽象：WS / JSONL / 两者（tee） |
| `vision/imageio.py` | Unicode 安全读写 | Windows 中文路径下 `cv2.imread/imwrite` 会失败 |

**为什么强调 Python 3.6**：板端 Ubuntu 18.04 只有 Python 3.6，
`dataclasses`、`from __future__ import annotations`、海象运算符全部不可用。
`vision/tests/test_py36_compat.py` 用 `ast.parse(feature_version=(3, 6))` 把这条钉死。

## 3. 双后端矩阵（今天就能跑 vs 有模型才完整）

| 检测 | 识别 | 能做什么 | 什么时候用 |
|---|---|---|---|
| YuNet | SFace | **完整**：认出熟人、带名字、带相似度 | 模型到位后（默认） |
| YuNet | none | 检测准、关键点有，但全按陌生人上报 | 只补了检测模型 |
| Haar | none | **能跑通链路**，但会误检（见 §5） | **当前状态**（模型未下载） |
| Haar + 想开 SFace | —— | 不允许：没有关键点，对齐必失败 | —— |

`detection.backend` / `recognition.backend` 都支持 `auto`，
所以**换机器只需要放模型文件，不用改配置**。

## 4. 运行手册（PC）

```powershell
# 0) 依赖：PyYAML（本机已装）；OpenCV ≥ 4.5.4
python -m pip install pyyaml

# 1) 冒烟：环境 + 模型 + 人脸库 + 单帧耗时
python scripts\vision_selftest.py

# 2) 终端 A：假对话节点（收 face_event → 写 data\sentinel.db）
python -u scripts\vision_endpoint_sim.py

# 3) 终端 B：视觉节点（sim 档，开预览窗口；q 退出，s 截屏）
python scripts\vision_sim.py

# 4) 没有摄像头时：用图片目录/视频回放
python scripts\vision_sim.py --source snapshots\probe\face1 --min-face-px 30 --no-window

# 5) 演示兜底：完全不看摄像头，回放预置事件流
python scripts\vision_sim.py --demo

# 6) 注册熟人（需要 YuNet + SFace 两个模型）
python scripts\enroll_faces.py --id p_10023 --name 王阿姨 --camera 0
python scripts\enroll_faces.py --id p_10023 --name 王阿姨 --images photos\wang

# 7) 测试（不需要摄像头/模型）
python -m vision.run_tests
```

**`--jsonl logs\events.jsonl` 是 tee，不是替换**：事件会同时走 WS 和落文件。
（2026-10-23 一开始写成了"有 jsonl 就不发 WS"，结果 DB 里一条没有 —— 已修并加了单测。）

## 5. 实测记录（2026-10-23，本机）

| 项 | 值 | 说明 |
|---|---|---|
| 环境 | Python 3.10.1 / OpenCV **4.13.0.92** / AMD64 | `FaceDetectorYN` 与 `FaceRecognizerSF` 都在 |
| 模型 | **均缺失** | 当前网络策略对 github/pypi/hf **全 403**，只能由用户浏览器下载 |
| 检测后端 | Haar（自动降级） | 1280×720 单帧 **p50 10.6 ms**（5 帧样本，p95 被首帧拖到 840ms） |
| 端到端 | 图片源 → 3 条 `face_event` → WS → SQLite | `person` 3 行、`event_log` 3 行，字段齐全 |
| 单测 | **63 个全绿** | 配置/事件/跟踪/人脸库/协议/主循环/3.6 兼容 |
| 假阳性实例 | Haar 把卫生间墙砖认成脸 | `snapshots/` 里已留证据图 → **必须换 YuNet** |

> ⚠️ **耗时数字只在本机成立**：Haar 在 x86 上 10 ms 不代表 Jetson 上也是 10 ms；
> 何况 Haar 本来就只是兜底。**V1 的正式答案必须上板跑 `vision_selftest.py`。**

## 6. 上板清单（TF 卡到货后照做）

1. **拷代码**（不需要 `git clone`，板子也不必能出网）：
   `vision/`、`scripts/vision_sim.py`、`scripts/vision_selftest.py`、`scripts/enroll_faces.py`
2. **装依赖**：`sudo apt-get install -y python3-yaml`（OpenCV 用自编的 4.5.4，见 `04` §2.2）
3. **放模型**：`vision/models/` 下两个 onnx（检测 230KB + 识别 37MB）
4. **回答 V1**：`python3 scripts/vision_selftest.py` —— 它会打印
   `OpenCV 版本 / FaceDetectorYN 是否可用 / 单帧 p50·p95 / 有没有检测到人脸`
5. **注册熟人**：`python3 scripts/enroll_faces.py --id p_10023 --name 王阿姨 --camera 0`
6. **改地址**：`vision/config/board.yaml` 的 `server.ws_url` 指向鲁班猫5 **实际 IP**
   （历史实测 `192.168.3.214`，但**以现场 `ip addr` 为准**，见 `memory/07-network.md`）
7. **跑**：`python3 scripts/vision_sim.py --profile board --no-window`
   —— 看日志里 `上报 …` 与心跳；PC 侧假节点换成真对话节点后不用改视觉端任何代码

> 板端没有可靠 HDMI（`memory/02` E-29），所以 `board.yaml` 默认 `headless: true`；
> 需要看画面时用 `--no-window` 的反面（去掉该参数）之前先确认显示器可用。

## 7. 已知问题与取舍

| 问题 | 现状 | 后续 |
|---|---|---|
| Haar 误检多、只认正脸 | 仅作兜底，日志明确提示 | 模型到位即切 YuNet |
| 没有模型时 `confidence = 0.0` | 协议要求 float，陌生人也带"最像的人"的相似度；无 SFace 时只能是 0 | 模型到位后自然有值 |
| Windows 中文路径 `cv2.imread/imwrite` 失败 | 已用 `vision/imageio.py` 包一层 | 板端 Linux 无此问题，但保留这层无副作用 |
| 图片目录源默认 2 fps | `ImageDirSource(fps=2)`，测试够用 | 视频回放用 `VideoFileSource` |
| 单帧耗时只有检测+识别，不含截图写盘 | 截图是 I/O，不进推理统计 | 板端测端到端时另记 |
| `vision/face_db/` 与 `snapshots/` 在 .gitignore 里 | 人脸特征/访客截图属敏感数据 | 绝不入库 |
