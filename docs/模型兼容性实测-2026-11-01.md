# 模型兼容性实测

结论：本机真实检测/对齐/特征推理成功；Jetson现有DNN可以运行SFace前向，但YuNet 2023模型导入失败。完整板端识别与跨轨关联仍未通过。

## 【输入输出定义】

输入为OpenCV官方opencv_zoo的face_detection_yunet_2023mar.onnx与face_recognition_sface_2021dec.onnx，以及已有双人公开视频。官方来源：https://github.com/opencv/opencv_zoo/tree/main/models 。模型仅保留在忽略目录和板端独立模型验证目录，无生产部署变更。

输出见[data/jetson-2026-11-01-model-compatibility.json](data/jetson-2026-11-01-model-compatibility.json)，含字节数、SHA256、加载结果与有限推理元数据，不保存图像或特征向量。两个模型本机与板端哈希一致。

## 【核心算法逻辑伪代码】

```text
官方模型下载 → 哈希 → 本机真实YuNet检测/对齐/SFace特征
隔离传输 → 板端readNetFromONNX逐模型加载
SFace加载成功 → 既有公开视频首帧缩放张量 → 前向执行及有限性检查
分别判断模型加载、张量执行、人员区分与完整链路
```

## 【异常与边界条件】

板端YuNet在ONNX导入器getMatFromTensor断言失败，尚未进入检测。SFace的板端输入是未经人脸对齐的整帧缩放，仅证明计算图可执行，不证明有效身份特征或识别准确率。其约3.57秒耗时包含加载/视频读取/首次前向，不是生产帧率。

本轮没有升级系统、安装依赖、读取身份库、调用摄像头或修改生产算法。自然姿态12条事件的失败未被本轮覆盖。认证只用于获授权的本轮连接，可读取历史认证的临时脚本已移除。

## 【验收测试用例】

- 本机OpenCV5.0.0：公开视频首帧检出2脸，各得到有效128维向量；通过限定推理检查。
- 板端OpenCV4.1.1：YuNet 2023导入失败；SFace加载通过，前向输出1×128且全部有限。
- 两端模型字节数与哈希完全一致；模型与原始运行日志均保持忽略。
- 完整板端检测/关键点/对齐/识别、跨轨关联与业务去重均未通过本轮验收。

下一步先验证兼容的检测与五点关键点路径，可调查旧版模型或隔离运行时；不能只把SFace张量执行成功当作识别链路成功，也不能直接启用陌生人跨轨合并。
