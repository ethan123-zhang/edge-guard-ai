# 跨轨关联与两层去重合同（2026-11-01）

状态：**用户已确认采用保守关联，先验证能力**。本轮已重新运行191项本机测试、复现自然姿态12条本地事件，并完成板端只读能力核查；没有修改生产算法、阈值或板端部署。整体可靠性仍未通过。能力结果与下一入口见[能力验证报告](短期关联能力验证-2026-11-01.md)。业务窗口细则仍为后续业务实现的建议语义，本次确认不表示业务状态机已实现。

## 已核验的事实与方案选择

- `FaceTracker`以IoU维持空间轨道；连续确认、逐轨一次上报与同一face_id的10秒冷却均已有实现。未知face_id属于轨道实例，不能当成跨轨稳定人员身份。
- `jetson_local`配置为Haar检测、recognition=none。`NullRecognizer.embed`返回None；`VisionService._identify`即便取得向量也只向tracker传递库匹配结果，不传特征。现有自然姿态夹具只有时间和框，不能检验外观关联。
- `dialog/`目前包含数据库、规则及其测试，没有对话状态机或visit_report构造/业务去重实现。数据库的create_visit直接创建记录，不实施10分钟去重。文档写有10分钟窗口不代表运行链路已实现。
- 同一组框和时间可以对应“原人员转头后恢复”或“原人员离开、另一人站到原位置”。若系统没有其他证据，这两个世界的输入完全一致，无法同时保证原人不重报和换人不漏报。具体反例及本轮源码哈希见同名JSON证据。

| 方案 | 可解决的范围 | 取舍 |
| --- | --- | --- |
| 延长TTL、扩大框匹配或按左右区域合并 | 减少固定构图片中的轨道碎片 | 不能区分原人恢复与同位置换人；不采用为身份关联依据 |
| 只补业务层10分钟窗口 | 在已有稳定身份/关联键时合并到访 | 不能让不同unk_ID自动变成同一人，也不能解决本地2条目标 |
| 独立的短期匿名关联层，使用经验证的外观/连续在场证据 | 在有足够证据时关联新旧空间轨道 | **建议采用**；先做能力验证，歧义时保留新候选，不能承诺当前Haar输入即可达到2条 |

建议先验证短期关联所需证据，确认可在Jetson上运行后再限定实现。不得直接在生产中启用未校准特征匹配，或把外观相似等同已知身份。此方案不是“把人脸库注册好才工作”：陌生人可使用仅驻留内存、随会话过期的匿名关联信息。

## 【输入输出定义】

### 责任划分

| 层 | 输入与输出 | 去重责任 | 禁止推断 |
| --- | --- | --- | --- |
| 空间轨道 | 逐帧框、帧时刻、识别标签 → 连续段、track_id、确认候选 | 连续3帧确认；漏检/换标签重数；轨道TTL=2秒；逐轨不重报 | track_id不同不等于人员不同 |
| 短期匿名关联（待实现） | 已确认轨道及经过验证的关联证据 → 临时session_id、关联结果和理由 | 一对一跨轨关联；同一持续在场会话只生成一次本地事件 | 框接近、同侧、同数量或时间短不足以证明同人 |
| 本地face_event | 首次确认且尚未上报的会话 → 既有v1消息 | 保留10秒同face_id冷却；未知身份仍is_known=false/name=null | 不等于到访计数，不等于熟人识别通过 |
| 业务到访（待实现） | 本地事件及可信人员/会话关联 → visit_id、visit_report、次数 | 10分钟业务窗口和报告幂等；与10秒冷却分开 | 不按bbox或所有unknown共用一个键合并 |

现有v1协议保持不变；session_id仅作内部键，明确关联后同一匿名会话沿用原unk_ID。不能把运行期匿名键写成人员永久身份，不能让合成测试ID或人工左右标注参与生产判断。

关联层的输入必须显式包含证据是否可用及来源。只有候选匹配唯一、证据质量达标且身份无冲突时才复用会话；没有证据或存在多解时返回“未关联/歧义”，生成独立候选。输出诊断只保存相对时间、轨道/会话标识、判定及理由；不保存特征向量、人脸图像或身份库。

### 业务窗口的建议语义（待确认，本轮不实现）

- msg_id重传只处理一次；报告补传沿用visit_id，不重新累加次数。
- 活跃到访中的可信同人事件复用visit_id，即使持续在场超过10分钟也不能凭计时自动生成新到访。
- 已结束到访之后，以该次arrived_at为10分钟固定窗口起点：同一可信人员键在`0 <= 新事件frame_ts - arrived_at < 600000ms`内归入同次；恰好600000ms另建到访。窗口不被重复消息滑动延长。
- 未知人员只能按已证实关联的匿名会话归并；缺少关联时不得跨unk_ID套用上述“同人”条件。
- 当前face_event没有离场/持续在场更新，不能单靠无消息判断离场，也不能从最后一条事件编造departed_at。离场判定与必要的协议扩展另立合同；本轮只明确这一限制。

## 【核心算法逻辑伪代码】

```text
逐帧空间轨道继续执行现有连续确认、TTL与逐轨语义
确认候选 → 查询短期会话（会话与轨道生命周期分开）
  身份冲突 / 特征无效 / 多候选相近 / 没有可信证据：
    不跨轨合并，记录未关联理由
  唯一可信匹配且无并发占用冲突：
    复用会话；已上报则不再生成本地事件
  无匹配：建立新匿名会话，按既有确认要求发本地事件
过期会话释放关联信息；reset清空会话及冷却
业务层将msg_id幂等、人员关联、到访窗口、报告补传分别处理
```

这是目标流程，不表示相关模块已经实现。不得拿人工真值充当运行时关联证据。

## 【异常与边界条件】

- 相邻双人、交叉移动、同位置换人：同帧两条活跃轨道不得同时独占同一匿名会话；歧义保留候选，不通过强制分配压低事件数。
- 同位置出现两个未知人员与原人恢复的坐标输入可以完全一致；仅坐标测试必须保留这一不可判别性。关联能力验收必须增加独立证据及真值，不能更改旧夹具使其带答案。
- 脸缺失不等于身体离场；不能仅靠人脸TTL决定一次到访结束。短暂失去证据时可以暂停确定性关联，不能伪造连续观测。
- 已知身份标签冲突不合并；陌生人关联成功也不能升格为熟人。身份注册、库维护与跨日人员记忆不在本轮范围。
- 能力探测、相似度阈值/歧义阈值、证据有效期、会话容量与回收门槛必须先经独立样本校准并写入后续限定任务卡；此文不虚构数字供生产启用。
- 探测只用已有公开视频及本地模型/API，不采现场人脸、不读身份库、不自动下载模型、不升级系统；缺能力则报告缺口，再审查所需方案。
- 老夹具、前三个冻结正例及原验收结论保留。能力不可用时仍运行原路径并标注未关联，不宣称整体去重通过。

## 短期匿名关联层实现（2026-11-06）

按上面的合同先落"核心判定"，**不接入生产主循环**：生产行为保持不变，配置默认关闭。

- 模块：`vision/association.py`（纯 Python，不依赖 cv2/numpy/OpenCV；板端 Python 3.6 可直接解析）。
- 判定：`own >= tau(0.45)` 且 `own - other >= margin(0.10)` 且候选唯一、未被其他活跃轨道占用，才复用会话；否则新建独立候选并返回理由（`below_tau` / `ambiguous_margin` / `session_occupied` / `invalid_evidence` / `track_bound` / `new_session`）。
- 入册质量门：只有 `alignment_rms_norm <= 0.10` 的脸写入参考库；低质量或缺失质量指标的脸参与匹配但不入册。数字来源见[质量筛选与保守参考策略](质量筛选与保守参考策略-2026-11-06.md)与 LFW 独立配对验证。
- 生命周期：会话 120s 过期、轨道绑定 2s 内沿用、`max_sessions=64`、每会话 `max_refs=8`；只驻留内存，不含图像或身份库。
- 配置：`vision/config/base.yaml` 的 `association.enabled=false`（默认），其余键只在打开后生效；`config.validate` 会拒绝非法阈值。
- 测试：`vision/tests/test_association.py` 20 项；本机全量 211 项通过（原 191 项不变）。
- **未做**：没有把 embedding/质量指标接到 `VisionService`，没有修改 tracker/事件协议，也没有把 session_id 写入 v1 消息；这些要等独立场景素材验收通过后另立实现任务。当前仍不能宣称业务去重或整体可靠性通过。

## 【接线与板端验收（2026-11-07）】

用户决定"本轮接进 `VisionService`"，接线与验收见 [关联层接线与板端验收](P2.5-关联层接线-2026-11-07.md)。

- **接线**（`vision/service.py`）：每张脸带 `embedding` + `rms_norm`；tracker 把 `track_id` 回填进 face；**每帧**给关联层喂证据；出事件时按会话去重（该会话上报过即抑制，计入 `stats.suppressed` 并记理由/相似度）；已知人脸不走这一层。v1 消息协议**未改**（不加 session_id）。
- **判定条款的两处细化**（都是板端实测驱动，不改变"证据充分且唯一才复用"的骨架）：
  1. `observe(..., tracked_ids=)`：占位轨道这一帧不在场 → 视为换轨交接，允许复用会话；两条轨道同时在场仍一律拒绝。没有此项时，点位框抖动会让同一人被复制成两条会话（own 0.888 / other 0.856），事件数反弹。
  2. 会话寿命按**最后一条证据**算（`track_bound` 分支刷新 `last_ts`）。原实现连续观察 120s 后会把会话判过期，导致同一个人站着不动也被重报。
- **质量门在该管线上的重标定**：`quality_max_rms` 模块默认仍 0.10；板上 320×320 输入把关键点量化到约 2.4 px，`rms_norm` 中位数 0.145，照抄 0.10 只能入册 2.5% 的脸。`board.yaml` 覆盖为 **0.16**（入册 58%，异类余弦上界 0.209 ≪ tau 0.45）。
- **验收**：287 点夹具（几何来自夹具 + 真实外观证据）12 → **3** 条（抑制 9）；生产几何整段视频"出画 3 s 再进画"5 → **3** 条（抑制 2），稳定在场 3 → 3 不多报。剩余 1 条是 `below_tau`（own 0.38）的保守重报，符合"歧义/证据不足就新建候选"。
- **开销**：+1.23 ms/帧（56.3 ms TRT 帧的 2.2%）。
- **仍未通过的部分**：真实门口素材（逆光/多人/快速穿过）未采；板上仍无摄像头；`below_tau` 漏关联需真实素材复评。本层仍**不承诺**自然姿态"每次连续在场只 1 条事件"的强口径已达成。

## 【真素材复评与两处收紧（2026-11-08）】

用 [真实素材关联复评](真实素材关联复评-2026-11-08.md) 的 8 条 take 复评后，在原骨架上收紧两处
（都不改变"证据充分且唯一才复用"的判定条款）：

1. **候选挂起**：弱证据（`below_tau` / `ambiguous_margin` / `session_occupied`）第一次只返回
   `pending_evidence`，同一轨道连续 `weak_obs`（默认 2）帧仍弱才落成新会话；单帧侧脸/走位残影
   不再建出"重复会话"（同一个人被拆成两条会话后互相比拼 → margin 不够 → 重报）。
2. **上报前质量门**（`association.require_quality_evidence`，关联层启用时生效）：一条轨道至少要有
   一帧 `alignment_rms_norm <= quality_max_rms` 的证据才允许上报；全程不合格的轨道（出画/转身残影）
   只计入 `stats.suppressed`。实测出画帧残差 0.21–0.80（甚至 25），本来就不该被采信。

复核结果：8 条 take 中 6 条通过；剩余 2 条各多 1 条**无身份**事件，来自 2–4 帧的"正面残影"
（余弦 0.29–0.38，落在同人侧脸与异人分布的重叠带）——仅凭外观不可判别，按合同保持保守新建，
不引入位置/时间连续性猜测。

## 【首报延迟（2026-11-09）】

残余的那类残影外观上不可判别，但**时间上可分**：出现一下就没了。因此在上报口加第三道收紧
（仍不改变"证据充分且唯一才复用"的判定条款，只改**何时**采信）：

1. **首报延迟**：会话第一次建出来先不发，同一轨道继续给证据、撑够
   `first_report_confirm_frames`（默认 3）帧**或** `first_report_confirm_ms`（默认 1000）
   毫秒（先到者）才真发；撑不住的按残影丢弃，并作废它建出的候选会话。
2. **口径按出生强度分**：弱证据（`below_tau` / 歧义 / 被占）建出的会话，后面几帧即便沿轨
   `track_bound` 也按弱口径（`weak_first_report_confirm_frames`，默认 6 帧）——
   否则残影会"先弱建、再沿轨"骗过确认。
3. **被推翻的候选立刻结算**：并回已报过的会话 = 同一个人（不报）；建不出新会话 = 残影（丢弃）。

复核结果：8 条 take 中 **7 条通过**（`sc02_adjacent_t2` 修好）；剩 `sc01_replacement_t1` 仍多
1 条无身份事件——该 take 是**慢速出画**，残影能连续给 ~10 帧干净正面，比 K 帧甚至弱口径都长，
"活得久"分不开它与真在场。收口只剩重录该 take（推荐）或放宽断言。详见
[首报延迟](首报延迟-2026-11-09.md)。
