# 跨轨关联与两层去重合同（2026-11-01）

状态：**责任与验收方案，待用户确认后进入实现**。本轮已重新运行191项本机测试并复现自然姿态12条本地事件；没有修改生产算法、阈值或板端部署。整体可靠性仍未通过。

## 已核验的事实与方案选择

- `FaceTracker`以IoU维持空间轨道；连续确认、逐轨一次上报与同一face_id的10秒冷却均已有实现。未知face_id属于轨道实例，不能当成跨轨稳定人员身份。
- `jetson_local`配置为Haar检测、recognition=none。`NullRecognizer.embed`返回None；`VisionService._identify`即便取得向量也只向tracker传递库匹配结果，不传特征。现有自然姿态夹具只有时间和框，不能检验外观关联。
- `dialog/`目前包含数据库、规则及其测试，没有对话状态机或visit_report构造/业务去重实现。数据库的create_visit直接创建记录，不实施10分钟去重。文档写有10分钟窗口不代表运行链路已实现。
- 同一组框和时间可以对应“原人员转头后恢复”或“原人员离开、另一人站到原位置”。若系统没有其他证据，这两个世界的输入完全一致，无法同时保证原人不重报和换人不漏报。具体反例及本轮源码哈希见同名JSON证据。

| 方案 | 可解决的范围 | 取舍 |
| --- | --- | --- |
| 延长TTL、扩大框匹配或按左右区域合并 | 减少固定构图片中的轨道碎片 | 不能区分原人恢复与同位置换人；不采用为身份关联依据 |
| 只补业务层10分钟窗口 | 在已有稳定身份/关联键时合并到访 | 不能让不同unk_ID自动变成同一人，也不能解决本地2条目标 |
| 独立的短期匿名关联层，使用经验证的外观/连续在场证据 | 在有足够证据时关联新旧空间轨道 | **建议采用**；先做能力验证，歧义时保留新候选，不能承诺当前Haar输入即可达到2条 |

建议先验证短期关联所需证据，确认可在Jetson上运行后再限定实现。不得直接在生产中启用未校准特征匹配，或把外观相似等同已知身份。此方案不是“把人脸库注册好才工作”：陌生人可使用仅驻留内存、随会话过期的匿名关联信息。

## 【输入输出定义】

### 责任划分

| 层 | 输入与输出 | 去重责任 | 禁止推断 |
| --- | --- | --- | --- |
| 空间轨道 | 逐帧框、帧时刻、识别标签 → 连续段、track_id、确认候选 | 连续3帧确认；漏检/换标签重数；轨道TTL=2秒；逐轨不重报 | track_id不同不等于人员不同 |
| 短期匿名关联（待实现） | 已确认轨道及经过验证的关联证据 → 临时session_id、关联结果和理由 | 一对一跨轨关联；同一持续在场会话只生成一次本地事件 | 框接近、同侧、同数量或时间短不足以证明同人 |
| 本地face_event | 首次确认且尚未上报的会话 → 既有v1消息 | 保留10秒同face_id冷却；未知身份仍is_known=false/name=null | 不等于到访计数，不等于熟人识别通过 |
| 业务到访（待实现） | 本地事件及可信人员/会话关联 → visit_id、visit_report、次数 | 10分钟业务窗口和报告幂等；与10秒冷却分开 | 不按bbox或所有unknown共用一个键合并 |

现有v1协议保持不变；session_id仅作内部键，明确关联后同一匿名会话沿用原unk_ID。不能把运行期匿名键写成人员永久身份，不能让合成测试ID或人工左右标注参与生产判断。

关联层的输入必须显式包含证据是否可用及来源。只有候选匹配唯一、证据质量达标且身份无冲突时才复用会话；没有证据或存在多解时返回“未关联/歧义”，生成独立候选。输出诊断只保存相对时间、轨道/会话标识、判定及理由；不保存特征向量、人脸图像或身份库。

### 业务窗口的建议语义（待确认，本轮不实现）

- msg_id重传只处理一次；报告补传沿用visit_id，不重新累加次数。
- 活跃到访中的可信同人事件复用visit_id，即使持续在场超过10分钟也不能凭计时自动生成新到访。
- 已结束到访之后，以该次arrived_at为10分钟固定窗口起点：同一可信人员键在`0 <= 新事件frame_ts - arrived_at < 600000ms`内归入同次；恰好600000ms另建到访。窗口不被重复消息滑动延长。
- 未知人员只能按已证实关联的匿名会话归并；缺少关联时不得跨unk_ID套用上述“同人”条件。
- 当前face_event没有离场/持续在场更新，不能单靠无消息判断离场，也不能从最后一条事件编造departed_at。离场判定与必要的协议扩展另立合同；本轮只明确这一限制。

## 【核心算法逻辑伪代码】

```text
逐帧空间轨道继续执行现有连续确认、TTL与逐轨语义
确认候选 → 查询短期会话（会话与轨道生命周期分开）
  身份冲突 / 特征无效 / 多候选相近 / 没有可信证据：
    不跨轨合并，记录未关联理由
  唯一可信匹配且无并发占用冲突：
    复用会话；已上报则不再生成本地事件
  无匹配：建立新匿名会话，按既有确认要求发本地事件
过期会话释放关联信息；reset清空会话及冷却
业务层将msg_id幂等、人员关联、到访窗口、报告补传分别处理
```

这是目标流程，不表示相关模块已经实现。不得拿人工真值充当运行时关联证据。

## 【异常与边界条件】

- 相邻双人、交叉移动、同位置换人：同帧两条活跃轨道不得同时独占同一匿名会话；歧义保留候选，不通过强制分配压低事件数。
- 同位置出现两个未知人员与原人恢复的坐标输入可以完全一致；仅坐标测试必须保留这一不可判别性。关联能力验收必须增加独立证据及真值，不能更改旧夹具使其带答案。
- 脸缺失不等于身体离场；不能仅靠人脸TTL决定一次到访结束。短暂失去证据时可以暂停确定性关联，不能伪造连续观测。
- 已知身份标签冲突不合并；陌生人关联成功也不能升格为熟人。身份注册、库维护与跨日人员记忆不在本轮范围。
- 能力探测、相似度阈值/歧义阈值、证据有效期、会话容量与回收门槛必须先经独立样本校准并写入后续限定任务卡；此文不虚构数字供生产启用。
- 探测只用已有公开视频及本地模型/API，不采现场人脸、不读身份库、不自动下载模型、不升级系统；缺能力则报告缺口，再审查所需方案。
- 老夹具、前三个冻结正例及原验收结论保留。能力不可用时仍运行原路径并标注未关联，不宣称整体去重通过。
