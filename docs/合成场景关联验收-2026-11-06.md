# 合成场景关联验收（2026-11-06）

## 为什么是合成素材

现场拍不到"门口换人/相邻/恢复"的素材，本轮改为**从公开标签数据构造受控片段**：用 Hugging Face 上的 LFW（`bitmind/lfw`，同人/异人配对带标签）取两组不同身份的人脸图，按固定机位拼成 640×480 / 12fps 的短片。身份标签来自数据构造本身：

- 一个 `same` 配对 = 同一人（两张图）；
- 第二身份取另一个 `same` 配对，且与第一身份的 SFace 余弦 < 0.15（实测 −0.0333），确保是不同人。

这验证的是**关联语义与接线**，不是真实门口的能力。真实场景素材仍然要拍，见[独立正负例素材采集与标注协议](独立正负例素材采集与标注协议-2026-11-06.md)。

## 三个片段与期望

| 片段 | 构造 | 期望（track 数 / 会话数 / 第二次关联） |
| --- | --- | --- |
| `sc01_replacement` | A 2s → 空白 3s（>track TTL 2s）→ B 2s，同一位置 | 2 / 2 / 不关联 |
| `sc02_adjacent` | A、B 并排同时出现 4s | 2 / 2 / — |
| `sc03_recovery` | A 2s → 空白 3.5s → A 2s | 2 / 1 / 关联 |

## 实测结果

链路：旧版 dnn 检测（`yunet_2022_opset9_experiment.onnx`）→ 五点 SFace 对齐 → `FaceTracker`（确认 3 帧、TTL 2s）→ `AnonymousAssociator`（τ=0.45、δ=0.10、质量门 0.10）。三个片段全部通过：

| 片段 | track | 会话 | 关键事件 |
| --- | --- | --- | --- |
| `sc01_replacement` | [1,2] | [1,2] | track2 `own_best=−0.0556` → `below_tau`，没有继承 track1 的会话 |
| `sc02_adjacent` | [1,2] | [1,2] | 同一帧两条轨道各自 `new_session`，没有互相占用 |
| `sc03_recovery` | [1,2] | [1] | track2 `own_best=0.9851` → `associated`，回到原会话 |

证据：`docs/data/scenario-association-eval-2026-11-06.json`（片段与标注图在忽略目录 `datasets/scenarios/`，不进仓库）。

## 过程中发现的一个坑（会影响板端与合成素材）

旧版 `decode()` 的大事脸先验只有 **5×5 网格、步长 64**（输入 320 时）。把 260px 的脸贴到画面某些位置（如 x=190）会正好落在网格边界，**整帧检测不到**；换到 x=150 就稳定检出。真实视频里脸是连续移动的，偶尔转瞬漏检会被跟踪器补上；但固定机位的合成素材、以及正面坐姿的板端调试，可能因此误判"检测坏了"。构造固定位素材前先用同一路径试几个位置，或把脸放在较密先验能覆盖的位置。

## 局限

- 合成静帧拼接，不是真实门口视频；没有运动模糊、遮挡、光照变化。
- LFW 仅研究用途，图片只放在忽略目录；仓库只存 JSON 汇总。
- 质量值贴着 0.10 门槛（0.08–0.10），本片段验证的是关联语义，不替代参考库入册的质量评估。
- 只有一个身份对，尚未覆盖"两个候选都很像"的歧义场景。
