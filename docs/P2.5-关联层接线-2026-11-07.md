# 关联层接线与板端验收（P2.5，2026-11-07）

本轮把 2026-11-06 就写好的短期匿名关联层（`vision/association.py`）真正接进 `VisionService`，
并按用户决定（决定一 = B、决定二 = D）在板上做了验收；同时给 `runtime.backend: auto` 补上
可观测性，让"静默退到 CPU"变成看得见、可断言的东西。

## 一、接线：证据从哪来，判定在哪做

改之前：`VisionService._identify` 拿到 embedding 只用来查人脸库，查完就扔；tracker 拿不到任何
外观证据，所以轨道一断，同一个人就会以新的 `unk_ID` 再报一条。

改之后（`vision/service.py`）：

1. 每张脸带上 `embedding` 与 `rms_norm`（= 五点对齐残差 ÷ 眼距，`vision/align.py:quality`）；
2. tracker 匹配完把 `track_id` 回填进 face（`vision/tracker.py`，向后兼容，tracker 仍只认
   bbox/face_id/name/score）；
3. **每帧**都给关联层喂证据（不是只在发事件那一帧）：参考库要靠整个在场过程建立；
4. 出事件时按会话去重 —— 该会话已经报过就抑制，计数进 `stats.suppressed`，日志写理由与相似度；
5. 已知人脸不走这一层（身份去重是业务层 10 分钟到访的事）。

配置：`association.enabled` 默认仍是 `false`（PC/单测行为不变），只有 `board.yaml` 打开。
另外新增 `scripts/check_backend.py`（决定二 D）与心跳里的 `backend` 字段。

## 二、四件必须改的事（都是板上量出来的，不是猜的）

### 1. 质量门要重标定：0.10 → 0.16

`quality_max_rms <= 0.10` 是离线研究定的（依据是 1:1 关键点精度）。板上 YuNet 输入固定
320×320，5 个关键点被量化到约 2.4 px 一格再放大回 768 宽，残差整体被抬高。实测（40 帧 79 张脸）：

| 门限 | 入册脸数 | 入册率 | 同类余弦 min/median/p90 | 异类余弦 max |
| --- | --- | --- | --- | --- |
| 0.10 | 2 | 2.5% | 0.851 / 0.872 / 0.888 | 0.163 |
| 0.12 | 12 | 15.2% | 0.599 / 0.851 / 0.892 | 0.181 |
| 0.14 | 33 | 41.8% | 0.528 / 0.877 / 0.940 | 0.209 |
| **0.16** | **46** | **58.2%** | **0.528 / 0.877 / 0.940** | **0.209** |
| 0.20 | 59 | 74.7% | 0.496 / 0.874 / 0.938 | 0.330 |
| 不限 | 77 | 97.5% | 0.461 / 0.852 / 0.933 | 0.330 |

取 **0.16**：入册率从 2.5% 抬到 58%，异类余弦上界仍只有 0.209（离 `tau=0.45` 还有 0.24）。
照抄 0.10 的话关联层实际上空转（几乎无参考可匹配）。模块默认值仍是 0.10（合同口径），
板上用配置覆盖。原始分布：`rms_norm p10 0.111 / median 0.145 / p90 0.287 / max 1.487`。
证据 [quality-gate-2026-11-07.json](data/quality-gate-2026-11-07.json)。

### 2. 换轨要允许交接（`tracked_ids`）

第一次板端回放 12 → **7** 条，仍有 9 个会话（应该 2 个）。诊断出的主因：**点位框抖动让
tracker 重建轨道，旧轨道在 TTL 内还挂着会话，新轨道被判 `session_occupied`** → 新建重复会话
→ 之后同一个人在两条会话上都很像（own 0.888 / other 0.856）→ 关联层只能判歧义 → 再新建。

处置：`observe(..., tracked_ids=)` 传入"这一帧在场的轨道集合"。占位轨道这一帧不在场 =
换轨交接，允许复用同一会话；两条轨道同时在场仍一律拒绝（不许两个人共享会话）。

### 3. 会话寿命按最后一条证据算（修 bug）

`track_bound` 分支只刷新 `track_ts` 没刷新 `last_ts`，结果**人在门口连续站超过 120 秒，会话会被
TTL 判过期**，下一条证据掉成 `below_tau` → 再报一条。板上真视频在 t≈120.3 s 正好撞上。
修完加单测：连续观察 200 s 不掉会话。

### 4. 同一帧重复检出要先去掉

夹具在 t=56.0 s 有三条框，其中两条 IoU 0.517（幽灵框）。幽灵框会以"另一条轨道"的身份拿到
同一张脸的特征，把会话复制成两份。箱子层已经去重（`VisionService._dedupe_detections`，
IoU>0.5 只留分数高的），也加了单测。两个人真正的脸挨不到 0.5（并排通常 <0.2）。

## 三、板端验收

板子 `192.168.3.154`（jetson-nano，L4T R32.6.1，cv2 4.1.1），TRT = YuNet fp16 + SFace batch fp16。

### 1. 287 点自然姿态夹具回放（几何来自夹具 + 真实外观证据）

夹具本身只有时间和框，所以外观证据是在同一段视频（sha256 与夹具 `source_media_sha256`
一致，768×432 @ 12 fps，夹具第 i 帧 = 视频第 6i 帧）上实测的：SFace 特征 + 五点质量。
463/463 个夹具框都匹配到了真实检测。判定跑的是生产代码 `VisionService._process_frame`。

| 跑法 | 本地事件 | 抑制 | 会话数 |
| --- | --- | --- | --- |
| 关联层关 | **12** | 0 | 0 |
| 关联层开 | **3** | 9 | 3 |
| 夹具期望 | 2 | — | 2 |

剩下那 1 条是 `below_tau`（own **0.38** < tau 0.45）：那个人隔了 30 s、姿态变化很大地回到画面，
外观证据不够"唯一"，按合同**宁可新建候选也不合错**。这是设计好的取舍，不是回归。
证据 [association-replay-2026-11-07.json](data/association-replay-2026-11-07.json)。

### 2. 生产几何回放（YuNet 检测 + 完整 service，整段 143 s 视频）

| 跑法 | 本地事件 | 抑制 |
| --- | --- | --- |
| 连续在场，关联层关 | 3 | 0 |
| 连续在场，关联层开 | 3 | 0 |
| **中间挖 3 s 空档（出画再进画），关联层关** | **5** | 0 |
| **同上，关联层开** | **3** | **2** |

"出画再回来"的重复事件被吃掉，稳定在场时不多报、也不误合并。第 3 条事件是 t≈63.7 s 出现的
另一张脸（`below_tau` own 0.245），是真实的新候选。证据
[association-service-2026-11-07.json](data/association-service-2026-11-07.json)。

### 3. 开销：+1.23 ms/帧

固定输入（2 张脸、无推理）下测：关联层关 1.919 ms/帧 → 开 3.145 ms/帧，**+1.226 ms/帧**，
占一个 TRT 帧（56.3 ms）的 2.2%。证据 [association-cost-2026-11-07.json](data/association-cost-2026-11-07.json)。

### 4. 真机入口与"静默降级"的可见性（决定二 D）

- `python3 scripts/check_backend.py --profile board` → 退出码 **0**，打印
  `yunet-onnx/tensorrt + sface-onnx/tensorrt`；`--expect dnn` → 退出码 **1**（真的在用 TRT，
  所以"期望 CPU"不成立，说明断言是活的）。
- `vision_sim --profile board` 12 s：真实入口正常，`关联层：开（tau=0.45, margin=0.10, 质量门 rms<=0.16）`，
  心跳里带 `"backend": "yunet-onnx/tensorrt"`。
- `--no-server` 下关联层开/关 = **15.8 / 16.0 fps**（单帧推理 62.3 / 54.9 ms），没有可见退化。

## 五、还没做到的（P2 要接着办）

- **板上仍没有 `/dev/video*`**：所有 fps 都是视频源，实时摄像头链路未验。
- **真实门口素材没有**：`tau/margin/质量门` 是在"公开视频 + 两个人"上验的，没有多场景
  （逆光、多人、快速穿过）样本，`below_tau` 的漏关联（上面那 1 条）需要在真实素材上再评。

  对话节点后回到 16.5 fps —— 事件发送失败会阻塞主循环，属于 P2 联调时的风险点。
- 已知人脸的重报仍由业务层 10 分钟窗口负责，本轮没动。
