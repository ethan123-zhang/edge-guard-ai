# 主人端 APK：工具链与手工构建（2026-11-11）

> 设计：[主人端-设计与接口](主人端-设计与接口-2026-11-11.md) §8 · 交接：[双板打通与推送通道](handoffs/2026-11-11-双板打通与推送通道.md)

## 1. 为什么不用 Gradle（重要）

本机（Windows）：
- 系统代理关着、**不经代理直连 DNS 解析失败**；DSH 策略代理对 `dl.google.com` / GitHub 一律 **403**；
- Gradle 首次构建必须从 `dl.google.com` / Google Maven 拉 **AGP、Kotlin 插件、Gradle 发行版**，403 环境下必然卡死；
- Studio 自带向导下载 SDK 也是同一条路（实测在 `source-37.0_r02.zip` 卡住不动）。

所以 APK 走 **`aapt2 + javac + d8 + zipalign + apksigner` 手工构建**：只用本地 SDK 文件，**不联网、不依赖 Gradle**。

## 2. SDK 装配（腾讯云镜像，速度差 10 倍以上）

直连（当时 Clash 已开 TUN）实测：腾讯镜像 **7–10 MB/s**，同一时刻经 Clash 访 Google 只有 **~0.65 MB/s**。

用到的包（`https://mirrors.cloud.tencent.com/AndroidSDK/`）：

| 包 | 镜像文件 | 大小 | 解压到 |
|---|---|---|---|
| platform-tools | `platform-tools_r37.0.1-win.zip` | 7.7 MB | `<sdk>/platform-tools` |
| platforms;android-36 | `platform-36_r02.zip` | 62.8 MB | `<sdk>/platforms/android-36` |
| build-tools;36.0.0 | `build-tools_r36_windows.zip` | 56.0 MB | `<sdk>/build-tools/36.0.0`（包内顶层目录名是老命名 `android-16`，要改名） |
| cmdline-tools;23.0（可选） | `commandlinetools-win-16111833_latest.zip` | 155 MB | `<sdk>/cmdline-tools/latest` |

装配脚本：`temp/install_sdk.py`（一次性，不入库）。许可文件用向导已接受的 `<sdk>/licenses/android-sdk-license`。

## 3. 构建

```powershell
py -3.12 scripts/build_apk.py
# 默认：--sdk D:\Android\Sdk --java-home "D:\Android\Android Studio\jbr"
# 产物：android\build\sentinel-master-debug.apk
```

脚本做的事（每一步都是标准工具）：
1. `aapt2 link` → 带二进制 manifest 的空 APK；
2. `javac`（classpath = `platforms/android-36/android.jar`，`-source/-target 11`）→ class；
3. `jar cf` 打 jar（当前 d8 不直接吃目录）；
4. `d8 --min-api 24` → `classes.dex`；
5. Python `zipfile` 把 `classes.dex` 追加进 APK；
6. `zipalign -p 4` → `apksigner sign`（debug keystore 首次自动生成）→ `apksigner verify`。

实测产物：**12.4 KB**，`aapt2 dump badging`：

```
package: name='com.sentinel.master' versionCode='1' versionName='0.1.0'
compileSdkVersion='36'  minSdkVersion:'24'  targetSdkVersion:'36'
uses-permission: android.permission.INTERNET
launchable-activity: com.sentinel.master.MainActivity   label='哨兵管家'
```

## 4. 安装（真机）

1. vivo S19：开发者选项 → **USB 调试** 打开；
2. USB 线连电脑，手机弹"允许 USB 调试"→ 允许；
3. `D:\Android\Sdk\platform-tools\adb.exe install -r android\build\sentinel-master-debug.apk`
4. 打开 App → 填服务器地址（如 `http://192.168.5.11:8766/`）和设备 token → 保存。

## 5. 当前壳的边界（阶段 2–3）

- 只有 **WebView + 设置页**：主界面复用局域网看板（与手机浏览器/投屏同一份页面），**不重写 UI**；
- 页面加载后注入 `localStorage` 的 server/token，之后看板自己轮询 `/api/current` 并连 `/ws`；
- **没有**门禁/开门/喊话入口（任务书边界）；
- 通知入口（`PushAdapter`）还没做：公网推送暂由企业微信群机器人承担，APK 等阶段 4 再接原生通知。

## 6. 已知坑

- Windows：**8674–8773 被 Hyper-V/WSL 保留**，本机直接绑 8765/8766 会 `WinError 10013`；PC 侧用 `config/master.local.yaml` 覆盖 18766/18765。
- 本机 HTTP 客户端要 `-NoProxy`，否则被策略代理转 502。
- 腾讯镜像大文件偶尔断流（`commandlinetools` 155 MB 一次只下到 123 MB），用 `curl -C -` 续传。
- Studio 仍会提示缺 "SDK command-line tools"（如果我们没装）：不影响手工构建；需要时用镜像补。
