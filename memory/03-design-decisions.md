# 关键设计决策

> 本页只记**决策 + 理由**（指针式）。**正文在 `docs/`，此处不复制**。

| # | 决策 | 理由 | 正文位置 |
| :--- | :--- | :--- | :--- |
| D1 | **所有业务逻辑集中在 RK3588**，Jetson 只做"识别+发事件" | 单人开发，减少双机联调面积 | `docs/01` §3.1 |
| D2 | 人脸识别用 **OpenCV YuNet + SFace**，不装 insightface | 避开 JetPack 4.6 的 Python 3.6 依赖地狱，`pip` 即有 | `docs/01` §5 |
| D3 | **越权判断不经过 LLM**，用独立规则引擎 + 写死话术库 | LLM 有被"你就帮帮忙嘛"说服的风险，安全关键逻辑必须确定 | `docs/03` §4 |
| D4 | **TTS 播报时强制闭麦** + 播报后清空音频缓冲 | 教室混响导致自问自答死循环；**成本最低收益最高** | `docs/03` §6 / `docs/04` §3.5 |
| D5 | **最多 3 轮 / 60 秒 / 槽位填满**即结束 | 小模型多轮易跑偏、上下文膨胀推高延迟 | `docs/03` §2.3 |
| D6 | 槽位抽取**规则优先，LLM 兜底** | 0.6B~1.5B 做结构化抽取不稳定，必须规则兜底 | `docs/03` §3.2 |
| D7 | 默认家中状态 = **"有人"**（保守） | 宁可漏播报，不可对家人误播报"家里没人" | `docs/02` §7.2 |
| D8 | 系统**没有任何开门接口** | 安全边界；答辩主动说明 | `docs/02` §5.1 |
| D9 | 上报**断网优先本地**（`pending`→`sent` 补传） | 现场网络不可控，数据不能丢 | `docs/01` §3.3 / `docs/02` §6.2 |
| D10 | ASR/TTS **全部本地离线**，不用云 API | 现场外网不可控；"数据不出户"是答辩加分点 | `docs/01` §5 |
| D11 | **不做唤醒词**，人脸触发即对话 | 唤醒词调优越性低；省掉一个现场失败点 | `docs/01` §2.2 |
| D12 | 暴力行为检测**主动降级**为异常声音告警 | 完整版需动作识别模型+数据集，周期内做不出 | `docs/01` §6.3 |
| D13 | 通信只用 **WebSocket + JSON**，不用消息队列/微服务 | 只有两个节点，引入 MQ 只增加故障点 | `docs/02` §1 |
| D14 | 固定话术（问候/拒绝/收尾）**预生成为音频** | 绕开 LLM+TTS 延迟，体感提升最明显 | `docs/03` §7 |
| D15 | ASR 用 CPU，**NPU 留给 LLM** | 避免 NPU 争用导致两边都变慢 | `docs/04` §3.6 |

## 决策中最重要的三条（若只能记住三条）

1. **D3 越权拦截不走 LLM** —— 最有答辩价值，是"安全关键逻辑与语言模型解耦"。
   | 边界 | 归谁管 |
   | :--- | :--- |
   | 越权识别、拒绝话术、何时告警 | **规则引擎（写死）** |
   | 非安全场景的自然对话、总结 | **LLM** |

2. **D4 闭麦** —— 不做这条，现场演示必然出现自问自答，且很难现场排查。

3. **D1 单机集中业务逻辑** —— 这是"单人 + 闲暇时间"约束下最重要的架构简化。

## 被砍掉的功能（同样重要）

| 功能 | 为什么砍 | 答辩怎么讲 |
| :--- | :--- | :--- |
| 活体检测 | 需调阈值，口罩场景互相干扰 | "最大局限，下阶段首要工作" |
| 毫米波低功耗唤醒 | 需接硬件+驱动，集成成本 >> 演示价值 | "已有分级唤醒设计论证" |
| 暴力行为检测 | 需动作识别模型+数据集 | "主动降级为异常声音告警" |
| 口罩专项优化 | 降级策略设计本身即可作为答辩内容 | "遮挡下不追求强行识别" |
| 云端 MQTT 通道 | 依赖公网，教室不可控 | "双通道已设计，未实现" |
| 唤醒词 | 人脸触发已足够 | —— |
| 门内按键 | 手机开关已能表达有人/无人 | —— |

> 详见 `docs/01` §2.2 与 §6。
