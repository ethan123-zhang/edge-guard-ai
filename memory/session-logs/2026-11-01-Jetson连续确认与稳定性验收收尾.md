## 【核心算法逻辑伪代码】

```text
既有连续确认：关联空间轨道 → 漏检/身份切换则重置当前连续段
→ 连续段达到确认门槛且未 emitted → 生成本地 face_event
→ TTL内保留轨道与 emitted；超TTL后按既有合同处理
后续设计顺序：先明确 face_event 与 visit_report 各自去重责任
→ 冻结跨轨身份/到访关联合同与负例 → 委派限定实现
→ Codex核对差异、冻结回归与独立执行结果 → 保存结论并推送
```

后续部分是待冻结方案的工作顺序，尚未实现；不能只延长TTL或减少事件总数宣布通过。必须保留相邻双人，证明没有合并不同人，并同时检查漏报和多报。

## 【异常与边界条件】

- 本地 face_event 的“一次持续在场只发一次”比现有逐轨TTL合同更严格；最终 visit_report 有单独业务去重层，本次没有运行该层。当前失败定位到跨轨持续到访目标，不能升级为已证明的业务报告重复。
- 人工空白控制不是物体遮挡；自然姿态变化不是出画重入。没有人脸框真值，不能据此宣布检测精确率/召回率通过。
- 压力是600秒墙钟人工循环回放；媒体累计时间、进程时间与外部驱动时间分开报告，不能推导多日或现场稳定性。
- 连续确认/自然片隔离目录：`/home/jetson/sentinel-check-20261101-consecutive-170927`；压力目录：`/home/jetson/sentinel-check-20261101-stability-01`。Python3.6.9 / OpenCV4.1.1；进程局部环境为 `OPENBLAS_CORETYPE=ARMV8`、`OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。系统包、已有服务环境与生产部署未修改。
- 本轮离线验收未调用摄像头、身份库，未保存现场截图或发送网络事件。历史现场实验只按其原日期/证据理解，不能冒充本轮自然姿态或压力结果。
