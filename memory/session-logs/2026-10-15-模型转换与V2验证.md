## 2. 遇到的问题与解决（按发生顺序）

### P1. 工作区被 Windows 文件权限挡住（**开工第一个坑**）

| 项 | 内容 |
| :--- | :--- |
| **现象** | 连 `Get-ChildItem E:\哨兵管家` 都失败：`SetNamedSecurityInfoW failed (Win32 5): grantWrite` |
| **根因** | 当前登录账号在 `E:\哨兵管家` 上**缺 WRITE_OWNER 权限**，DSH 无法设置工作区授权 |
| **解决** | 用 `diagnose-windows-sandbox-acl` 技能跑一次修复，补上完全控制权限 |
| **验证** | `writeOwner` false → true；列目录恢复正常 |
| **备注** | 改动有备份和回滚命令，存于 `E:\哨兵管家-acl-recovery\`（**在仓库外**）。**⚠️ 该目录已于 2026-10-15 清理删除**——修复验证通过且长期正常，无回滚价值；回滚命令模板已存档到 `02-environment.md`，详见 `04` 的 E-7a |

### P2. WSL / Docker / git push 三处同时"故障"（**最有价值的排查**）

| 项 | 内容 |
| :--- | :--- |
| **现象** | `wsl -l -v` 报 `Wsl/E_ACCESSDENIED`；`LxssManager` 停在 Stopped；Docker 守护进程起不来；`git push` 报 `schannel: SEC_E_NO_CREDENTIALS`（**连只读的 `ls-remote` 都失败**） |
| **误判** | 一度以为是 WSL 坏了 / 需要管理员权限 / 豆包模拟桌面的干扰 |
| **真根因** | **DSH 默认沙箱把进程降到 Low 完整性级别**（`S-1-16-4096`），管理员组被标为 *Group used for deny only*。Low IL 下**读不到凭据库、开不了服务** |
| **关键证据** | `whoami /groups` 显示 `Mandatory Label\Low Mandatory Level`；改用 `danger-full-access` 后变成 `Medium`（`S-1-16-8192`），**三条链路同时恢复** |
| **⚠️ 烟雾弹** | **`wsl --version` 在 Low IL 下依然正常**——最容易误导人。判断 WSL 好坏**必须跑 `wsl -l -v`** |
| **沉淀** | `04` 的 E-7 |

### P4. WSL 里默认不通宿主机代理

| 项 | 内容 |
| :--- | :--- |
| **现象** | Windows 开着梯子，WSL 里 git/pip 极慢或直连失败 |
| **根因** | **WSL2 是独立虚拟机，里面的 `127.0.0.1` 指 WSL 自己**，不是 Windows |
| **解决** | 用宿主机在 WSL 网络中的**网关地址** `172.28.240.1:10090`（`ip route \| grep default` 可查，重启会变）；写入 `~/.bashrc`、`~/.pip/pip.conf`、`git config --global http.proxy` |
| **实测对比** | 走代理 HTTP 200 / 直连不通 |
| **沉淀** | `04` 的 E-8；脚本 `scripts/wsl_setup_proxy.sh` |

### P5. 大仓库克隆 TLS 中断

### P7. 官方 `build-linux.sh` 在板子上必然失败

| 项 | 内容 |

| **根因** | 那是给 **x86 PC 交叉编译**用的；**板端本机编译不需要，且该路径不存在** |

### P8. 只拷 `deploy` 会编译失败

| 项 | 内容 |
| :--- | :--- |
| **根因** | `CMakeLists.txt` 写死依赖 `${CMAKE_SOURCE_DIR}/../../../rkllm-runtime/.../librkllm_api/` |
| **解决** | 打包时连带 `rkllm-runtime/Linux/librkllm_api/{include,aarch64}` |
| **好消息** | `librkllmrt.so`（7.7MB）**仓库里本来就有**，无需另外下载 |
| **沉淀** | `04` 的 E-14 |

### P9. 两个"看起来像别的问题"的报错（**极具误导性**）

| 报错 | 真实原因 | 教训 |
| :--- | :--- | :--- |
| `./llm_demo: 没有那个文件或目录` | ① 没 `cd` 进产出目录；② 或动态库找不到 | Linux 下这两种情况**同一句报错**，要用 `find` / `ldd` 区分 |
| `Failed to open '...rkllm': No such file or directory` + `rkllm init failed` | **模型文件没传上去** | ⚠️ **极易误判成版本不匹配或模型损坏**——可能白折腾重转模型、启用降级方案。**传完先核对 SHA256** |

### P10. `max_new_tokens` 在文档里有三个矛盾值

| 项 | 内容 |
| :--- | :--- |
| **现象** | `docs/03` 中 §5.3 写 48、§6 预算表写 128、§6 降级建议写"降到 64" |
| **依据** | 按实测 31.65 tok/s 反推：**128 token = 4 秒**，光 LLM 就吃穿端到端 3.5 秒预算 |
| **决定** | **统一为 48**（人类确认，2026-10-15） |
| **理由** | 设计要求的"每次 1~2 句话" ≈ 30~45 token，48 够用且安全 |

### P11. 沙箱内 Git 自带 bash 跑不了

| **解决** | 改用 PowerShell 做等效检查；**这是预期边界，不要反复重试** |
| **沉淀** | `04` 的 E-9 |
