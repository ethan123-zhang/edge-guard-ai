## 2. 问题与决定（按发生顺序）

### P5. 用户误用占位符导致 `tar` 失败（**给指令时的教训**）

| 项 | 内容 |
| :--- | :--- |
| **现象** | 用户在板子上跑 `tar xzf ... && cd rkllm-board-v1.3.1`，报 `无法 open: 没有那个文件或目录` |
| **真根因** | **`...` 是我写在说明里的占位符，不是真实文件名** —— 用户照抄了 |
| **教训** | ⚠️ **给人类的命令必须给可直接复制的完整形式**，不要用 `...` 占位符。需要占位时**必须显式标注"把 X 换成 Y"** |

### P6. v1 / v2 包并存引出的混乱（**文档没跟上产物**）

| 项 | 内容 |
| :--- | :--- |
| **问题** | 出了 v2 后，`docs/04`、`docs/板端验证清单`、`memory/01` **仍写着传 v1** —— 会把用户引向官方原版（**跑不出人设**） |
| **决定** | **v1 不删**。理由：它是 `scripts/make_board_pkg.ps1` 的**打包输入**（该脚本以 v1 为基底增量重打），删了就得重新克隆 773M 仓库 |
| **性质澄清** | **v1 实质是构建输入（build input），不是交付物**；交付物是 v2。两者都被 `.gitignore` 排除，不在 git 里 |
| **已修** | `docs/04`、`docs/板端验证清单-明天用.md`、`memory/01` 三处改为**明确指向 v2**，并注明"v1 勿删、原因是什么" |
| **附带澄清** | 压缩包名带 `-v2`，但**解压后目录名不带** → 已在文档里显著标注，避免 `cd rkllm-board-v1.3.1-v2` 这类错误 |

### P8. 归整 PC 侧待传文件到 `board-pkg/`（**用户要求**）

| 项 | 内容 |
| :--- | :--- |
| **背景** | 用户想把模型 + v1 + v2 归到一个文件夹，方便传板子 |
| **事实澄清** | **`board-pkg/` 本来就已经是那个文件夹**（v1、v2、prompts、src、脚本都在里面），**只有模型在外面** |
| **动作** | **移动**（非复制）`Qwen3-0.6B_W8A8_RK3588.rkllm` 到 `board-pkg/`，并**同步修正全部 6 处引用** |
| **⚠️ 一处主动偏差** | 用户选的是"移动"，但**只移动了 `.rkllm`，没有移动整个 `models-rkllm/`** —— 因为该目录里的 `data_quant.json`（1.4KB）**是 git 跟踪的转换元数据**，不是待传文件，移进"待传板子"目录属于归类错误。`models-rkllm/` 保留，只装这一个文件 |
| **完整性** | 移动前后 SHA256 核对一致（`8064c9a9...`），**890MB 文件无损** |
| **git 安全** | `.gitignore` 的 `*.rkllm` 按**文件类型全局生效**，换目录后**依然被排除**，无需改规则（已复验 `git status -uall` 无 rkllm 字样） |
| **已修正引用** | `docs/04`、`docs/板端验证清单`、`memory/01`、`memory/06`、`2026-10-15` 会话记录（共 6 处） |

> **教训**（通用）：**"把某类文件归到一个文件夹"前，先确认那个文件夹里有没有不该混进来的东西。**

### P9. 板端目录归整为 `~/sentinel/` + 传输方式选型（**用户要求**）

| 项 | 内容 |
| :--- | :--- |
| **需求** | 用户要把板子上 LLM 相关数据也收进一个文件夹 |
| **方案** | **`~/sentinel/`**（`models`/`prompts`/`rkllm`/`rkllm-src`/`logs`），产出 `setup-sentinel-dir.sh` |
| **安全设计** | **只移动不删除**；目标已存在则**跳过而非覆盖**；`rkllm/` 用**软链**避免复制 7.7MB 库；移动后**核对 SHA256** |
| **传输结论** | PC 侧**没有 rsync**（Git Bash 也没带）；但 OpenSSH **9.5p1**，`scp` 走 SFTP 协议，**比老 scp 快得多**。模型 890MB 建议优先试 rsync（若板上有），否则 scp |
| **关键认知** | `.rkllm` 是量化权重，**gzip 压不动** → 传输**不要加压缩**，浪费 CPU |

### P10. 版本号治理：v3 内容直接覆盖 v2（**不新增版本号**）

| 项 | 内容 |
| :--- | :--- |
| **问题** | 加"目录归整脚本"后本可叫 v3，但**反复加版本号正是造成 v1/v2 混乱的原因**（12 处文档引用要跟着改，极易漏改） |
| **决定** | **v3 内容覆盖 v2，文件名不变** —— 文档引用**一处都不用改** |
| **保留原则** | 只有 **v1（打包输入）** 与 **v2（当前交付物）** 两个包，不再增长 |
| **判据** | 若将来改的是**补丁/提示词**（影响复验结论）→ 才需要新版本号；纯脚本增补 → 覆盖同名包 |

### P11. 板端报「权限不够」—— Windows 打的 tar 包丢了执行位（**实测踩到**）

| 项 | 内容 |
| :--- | :--- |
| **现象** | 板端 `./build-on-board.sh` → `bash: ./build-on-board.sh: 权限不够` |
| **根因** | 包是 **Windows 上用 bsdtar 打的**，而 **Windows tar 无法写 Unix 权限位**（实测 `--mode=755` 直接报 not supported）。包内 `.sh` 全是 `-rw-rw-rw-` |
| **为什么 v1 没这问题** | v1 在 **WSL(Linux) 里打的**，保留 `-rwxr-xr-x` —— **这解释了"为什么以前没遇到"** |
| **我漏掉的原因** | 我验证了包内**文件名、大小、内容、行尾**，**但没验 `tar -tvzf` 的权限列**。行尾我专门查了，权限位漏了 |
| **解法（三选一）** | ① 板端 `bash fix-perms.sh`（**包内已附**）② `chmod +x *.sh` ③ 直接 `bash xxx.sh` |
| **已做** | ① 新增 `fix-perms.sh` 并入包 ② `build-on-board.sh` 顶部**自检执行位并提示** ③ 文档写明"v2 必须先 `bash fix-perms.sh`，v1 不用" ④ 打包脚本加**权限位打印**与警告 |
| **沉淀** | `04` 的 **E-19**（含通用教训：跨平台打包要 `tar -tvzf` 验权限） |

> ⚠️ **本次最该记住的**：我做完"移动 890MB 文件"时**记得核 SHA256**，
> 却**忘了核跨平台打包必然丢失的权限位**。同类风险还有 owner、时间戳、符号链接目标 ——
> **打完包用 `tar -tvzf <包>` 看一眼完整元数据**，比只看文件名清单可靠。
