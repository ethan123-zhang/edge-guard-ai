# 2026-10-21 — Jetson 首启卡死：OEM 向导在等串口

> 结论已归入：`02-environment.md`（命门表）、`04-pitfalls-and-risks.md`（E-29~E-32）、
> `docs/04` §2.0（首次开机 + 失败对照表）。本文件只记"这一晚发生了什么、错在哪、怎么走出来的"。
> 时间跨度 10-20 深夜 → 10-22 晚收尾。

## 1. 现象

官方 JetPack 4.6（JP46，`sd-blob-b01.img`）用 Rufus **DD 模式**烧进 32G 卡，上电后：

```
A start job is running for End-user configuration after initial OEM installation (20min 10s / no limit)
```

- **永久挂住**，`no limit` 表示没有超时；
- HDMI 上**能看到完整启动日志**，然后就这一行不再动；
- **Alt+F2 切不进 TTY**（那台 tty 根本没起）；
- 日志噪音：`imx219 i2c read probe (-121)`（没接 CSI 摄像头）、`dpd enable lookup fail:-19`、
  `tegra-i2c no acknowledge from address 0x54`、`cgroup2: unknown option "nsdelegate"`、
  `Failed to start Load Kernel Modules`。

## 2. 根因（一句话）

**`nv-oem-config` 探不到可用显示，回退到 micro-USB 虚拟串口（`ttyGS0`）等人输入。**

`0x54` 是 HDMI DDC 上的 EDID 地址，`no acknowledge` = **读不到显示器 EDID**；`dpd ... -19` 是显示电源域 ENODEV。
于是它判定"没有显示器"，把初始化向导挂到串口上 —— 而串口那头没人，它就是 `no limit` 地等。

NVIDIA 论坛同款日志里有一行决定性提示（用户当时没注意到，因为它被刷屏淹了）：

> Please complete system configuration setup on the serial port provided by jetson's USB device mode connection.

**所以：镜像没问题、卡没问题、板子也没坏。** 前面那些 i2c/cgroup/模块报错全是噪声。

## 3. 走通过的路（可复用）

| 步骤 | 关键点 |
| :--- | :--- |
| 找设备 | 设备管理器 → 端口 → `USB Serial Device (COMx)`（本例 COM16） |
| 连串口 | **必须用数据线**；J48 短接 + DC 圆口供电（micro-USB 只当串口） |
| 终端 | `tools\putty.exe`：Serial / COM16 / **115200** / *Translation → UTF-8* / *Serial → Flow control = **None*** |
| 结果 | 向导**直接出现在串口窗口**里（EULA → 键盘 → 时区 → 用户名 → APP 分区） |

## 4. 这一晚踩的四个坑（都已写进 E-29~E-32）

1. **E-29 先开 HDMI、后连串口** —— 顺序反了，向导已经决定走串口，永远等不到。
2. **E-32 `plink -serial` 满屏乱码** —— UTF-8 被按 GBK 显示成 `鈹?`，ANSI 光标定位原样打出 `[10;12H`。
   换 `putty.exe` GUI + UTF-8 就好了。**这浪费的时间最多，因为看起来像"板子出问题了"。**
3. **E-30 向导里被卡住 → 直接拔 DC** —— 后果：ext4 侥幸没事（还能起到 `login:`），
   但**用户根本没建成**（向导在创建账号之前就死了）。所有账号都登不进，`yahboom` 也不行
   （那是亚博镜像的账号，官方镜像没有）。
4. **E-31 想用 WSL 离线改卡** —— `wsl --mount` 不认 **USB 可移动介质**：
   `HCS/ERROR_INVALID_DRIVE`；`Set-Disk -IsOffline` 又 `Not Supported`。这条路在 Windows 上基本堵死。

## 5. 最后的处置

- 讨论过"不重烧"的两条路：板端 **U-Boot 单用户**（`setenv cbootargs "${cbootargs} init=/bin/bash"` → `boot`）
  建账号；或裸盘读 → WSL loop 挂载 → 写回。**都没走**。
- 用户选择**重新烧录**（Rufus DD，`firmware/sd-blob-b01.img`）—— 判断正确：
  卡上没有任何数据，15 分钟重烧比"修一个没配完的系统"确定性高得多。

## 6. 下次开工第一件事（**按这个顺序，别改**）

1. **串口先连好**：`tools\putty.exe`，COMx，115200，**流控 None**，UTF-8。
2. 窗口开着，**再上电**（J48 短接 + DC 5V4A）。
3. 向导出现后**一屏一屏走**，每屏确认了再进下一步：
   EULA → 键盘 → 时区 → **用户名/密码** → **APP partition size 选最大**。
   **全程不断电。**
4. 起来后立刻：
   ```bash
   passwd                       # 若用临时密码
   df -h /                      # 期望 ≈28G；若是 ≈12G 说明没扩分区
   uname -a; cat /etc/nv_tegra_release
   python3 -c "import cv2; print(cv2.__version__, hasattr(cv2,'dnn'), hasattr(cv2,'FaceDetectorYN'))"
   ```
5. 回填 `02-environment.md` 的基线表，并回答 **V15**（JP46 自带 OpenCV 到底几版）。
6. 能做到就立刻配 **静态 IP + SSH**，之后一律远程，别再靠 HDMI（那块板的显示通路本来就是坏的）。
