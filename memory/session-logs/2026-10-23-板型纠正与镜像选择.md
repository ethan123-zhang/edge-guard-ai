## 3. 学到的经验（可复用）

1. **型号以用户/官方规格为准，绝不从"有没有 eMMC"倒推板型。** B01 模块本身带 eMMC，载板另有 TF 卡槽 —— 这与 SUB 版无关。（E-33）
2. **"能开机"≠"能用"。** 内核与模块树版本不一致时，内建驱动照常工作，但**所有模块类驱动静默失效**；判据只有一条：`uname -r` 与 `ls /lib/modules` 完全相同。（E-35）
3. **遇到"每次开机都一模一样"的故障，先怀疑配置/竞争，不要怀疑介质。** `default.target → nv-oem-config.target` + 模板单元双跑，完美解释了"重烧无效"。（E-34）
4. **Windows 上改 ext4：`wsl --mount` 不行，`usbipd` + 直通整块 USB 设备可以。** 这是本机最有用的一条工具认知。（E-31 / E-33 的邻接坑）
5. **串口是"短命令通道"，不是"交互终端"。** 长命令会丢字符，丢了引号会卡在 `>`；长逻辑一律 `pscp` 传脚本。（E-37）
6. **"能看到对端"≠"能出网"。** 出口只认两条：`ping 223.5.5.5` + `getent hosts www.baidu.com`。（E-38）
7. **怀疑镜像之前，先看它是否走到了 userspace。** 能打印 `debconf: …` 说明内核、根分区、systemd 都正常 —— 那就不可能是镜像损坏。
8. **给外部模型/文档的推断要标"推断"，不要写成"实测"。** 本次"亚博 4.6.3 配 4.9.299"就是没验证的推断。

## 4. 接下来该做的（按顺序，别跳）

### 第一步：给板子一个出口（2 分钟，唯一硬阻塞）
- **有路由器** → 网线插路由器 LAN 口，板子 DHCP 直出；
- **没有路由器**（当前情况：电脑连手机热点） → 在 PC 上打开 `ncpa.cpl` → **WLAN** 属性 → **共享** → 勾"允许其他网络用户…" → 选 **以太网** → 确定（若已勾着：取消→确定→再勾上，强制重建 NAT）。
- 验证：板子上 `ping -c2 223.5.5.5` + `getent hosts www.baidu.com`。

### 第二步：把 TF 卡换成"与 eMMC 内核配套"的系统镜像（解决 WiFi）
- 需要的镜像：**模块版本 = `4.9.299-tegra`** 的那一套（亚博出厂镜像，默认账号 `jetson` / `yahboom`）。
- 来源：亚博资料页（密码 `72q3`）→ **「3. JETSON NANO B01 官方版 → 2.烧写系统镜像」**；
  或 [GitHub 仓库](https://github.com/YahboomTechnology/Jetson-NANO-4GB) 根目录 `Annex_Download_Link.txt` 指向的 [Google Drive 资料夹](https://drive.google.com/drive/folders/1Y0AzVDR6EiMymSxnpLwKRTtmjtUCooWb)；
  或直接问技术员："**B01 官方版的出厂 SD 卡镜像**（不是 SUB 的 U 盘镜像）"。
- ⚠️ **烧之前先验**：把 img 给我，我扫 `/lib/modules` 的版本串。**不是 4.9.299 就别烧**（白烧一次 + 又回到残疾状态）。
- eMMC **不用动**（它的 `extlinux` 已指向 `root=/dev/mmcblk1p1`）。
