## 2. 遇到的问题与发现（按发生顺序）

### P1. Jetson 自带 OpenCV 是 3.2.0，不含 YuNet/SFace（**V3 被推翻**）

| 项 | 内容 |
| :--- | :--- |
| **预期** | `docs/01` D2 假设"JetPack 自带 OpenCV ≥ 4.5.4，含 `FaceDetectorYN`" |
| **实测** | OpenCV **3.2.0** + Python **3.6.9** → `YuNet False` / `SFace False` |
| **成因** | 3.2.0 是 Ubuntu 18.04 官方源版本，远低于所需的 4.5.4（差三年多） |
| **影响** | **D2 决策在本机不成立**，必须换 OpenCV |
| **沉淀** | `05` 的 V3 标记「已推翻」 |

### P2. `cv2.dnn` **整个模块不存在**（**本次最硬的发现**）

| 项 | 内容 |
| :--- | :--- |
| **现象** | 跑基线探针报 `module 'cv2' has no attribute 'dnn'` |
| **真根因** | **Ubuntu 打包的 `python3-opencv` 3.2.0 把 dnn 模块裁掉了**（C++ 层的 `libopencv-contrib3.2` 装了，但 Python 绑定没跟上） |
| **不是** | ❌ 不是"OpenCV 3.2 太旧解析不了 ONNX" —— **这个区分很重要**，两者处置完全不同 |
| **影响** | **换任何 DNN 模型都没用**。加上 `cv2.cuda` 也不存在，等于：<br>D2 方案 ✗ / 换 DNN 模型 ✗ / GPU 加速 ✗ —— **三条路同时堵死** |
| **教训** | ⚠️ **我（agent）的探针脚本一开始把两种情况混为一谈**，误报成"模型兼容性问题"。已修正为分别判断 `hasattr(cv2,'dnn')` 与解析异常 |

### P3. 这块板子跑的是**亚博智能的「出厂镜像」**，环境被预装内容改过

| 项 | 内容 |
| :--- | :--- |
| **证据** | 主机名 `yahboom`；`dpkg` 里有 ROS Melodic；有两套 OpenCV 并存 |
| **两套 OpenCV** | ① Ubuntu 源 `libopencv-*3.2` + `python3-opencv` 3.2.0（Python 实际用这套）<br>② 亚博自编译的 `libopencv`/`libopencv-dev`/`libopencv-python` **4.1.1**（版本号带 git hash） |
| **风险** | 将来编译 OpenCV 时，那套 4.1.1 的头文件/库**会混进来造成链接冲突** |
| **副作用** | **磁盘 55G 用掉 47G（88%），仅剩 6.6G** → ⚠️ **不足以编译 OpenCV**（需 8~15G 临时空间） |

### P4. ROS 只占 174M（**修正一个我下得太快的判断**）

| 项 | 内容 |
| :--- | :--- |
| **我先前的判断** | "ROS Melodic 占用内存，导致 4G 里只剩 1.4G" ❌ |
| **实测** | `/opt/ros` 仅 **174M**，且**未运行**（静态占磁盘，不占内存） |
| **修正** | 1.4G 可用更可能是**桌面环境 + 亚博预装服务**造成。**"ROS 占资源"的说法作废** |
| **但** | **烧干净镜像仍然值得**，理由改为准确的：**消除不可知的环境污染** |

### P5. 硬件身份确认：**官方 Dev Kit 规格**

| 项 | 值 | 含义 |
| :--- | :--- | :--- |
| `COMPATIBLE_SPEC` | `3448-300-0002--1--jetson-nano-devkit-` | **`jetson-nano-devkit`** —— NVIDIA 烧在模块上的规格标识，**亚博改不了** |
| `TNSPEC` | `...jetson-nano-qspi-sd-mmcblk0p1` | **SD 卡版**（模块无 eMMC，QSPI+SD 启动） |
| 载板版本 | `B.0` | 与 `memory/02` 记的 **B01** 一致 ✅ |
| 系统 | Ubuntu 18.04.6，内核 `4.9.299-tegra`（构建于 **2022-11-22**） | 对应较新的 L4T 32.7.x |
| CUDA | **10.2**（`/usr/local/cuda-10.2`，`nvcc V10.2.300`） | ✅ 完整可用 |

> ⚠️ **未决问题**：核心模块是官方规格，但 **B01 sub 载板是否有亚博改动、能否直接烧 NVIDIA 官方镜像，尚未确认**。

### P6. 亚博的两个「出厂镜像」都不能用（**用户提供截图**）

| 镜像名 | 判断 |
| :--- | :--- |
| `出厂镜像_ROS+AI视觉` | ❌ **就是现在这块板子上的** —— 重烧等于原样装回所有问题 |
| `出厂镜像_在线+离线大模型+OpenClaw` | ❌ 预装一堆不需要的大模型运行时；**它的 OpenCV 版本未知** |

**共同问题**：亚博镜像**改过什么不透明** —— 出问题时无法判断是 Jetson 普遍问题还是该镜像特有，搜索都搜不到。
