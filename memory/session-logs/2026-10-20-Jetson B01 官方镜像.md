# 2026-10-20 — Jetson B01 型号纠正 + 官方 JetPack 4.6 镜像下载

> `docs/04-部署与运维.md` §2.0（烧写正文）。本文件只记"这次发生了什么"。

## 2. 找到并核实镜像

| 项 | 值 |
|---|---|
| 文件 | `jetson-nano-jp46-sd-card-image.zip` |
| 版本 | JetPack 4.6 = L4T R32.6.1（CUDA 10.2 / cuDNN 8.2.1 / TensorRT 8.0.1 / OpenCV 4.1.1 / Python 3.6.9） |
| 大小 | 6,533,894,369 B（6.09 GiB） |
| 直链 | `https://developer.nvidia.com/embedded/l4t/r32_release_v6.1/jeston_nano/jetson-nano-jp46-sd-card-image.zip` |
| 出处 | JetPack 4.6 发布页 → *Jetson Nano Developer Kits* → *Download the SD Card Image*（与 Get Started 页给的入口一致） |
| zip 内镜像 | **`sd-blob-b01.img`** ← B01 载板的 dtb，正是需要的那个（12.76 GiB 未压缩） |
| SHA256 | `2ab9f0eaf3ea432419a8fff230659ad1e402f5c03f872097ed620924b1c14ecb` |

**两个核实点**（不是猜的）：

1. **官方发布页**（`developer.nvidia.com/embedded/jetpack-sdk-46`）在 *Jetson Nano Developer Kits* 下
   给的正是这条链接；*Jetson Nano 2GB Developer Kit* 是另一条 `jeston_nano_2gb/...`，
   下载中心的 "works for Jetson Nano 2GB" 是**页面模板话术**，不是"只能 2GB 用"。
2. **A02/B01 不能通用**：第三方实测解压出的镜像是 `sd-blob-b01.img`；社区踩坑帖写明
   「A0x 的 pinmux(dtb) 在 B0x 板上不工作」，症状是**绿灯亮、HDMI 全黑、无 splash**。
   → 本项目的规矩：**B01 只认 `sd-blob-b01.img` 这一支，旧卡不插到这块板上试**。

## 3. 下载：踩到的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **PowerShell 走不通** | `Invoke-WebRequest -Proxy` → `The SSL connection could not be established` | 放弃 |
| **curl.exe 走不通** | `curl -x http://127.0.0.1:10090` → CONNECT 成功（`200 Connection established`）但 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | 沙箱里 schannel 拿不到凭据，**别修 curl**，换 Python |
| **Python 的 OpenSSL 可以** | `urllib` + `ProxyHandler` → HEAD `200`，`Content-Length: 6533894369` | ✅ 走这条 |
| **代理偶发掐 TLS** | 第一次跑脚本时 HEAD 报 `ssl.SSLEOFError: EOF occurred in violation of protocol`，重跑就 200 | 给 HEAD 加 6 次重试（脚本已内建），**这不是本地网络坏了** |
| **Tee-Object 缓冲** | 日志比实际落后几分钟 | 判进度直接看 `*.zip.part` 的字节数，别信日志尾巴 |

下载速度实测 **~2 MiB/s**（代理线路），6.09 GiB 约 **50 分钟**；脚本用 `Range` 断点续传，
中断后**重跑同一条命令**即续。

脚本：`scripts/download_jetson_jp46.py`（可 `--key jp461` 换 4.6.1，`--no-proxy` 直连）。

## 3.1 下载后校验（**烧写前必须做的这一步**）

| 检查 | 结果 |
|---|---|
| 大小 | **6,533,894,369 B**，与服务器 `Content-Length` 逐字节一致 |
| SHA256（独立重算） | `2ab9f0eaf3ea432419a8fff230659ad1e402f5c03f872097ed620924b1c14ecb` |
| zip 完整性 | `zipfile.testzip()` → `None`（无损坏）；zip 内**只有一个文件** |
| zip 内容 | **`sd-blob-b01.img`，12.76 GiB 未压缩** ← 正是 B01 |
| 官方 checksum | ❌ **不存在**：`.zip.sha256` / `.sha1` / `.md5` 全部 404 |

> ⚠️ **老实说清楚校验的边界**：NVIDIA **不发布**这个镜像的 checksum，
> 所以上面那个 SHA256 是**本机记下的基线**，不是"和官方对过"。
> 另外社区帖子里流传的 jp46 的 SHA1（`522EC5C8…`）**与本次不符** ——
> 服务器 `Last-Modified` 是 2026-06-07（这个 2021 年的包被重传过），重传会改哈希但不改内容，
> **不能据此判定文件有问题**。真正的信心来源是：**官方发布页直链 + 尺寸精确匹配 + CRC 全通过 + 包内就是 `sd-blob-b01.img`**。

## 4. 顺带纠正的文档错误

- `docs/04` §2.2 原来的依赖块写着 `apt install python3-opencv` + `pip3 install opencv-python`，
  **与它自己下面的"千万不要用 pip 版"警告自相矛盾**，而且 `python3-opencv` 正是 Ubuntu 源的 **3.2.0**
  —— 亚博镜像里那套脏 OpenCV 很可能就是这么来的。**已删掉这两个包**，并加注释说明。
- `docs/04` §2.2 的「自带 OpenCV 3.2.0」实测注**加了限定**：那是**亚博镜像**的画像，
  干净 JP46 镜像上是 4.1.1，**要以 §2.0 末尾的重测为准**。
