## 2. 遇到的问题与发现（按发生顺序）

> **P1~P4 的技术细节已归入 `04` 的 E-15~E-18**（那才是它们的归属），本节只留一句话结论 + 指针。

### P1. `rkllm_set_chat_template()` 就是系统提示词的官方入口（**本次最重要的发现**）

`rkllm.h:463` 本就有这个 API，`llm_demo.cpp:169` 也本就有这行调用，**只是被注释掉了**。
所以裸跑没人设**不是模型能力问题、也不是缺 API**。⚠️ 官方那行**注释写错了参数个数**（4 个 vs 头文件 3 个），
**照抄取消注释会编译不过**。→ `04` **E-15**

### P2. Qwen3 的 thinking 模式会偷吃 token 预算（**新识别的混淆变量**）

`rkllm.h:188` 的 `enable_thinking` 若开着，模型先吐推理，**48 token 被推理吃掉**，
回复看起来像"被截断"→ 会**误判**成"48 不够"或"人设失败"。补丁**强制关掉并打印状态**。→ `04` **E-16**

### P3. 本机有 g++，编译检查不必依赖 WSL（**绕开了沙箱阻塞**）

`C:\Program Files\mingw64\bin\g++.exe`（**8.1.0**）。写桩冒充 `librkllmrt.so` 即可在本机编译+链接，
**上板前先排掉语法/类型错误**。→ `04` **E-18**（含"沙箱禁子进程管道，别用重定向 stdin 喂交互程序"的绕法）

### P4. 验证方式：不靠"能编译"，而靠"每条分支都跑过"

本机桩环境逐条验过：官方原始用法**向后兼容** ✅、带提示词注入成功 ✅、
提示词文件不存在**报错退出** ✅、`history` 非法参数**报错退出** ✅、`history on/off` ✅、
**带 BOM 的文件 BOM 被剥掉** ✅（37→34 字节）。

> BOM 那条不是凑数：**Windows 上编辑过的文本常带 BOM**，混进提示词开头会带偏模型。→ `04` **E-17**

### P5. 用户误用占位符导致 `tar` 失败（**给指令时的教训**）

| 项 | 内容 |
| :--- | :--- |
| **现象** | 用户在板子上跑 `tar xzf ... && cd rkllm-board-v1.3.1`，报 `无法 open: 没有那个文件或目录` |
| **真根因** | **`...` 是我写在说明里的占位符，不是真实文件名** —— 用户照抄了 |
| **教训** | ⚠️ **给人类的命令必须给可直接复制的完整形式**，不要用 `...` 占位符。需要占位时**必须显式标注"把 X 换成 Y"** |

### P6. v1 / v2 包并存引出的混乱（**文档没跟上产物**）

| 项 | 内容 |

**补丁的 5 处改动**（相对官方）：

1. 新增可选第 4 参数 `system_prompt_file`：**不传 = 与原版完全一致**（向后兼容）
2. 用 `rkllm_set_chat_template()` 注入提示词（官方通道）
3. 强制 `enable_thinking = false` 并打印
